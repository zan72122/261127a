# E14 あめあがりの ほうせきパラソル — 実装メモ

実装: `site/games/e14/index.html`（HTML + CSS + JS を1ファイル。Three.js r187 同梱版を importmap で読み込み。CDN・外部画像・外部モデル・音声ファイルなし。形・模様・音はすべてプログラム生成）

## 実装の要点

- **舞台**: 220×220m の草原（PlaneGeometry をノイズと三角関数で起伏、外周は遠い丘へ上がる）。地面シェーダーで低周波の色むら・細かな草の縞・金色がかった斑・ゆっくり流れる雲の影。草は 7枚刃の株を InstancedMesh で配置（high 28,000 / mid 15,000 / low 6,000 株）、頂点シェーダーで草原を渡る風の波、先端ほど低い roughness で濡れた光沢。水たまり 11か所（不規則な輪郭、フレネル反射・複数方向の微細な揺らぎ・空の解析反射・水底の色・落ちた水滴の同心円の波紋 16個・開いたパラソルの色の映り込み）。空は球のシェーダー（地平線→天頂の勾配、fbm の雲と陰影、太陽の暈、第1段階だけ遠方に雨雲の名残）。光の筋は太陽方向に沿った低不透明度の加算メッシュ。遠景に霞んだ丘のリング。
- **環境マップ**: 空・太陽・雲・草原の色を持つ小さな独自シーンを PMREM で処理（段階が変わったときだけ再生成）。外部 HDRI なし。
- **パラソル（主役）**: 支柱・ろくろ（持ち手兼スライド：金の筒と輪＋真珠の玉）・親骨 8/10/12本・受骨・親骨の先端部品・頂点の金の飾り・骨の間の曲面生地（縫い目と縁のレース帯はシェーダー）・縁の金のトリム。開閉率 0〜1 から「親骨の角度とたわみ → 受骨の付け根位置 → ろくろの高さ（受骨の長さ一定の拘束から計算）→ 生地の形」を毎フレーム一貫して計算。閉じた状態では生地の余りが骨の間で外にふくらむ襞になり、開くと張って骨の間がわずかにくぼみ縁が波形になる。モデルの切り替えなし。
- **素材**: 真珠・桜色ガラス・アクアマリン・アメジスト・シャンパンゴールド・オパール（MeshPhysicalMaterial。真珠とオパールは clearcoat＋iridescence、ガラス系は mid/high で半透明＋内側を白く抜く色の勾配、low は不透明）。ガラスの傘は開くと太陽方向に投影した位置へ色付きの花弁模様の光を地面に落とす。
- **水滴**: 付着水滴は下が平らで、大きい粒は重力方向に伸びた形（InstancedMesh、傘ごと）。専用シェーダー（IOR 1.333 のフレネル、反転した屈折像、太陽の鋭い反射、集光点）。開くとき、各水滴は生地上の位置の速度（前フレームとの差）＋外向き 2.0〜5.5m/s＋上向き 0.8〜3.0m/s＋回転の接線速度で放出、重力 8.6m/s²・空気抵抗つき、速度方向に伸びて描画。地面では小さな飛沫、水たまりでは波紋と落水音。引き上げ中にも少数の大粒が滑り落ちる。1本あたり 100/150/210（中央 240、low は 0.75 倍）。約14%は縁に残り、クライマックスの回転で放出。
- **操作**: 指1本。Pointer Events、最初の pointerId のみ、Pointer Capture、当たり判定は持ち手周り（最小 約140px 径）＋支柱・傘全体。上ドラッグ短辺の10%で開閉率 0→1、0.6 で残りを自動で一気に開く（0.32〜0.48秒、加速して「カチッ」で止まり、直前に骨がしなり、その後約0.5秒振動）。途中で離すとそのまま保持。タップだけなら少し後に持ち手が自動で上がる。2.7秒操作がないと持ち手に光が走り、5.5秒でスライドが 2.5cm 上下。対象外を触ると持ち手が光るだけ（失敗・減点なし）。touch-action:none、ジェスチャー・ダブルタップ・長押しメニュー抑止。
- **進行**: 状態 START → TARGET_READY → OPENING → SPLASH → NEXT_TARGET → … → CLIMAX → AFTERGLOW → FREE_PLAY。17本を半径約21mの弧（260°）に、18本目（直径5.5m）を中心に配置。6本目で雲が切れて陽光が増し、12本目で黄金の午後へ（表の色・強度・霧・ブルーム・露出を約3秒で補間）。開いた傘は残ってゆっくり回転（約3rpm）。
- **クライマックス**: 中心の傘を開くと開始。0〜1秒 中央が開く → 1〜3秒 中央から順に回転開始（約6.7rpm）→ 3〜5秒 残っていた水滴が順に放出、縁を光が一周 → 4〜9.5秒 草原全体に光る水の粒が舞う → 8〜12秒 落ち着く。カメラは中央の傘を注視したまま約7秒かけて斜め上の全景へ。その後約12秒の余韻（縁からの滴り、回転減速）→ 中央の傘がゆっくり閉じ水滴が再付着 → フリープレイ（中央、続いて各傘が順に閉じて再び対象になる、無制限）。
- **光（前回の反省）**: ACESFilmic トーンマッピングは OutputPass で1回だけ（low はレンダラーで直接）。ブルームしきい値 1.0、半径 0.3、強度は表の値＋クライマックス最大 +0.2（最大 0.85）、露出は最大 1.13。全景では霧を遠ざけ、俯瞰角を浅く（15°）して空の青・草原の緑・傘の形が残るようにした。光の筋はカメラ近くで消える。
- **カメラ**: 現在の傘の「開いた状態」の外形（縁の円・ドーム頂・飾り・支柱）を、縦横の FOV で投影して画面の80%に入る距離を二分探索で決定（横 44°、縦長 48°）。注視点は常に傘の中心（画面中央）。移動は 2秒のイージングで弧の外側を回り込む。リサイズ時に再計算。
- **音**: WebAudio のみ（最初の pointerdown で生成/resume）。接触音・骨の動作音（フィルターノイズ）・開く空気音・カチッ＋金属の余韻・飛沫音（まとめて1音）・落水音（周波数下降、間引き）・風（ローパスノイズ）・持続音（段階ごとに和音）・成功音（第1段階 単音 → 第2段階 2〜3音 → 第3段階 分散和音）・クライマックスで散った音が1つの協和音に集まる。DynamicsCompressor、簡易リバーブ。非表示時は suspend とアニメ停止、復帰時の時間差は捨てる。
- **画質**: `?q=low|mid|high` で固定（自動変更なし）。指定なしは mid で開始し、3秒 48fps 未満で1段階下げ、10秒 57fps 以上で上げる（切替後は待機）。変更対象：ピクセル比・草の数・水滴/光粒の上限・影の解像度・ブルーム（low なし / mid 半解像度 / high）。
- **テスト用**: `window.__ready` / `window.__errors`（error・unhandledrejection を捕捉）、`window.__test`（状態・本数・FPS・ブルーム・露出・対象が画面内か等）。`?autotest` は合成 PointerEvent で通常と同じ入力処理を通して全18本（ドラッグとタップを交互、2本目の指・対象外タップも検証）→ クライマックス → 余韻 → フリープレイで2本開いて `[autotest] finished {...}` をコンソールに出す。`?jump=N` は開発用（N本開いた状態から開始。autotest では使わない）。

## 確認結果（このクラウド環境）

- `python3 -m http.server`（ルート `site/`）＋ヘッドレス Chromium（Playwright）＋ SwiftShader（`--use-angle=swiftshader --enable-unsafe-swiftshader`）。
- `games/e14/index.html?autotest&q=low` を 1024x768（横）と 768x1024（縦）で全編実行 → 結果は `logs/e14/test.txt`。
  - `__ready` true、`__errors` 空、コンソールエラーなし、18本すべて開く、段階変化2回、クライマックス・余韻・フリープレイ到達、フリープレイで2本、止まっている間の対象の外形の画面外判定 0。
- スクリーンショット: `shot-1.jpg`（序盤：1本目が開いて水滴が飛ぶ）、`shot-2.jpg`（中盤：第2段階のガラスの傘）、`shot-3.jpg`（クライマックス 6秒）、縦は `p-shot-1〜3.jpg`。
- サムネイル `site/thumbs/e14.jpg`（640x480、文字なし、第2段階で傘が開いた瞬間）。
- 禁止語の grep: 該当なし。
- 開発中に mid でもクライマックスを撮影し、白飛びがないこと（ブルーム最大 0.85、露出 1.13）を確認。

## 未解決・注意点

- 実機（iPad / iPhone Safari）は未検証。SwiftShader では low でも 4〜6fps のため、実機の FPS・自動画質調整の挙動は未計測。
- クライマックスの全景は18本すべてを収めるため、個々の傘と水滴は小さく見える（光の粒は距離に応じて大きく描いて補っている）。
- ガラス系の傘は透過計算（transmission）を使わず半透明＋色の勾配で近似。
- 水たまりへの傘の映り込みは方向判定による近似（実際の反射描画ではない）。
- 音は自動テストでは鳴らないため、実機で音量バランスの確認が必要。
