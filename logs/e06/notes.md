# E06 そらを うつす きょだいなかがみ — 実装メモ

実装: `site/games/e06/index.html`（HTML + CSS + JS + シェーダーを1ファイル。Three.js r0.187.0 同梱版を importmap で読み込み。CDN・外部画像・外部モデル・音声ファイルなし）

## 実装の要点

- **遊び**: 白い塩原（作業領域 72m×96m＝内部で 6列×4行の24区画、1区画 12m×24m）を、幅12m・直径1.8mのゴム製ローラーで1区画ずつならし、空を映す水鏡にしていく。区画線・番号・矢印・文字は出さない。
  - 開始時からローラーが画面中央。持ち手（クリーム色のグリップ）がゆっくり金色に光り、金色の光の粒が持ち手へ集まる。タイトル・ボタン・説明なし。
  - 操作: ローラー（実形状より約35%大きい当たり判定＋画面上の半径フォールバック）に触れて、奥へ画面短辺の5%動かすと発進。単純なタップ（離した時点）でも発進。逆方向・途中で離す・連打・2本目の指は失敗にならない（2本目以降は無視、走行中の入力は無視、pointercancel で操作状態を解除）。
  - 走行: 24mを約3.5秒（第2段階以降は約8%速く）、発進・停止に0.42秒の加減速。ドラムは移動距離÷半径で回転。前方に細い水の盛り上がり、両端と前方から水滴（粒子プール）、後方で波紋が約0.32秒かけて静まる（マスクをローラー位置と同期して行ごとに更新）。
  - 成功: 新しい鏡面に沿って金色の細い光が走り、和音（第1段階 C5/E5 → 第2段階 C5/E5/G5 → 第3段階 +A5 → 第4段階 +C6 と高音のきらめき）。次の区画へはローラーが後退しながら曲線経路でなめらかに移動（舵を切るように向きが変わり、到着時に正面へ戻る）。
  - 区画の順序: 第1段階は中央から外へ（2,3,1,4,0,5列）、第2・3段階は端から端へ、第4段階は外側から中央へ寄せ、最後の1区画が中央寄りに残る。
  - 放置: 3秒で持ち手が強く光る、5秒でローラーが進行方向へ数cm動いて戻る、以後4秒ごとに繰り返し。ローラー以外に触れても持ち手が光って応える。
  - 4段階（6回ごと）: STAGE_UP で引きの構図になり、太陽が上がり（仰角 3→5→7.5→10°）、空・雲・山・光の色が約2.8秒かけて移り変わる。12回目のあとはカメラを太陽側へ振って低い角度から水面の太陽の反射を見せる。18回目のあとは完成した水面全体を光の波が横切る。第3段階から遠景に白い鳥（胴体＋左右の翼、羽ばたきと滑空、水面にも映る）。
  - クライマックス（約15秒）: 最後の走行（約3.5秒）→ 全体を見下ろす構図で光が鏡全体を走る → 金色の光の輪が作業領域の外へ広がり、輪の内側の遠い水面も同時に静まる（光と水面の変化は同じ半径で同期）→ 約4.5秒かけてカメラが太陽の方向へ回り込み、俯角約4°まで下がる（地平線は画面上端から約41〜44%）→ 壮大な和音（C3〜E6、約5秒で減衰）。
  - 余韻: 雲がゆっくり流れ、風の音が少し大きくなる。12秒後に持ち手が再び光り、触れると直前の画面から新しい夜明けの塩原へ2秒のクロスフェードで最初から。触れなければ完成した景色をそのまま維持。
- **水面シェーダー**（1枚の平面、ワールド座標で計算）: 方向の違う周期波（low 2 / mid 3 / high 4 成分、位相をノイズでずらして格子状のモアレを防止）＋ノイズ由来の細かい波紋、フレネル（垂直入射 0.02）、空・雲・太陽・山の解析的な反射（空と同じ関数を共有するので、太陽・雲・山の位置が空と水面で一致）、水を通して見える塩の多角形結晶（ゆがめた Voronoi＋FBM の色むら、距離で模様をフェード）、ローラーの長い影（低い太陽からの解析的な影、反射には影を落とさない）、太陽のきらめき。
  - 作業済みの範囲は 192×256 の R8 DataTexture で管理。境界はノイズでゆがめ、隣り合う区画は継ぎ目なく一枚の鏡になる。
  - 作業前: 反射は雲の高周波を抑え・彩度を下げた「白銀色」。作業後: 反射の強さを芸術的に補強（0.8〜1.0）し、雲・山の輪郭がはっきり映る。
  - ローラーと鳥の映り込み: 上下反転したコピー（レイヤー1）だけを低解像度のレンダーターゲットに描き、水面からスクリーン座標で参照（低コストな平面反射）。
- **空**: 天頂〜地平線のグラデーション、地平線の上の桃色の帯、太陽のまわりの散乱光、FBM の雲（受光面・陰影・太陽側の縁の光、雲のノイズ層 low 2 / mid 3 / high 5）、地平線の淡い大気の層。遠方の山は低周波の正弦波の合成で作ったリング状の地形メッシュ（太陽の方向は低くして太陽を隠さない）で、空と反射にも同じ関数で描く。
- **ローラー**: 基本ジオメトリで組み立て。ゴム円筒（#38444E、roughness 0.8、軸方向の継ぎ目と細かな凹凸のバンプ）、端部の面取りリング、鋼の端板・リム・ボルト10本×2・ハブ・回転軸、軸受け（面取りボックス）、珊瑚色の金属フレーム（面取り側板＋ボルト）、白い上部梁、大きな持ち手。環境マップは空シェーダーから PMREM で生成（段階変化中のみ0.7秒ごとに更新、古いものは dispose）。
- **光学**: ACESFilmic、sRGB 出力、露出 1.04（クライマックスで最大 1.09、白フラッシュなし）、距離霧 #DCE5ED（120m〜950m、水鏡が見えにくくならないよう最大55%、クライマックスは35%）、カメラ far 1900m。ブルームは強度 0.25→0.65（段階）、クライマックスでも最大0.8、しきい値0.95、半径0.28。
- **白飛び対策（前回の反省）**: 最初の試作では mid 画質のクライマックスで太陽ディスク（輝度22）がブルームで大きくにじみ、ローラーが白く霞んだ。太陽ディスクの輝度を7、太陽周辺の散乱光を弱め、ブルーム上限を0.8に下げて再確認し、最大の光の瞬間でもローラーの形・空の青・雲・山が見えることをスクリーンショットで確認した。
- **カメラ**: 透視投影、FOV 44°（縦画面 48°）、ロール0。作業中は俯角33°で「ローラー＋進行先13m＋後方4m」の直方体の8隅が画面の約78%に収まる距離を、画面比から毎フレーム計算（固定距離は使わない）。注視点（＝箱の中心）が常に画面中央。補間は時定数0.45秒（約1.3秒で収束）。段階が進むと少しずつ引く。縦画面では自動的に引く。
- **音**: WebAudio のみ（最初のタップで AudioContext 生成／resume）。風（帯域ノイズ＋ゆっくりした揺らぎ）、浅い水の音、遠い持続音、ローラーの転がる低音＋水を押す音（速度で音量とフィルター、停止時0.1秒の時定数で減衰）、ベル系の成功音、クライマックスの和音。マスターゲイン＋コンプレッサー＋簡易リバーブ。自動テストでは無音のまま進行。
- **入力・端末**: Pointer Events、pointerId 1つだけ、Pointer Capture、touch-action / overscroll / user-select / callout 無効化、gesture・dblclick・contextmenu・2本指タッチを抑止。画面回転・リサイズで進捗は維持（カメラだけ再計算）。WebGL コンテキスト喪失時は描画を止め、復帰時にマスクと環境マップを再送。
- **画質**: `?q=low|mid|high` で固定。指定なしは mid から開始し、移動平均 FPS が 50 未満3秒で1段階下げ、58 以上8秒で上げる（変更後8秒のクールダウン、タブ非表示・復帰直後は除外）。
  - high: PR 1.75 / 影 2048 / ブルーム（フル）/ 粒 350 / 雲5層 / 波4
  - mid: PR 1.25 / 影 1024 / ブルーム半解像度 / 粒 160 / 雲3層 / 波3
  - low: PR 1.0 / 影マップなし（水面の解析的な影で代替）/ ブルームなし（太陽と持ち手の光はシェーダーとスプライトで代替）/ 粒 60 / 雲2層 / 波2。水鏡・反射・ローラーの映り込みは全画質で維持。
- **状態**: READY / WAIT_INPUT / ROLLING / POLISHED / NEXT_ZONE / STAGE_UP / CLIMAX / AFTERGLOW / RESET を1つの update で管理。`window.__ready`、`window.__errors`、`window.__test`（state, count, stage, climaxReached, afterglowReached, resetCount, done, q, fps, cam, 画面上のローラーと太陽の座標）。
- **`?autotest`**: 通常と同じ onDown / onMove / onUp に合成ポインター入力を流して24回走行（奥へ押す・タップ・キャンセル→2本目の指つき押し出し を混ぜる）、クライマックス → 余韻 → 持ち手に触れて RESET → READY まで進む。各状態への遷移と成功回数を `[e06] state ...` としてコンソールに出す。開発用に `ts`（autotest 時のみ有効な時間倍率）がある。

## 確認結果（このクラウド環境）

- `python3 -m http.server`（ルート `site/`）＋ Playwright のヘッドレス Chromium（SwiftShader: `--use-angle=swiftshader --enable-unsafe-swiftshader`）で `games/e06/index.html?autotest&q=low` を 1024x768（横）と 768x1024（縦）で等速実行。スクリプトは `logs/e06/run-test.cjs`、結果は `logs/e06/test.txt`（tee で保存）。
- **横・縦とも PASS**: `__ready === true`、`__errors` 空、コンソールエラーなし。24回の走行（4段階）→ クライマックス → 余韻 → 持ち手に触れて RESET → READY まで到達（各 約260秒、SwiftShader で約4〜5fps）。
- `?autotest&q=mid&ts=2`（ブルームあり）を縦 768x1024 で全工程実行し PASS。クライマックス最大時でもローラー・空の青・雲・山が白飛びしないことを確認。
- スクリーンショット（JPEG、各 300KB 以下）: `shot-1.jpg`（序盤・横、2回目の走行中。手前に1枚目の水鏡、後方で波紋が消えていく）、`shot-2.jpg`（中盤・横、12回目のあとの段階演出。太陽側へ振った低い視点で、完成した水鏡と水面の太陽の光）、`shot-3.jpg`（クライマックス約10.5秒＝最大の光の瞬間・横）、`p-shot-1〜3.jpg`（同じ場面・縦）。
  - 作業中は縦横ともローラーが画面中央（横 512,478 付近／縦 384,600 付近）で左右に見切れない。クライマックスは縦横とも太陽が水平方向の中央・上端から約19〜22%、ローラーとその映り込みが中央、地平線は上から約41〜44%。白飛びなし。
  - 段階演出（STAGE_UP）中だけは完成した範囲全体を中央に置く構図のため、ローラーは中央から外れる（見切れはしない）。
- 試作中に直したもの: (1) mid のクライマックスで太陽のブルームが広がりローラーが霞む → 太陽輝度とブルーム上限を下げた。(2) 空が淡すぎて色が識別しにくい → 天頂を深くし、桃色の帯と彩度補正を追加。(3) 雲が大きすぎて水鏡に形が映らない → 雲のスケールを細かくした。(4) 周期波が格子状のモアレに見える → 位相をノイズでずらし、ノイズの波紋を主体にした。(5) クライマックス到達フラグが大きな時間刻みで立たない不具合を修正。
- サムネイル: `site/thumbs/e06.jpg`（クライマックスの横画面を 640x480 に縮小、約23KB、文字なし）。
- 指定の禁止語（ひらがな・カタカナ表記を含む）が `site/games/e06/` と `logs/e06/` に含まれないことを grep で確認。ゲーム本体に外部 URL なし。

## 未解決・注意点

- iPad Safari 実機での動作・FPS・タッチ感触は未確認（ヘッドレス Chromium＋SwiftShader のみ）。SwiftShader は CPU 描画のため数fpsしか出ず、性能の指標にならない。**実機で50fps以上かどうかは未検証。** 水面シェーダー（Voronoi＋雲FBM×2）が最も重いので、実機では mid→low への自動切り替えが起きる可能性がある。
- 全工程の自動テストは q=low（固定）で実施。mid は全工程を時間倍率2で実行してクライマックスの白飛びがないことを確認。high は未確認。
- 太陽の最終仰角は指示文の12°ではなく10°にした（縦横どちらの画面でも、地平線を画面の40〜50%に置いたまま太陽が上端の余白内に収まるようにするため）。
- 低 FPS 環境では1フレームのゲーム時間を最大0.1秒（autotest は0.35秒）に制限しているため、極端に遅い端末では演出がゆっくりになる。
- 必須の共通スクリプト `../../gf-playlog.js` だけが外部へビーコンを送る（このサンドボックスではテスト時にそのリクエストを 204 で代用）。ゲーム本体は外部通信なし。
