# E09 てんくうの ひみつのていえん — 実装メモ

実装: `site/games/e09/index.html`（HTML + CSS + JS を1ファイル。Three.js r0.187.0 同梱版を importmap で読み込み。CDN・外部画像・外部モデル・音声ファイルなし）

## 実装の要点

- **遊び**: 高山の岩棚の上にある、白い石の円形広場（直径約8m）と、6方向×3段＝18ユニットの折り畳み花壇。取っ手を外側へ引くと、そのユニットが展開する。全18回 → クライマックス → 余韻 → フリープレイ。
  - **機構**: 各ユニットは5枚の扇形トレイ（石の縁＋土＋真鍮の縁金具＋鋼の底板とリブ）で、**庭園の中心軸のまわりに回る扇**として作った。収納時は5枚が同じ角度に重なって数段の「積み重ね」になり（内側は広場の上に上向きに、中間・外側は内側の下に下向きに収納）、
    操作すると ①伸縮アーム（3段）がレール上の台車ごと外へ伸び（内側1.2m／中間7.45m／外側13.85m）、②5枚が0.15秒ずつずれて扇のように開きながら所定の高さへ降り（外側は上がる）、③支柱が下へ伸びて岩棚に着地し、斜材が張られ、④植物が育って色づく。展開時間は段階ごとに約4.0／3.6／3.2秒（指示文どおり）。
  - 庭園の直径: 収納時 約19m → 第1段階 21m → 第2段階 34m → 完成 46.4m。完成形は中央円盤＋内側の輪＋中間の幅広い花びら＋外側の細い花びらで、一輪の花の形になる。段ごとに 0 / −1.0 / −2.0m の段差（テラス）。
  - **取っ手**: 18本すべて広場の中央部（半径1.05〜2.25mの溝）に集約。次に引く1本だけが広場の床からせり上がって金色に光る（他は床下に隠れている／引き終えたものは溝の外端で止まって残る）。最後の1区画が終わると、18本すべてが床にきれいに沈んで対称形が完成する。
  - 操作判定: 取っ手の外向き方向を画面に投影し、その成分だけで進捗を計算（斜めのドラッグも可、逆方向は無視、進捗は戻らないラチェット式）。必要な指の移動量は画面上の溝の長さから 45〜90px に調整し、70% で自動的に最後まで引き込む。途中で離しても進捗は保持。短いタップでは取っ手が溝に沿って少し出て戻る。当たり判定は 64px 以上（画面短辺の12%、離れたタップでもすぐ誘導が始まる）。
  - 放置3秒で誘導（3.2秒周期）: 金属に金色の光が走る → 取っ手が溝に沿って少し外へ → 溝の外側へ光の粒が流れる → 元の位置へ。文字・矢印・手のアイコンなし。
  - 段階完了: 金色の光が花壇の縁を一周する＋段階ごとの成功音。
  - **クライマックス（15秒）**: 0〜2秒 中央円盤の継ぎ目が金色に → 2〜5秒 光が中心から外周へ放射状に走る → 5〜8秒 全花壇の縁に光が行き渡り、広場の水路に水が流れる（水音） → 8〜11秒 風の波が庭園を同心円状に渡り、光の粒が立ち上る → 11〜15秒 夕方の金色の光が遠方の山へ、光芒、完成した全景。画面全体のフラッシュ・点滅・カメラの振動なし。
  - 余韻12秒（機械音なし、風・水・鳥）→ 中央のハブに小さな取っ手がせり上がって光る。引くと光と水の波が庭園を巡り、花が順番に揺れる。何度でも繰り返せる（完成した庭園はそのまま）。
- **絵作り**: 空はシェーダーの球（天頂・地平線・太陽）。岩棚は頂点変位の極座標メッシュ（灰白の岩と高山の草地、崖、岩塊）、遠景は複数周波数の ridged ノイズの山（緑の斜面 → 青紫の山並み → 雪の稜線）、谷に湖（多方向の正弦波・フレネル・太陽の反射）、雲海はノイズの半透明平面を画質に応じて2〜5層（0.03〜0.12m/s）。石・土・岩・金属の使用痕・葉脈はすべて canvas で手続き生成したテクスチャ／法線マップ。環境マップは空から PMREM で生成（時間帯が変わると更新）。
  - 植物はすべて手続き生成の InstancedMesh: バラ（多層の曲面花弁）、チューリップ（6枚の花弁）、マーガレット（花芯＋放射状の花弁）、ラベンダー（小花の穂）、アジサイ（小花の集まり）、シダ（羽状の葉）、グランドカバー（小さな5弁花）。テラコッタの鉢。茎と葉は頂点シェーダーで風に揺れ、葉は逆光で透ける表現あり。展開前は控えめな色で、陽が当たると鮮やかになる。6方向それぞれ色の傾向が違う（正誤判定には使っていない）。
  - 蝶（第2段階以降、画質で最大3/6/12）と遠景の鳥。人物・乗りものなし。
  - 時間帯: 展開数に合わせて 早朝 → 朝 → 昼 → 黄金の光 → （クライマックス）さらに金色、を指示文の表の色・強さで連続補間。
  - **白飛び対策（前回の反省）**: ACESFilmic、露出は最大 1.1（通常 0.95〜1.05）、ブルームはしきい値 0.86・強さ最大 1.0。光は細い真鍮の縁と石の縁の控えめな発光、少量の光の粒、薄い光芒で表現。最大の光の瞬間のスクリーンショットで、6枚の花びらの輪郭・花の色・空の色が見えることを確認（shot-3 / p-shot-3）。
- **カメラ**: 方位固定・ロール0・減衰補間（0.6〜2.6秒）。操作待ちでは次の取っ手を画面中央に置き、**次の段階で到達する最大展開形**（花壇の先端＋植物の高さ＋支柱）をカメラ空間に投影して、縦横どちらの画角でも上下左右10%ずつの余白が残る距離を計算（縦画面は自動的に横幅基準で引く）。段階の切り替えは、次の花壇が展開する前（段階完了の光の一周の間）に始める。ドラッグ中はカメラ固定。見下ろし角はプレイ中 43°、クライマックスと余韻は庭園の中心を画面中央に置いたまま 20°（空と山並みが入るように）。
- **入力**: Pointer Events、最初の pointerId のみ追跡（2本目の指は無視）、setPointerCapture、pointercancel / lostpointercapture / blur / タブ非表示 / 画面回転で入力を安全に解除。touch-action・選択・長押し・ダブルタップ・ピンチ・スクロールを抑止。展開中・段階移行中は入力を受け付けないので二重展開しない。
- **音**: WebAudio のみ。最初のタッチで AudioContext を生成/再開（失敗してもゲームは続行）。取っ手に触れる（金属音）、引く（ラチェット）、固定（装着音）、アームの駆動音（ノコギリ波＋ローパス、動きに同期）、歯車の駆動音、トレイの固定音、展開完了のベル、段階ごとの成功音（単音2つ → 長三和音 → 5音のアルペジオ）、クライマックスの和音進行（C → Am → Fmaj7 → G → C add9、約5秒）、水音（フィルターノイズ）、風、鳥、控えめな持続和音。手続き生成の残響、コンプレッサー、マスター 0.38。タブ非表示で停止。
- **画質**: `?q=low|mid|high` で固定（自動調整なし）。指定なしは mid で開始し、48fps未満が3秒で1段階下げ、57fps以上が10秒で上げる（切り替え後8秒待機、非表示タブは計測しない、段階完了時にも再評価、クライマックス中は上げない）。high: PR上限1.5・影2048・ブルーム・粒350・雲5層・蝶12、mid: 1.15・1024・半解像度ブルーム・160・3・6、low: 0.8・512・ブルームなし（発光のみ）・60・2・3。植物の形の細かさは起動時の画質で決まる。展開数・機構・完成形は画質で変わらない。
- **状態**: start（開始待ち）→ idle（操作待ち）→ drag → lock → deploy → settle / stage（段階移行）→ climax → after（余韻）→ free（フリープレイ）。`window.__ready`、`window.__errors`（Three.js より前に監視開始）、`window.__test`（state, done, stage, climax, peak, free, freeWaves, centerErr＝対象の画面中央からのずれpx など）。
- `?autotest`: 通常と同じ onDown / onMove / onUp に合成ポインターイベントを流して全18回を実際に引く（1回目は先に短いタップ、4回目は途中で離して再開、6回目は逆方向に引いてから正方向、8回目は放置して誘導を再生、11回目はドラッグ中に2本目の指）→ クライマックス → 余韻 → フリープレイで中央の取っ手を1回引いて波を確認 → `finished`。
- 見た目確認用に `?pre=N`（N個展開済みの状態から開始。18なら `&ct=秒` でクライマックスの途中から）を用意（autotest では無効）。
- **画面の文字**: なし（読み込み中は金色の円が脈打つだけ）。

## 確認結果（このクラウド環境）

- `python3 -m http.server`（ルート `site/`）＋ Playwright ヘッドレス Chromium（SwiftShader: `--use-angle=swiftshader --enable-unsafe-swiftshader`）で `games/e09/index.html?autotest&q=low` を 1024x768（横）と 768x1024（縦）で全工程実行。結果は `logs/e09/test.txt`、スクリプトは `logs/e09/run-test.js`。
- **横・縦とも PASS**（`__ready === true`、`__errors` 空、コンソールエラーなし、18/18 展開 → クライマックス（最大の光に到達）→ 余韻 → フリープレイで波1回 → finished）。横 441秒・縦 415秒（SwiftShader で約2.5fps）。操作待ち・クライマックス中の「対象の画面中央からのずれ」は最大 14px（横）/ 12px（縦）。合成タップ1回・2本目の指の無視1回も記録。
- `q=mid`・`q=high` は横で開始〜最初の操作まで（約30秒）を実行し、`__ready`、エラーなし、コンソールエラーなしを確認（test.txt 末尾）。
- iPhone 相当（390x844 縦）は `?pre=` で操作待ちとクライマックスの静止画を撮り、庭園が中央で見切れないことを目視確認（自動テストの全工程は未実行）。
- スクリーンショット: `shot-1.jpg`（序盤・2ユニット展開後）、`shot-2.jpg`（中盤・10ユニット）、`shot-3.jpg`（クライマックス約12.4秒＝最大の光付近）、`p-shot-1〜3.jpg`（縦の同場面）。すべて 300KB 以下の JPEG。
- サムネイル: `site/thumbs/e09.jpg`（high 画質のクライマックス画面を 1280x960 で撮って 640x480 に縮小、約60KB、文字なし）。
- 禁止語（ひらがな・カタカナ表記を含む）が `site/games/e09/` と `logs/e09/` にないことを grep で確認。
- 外部通信: ゲーム本体は外部にアクセスしない。共通の `../../gf-playlog.js` のビーコンだけはテストで 204 を返して代用。

## 未解決・注意点

- iPad Safari 実機での動作・FPS・タッチ感触は未確認（SwiftShader は CPU 描画で 2〜3fps のため性能の指標にならない）。描画の目安（このページで計測）: 三角形数 low 約50万 / mid 約77万 / high 約119万、ドローコール約50（low、影の更新は動きがあるときだけ）。実機で mid が重い場合は自動調整で low に下がる。
- 自動テストとスクリーンショットは q=low（ブルームなし、影512）なので、mid/high より平板に見える。mid/high は `?pre=` で静止状態を撮って、白飛びしないこと・縁の金色の光が見えることを目視確認した（全工程の自動テストは low のみ）。
- 指示文との差: クライマックスと余韻の見下ろし角は 20°・画角46°（指示文は 45〜55°・38〜45°）。45°以上だと空も山並みも画面に入らず「空の色が見える」を満たせないため、庭園の中心を画面中央に置いたまま角度を浅くした。プレイ中は 43°。植物は遠くから色が見えるよう実寸の約2〜2.5倍の大きさ。扇の回転軸は「各ユニットの根元」ではなく「庭園の中心軸」（隙間のない花の形にするため）。
- 遠景は霞（雲海と霧）が強めで、湖はプレイ中の画面上部とクライマックスの奥に小さく見える程度。
- 植物の揺れは影には反映していない（影は静的な形）。
