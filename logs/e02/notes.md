# E02 ひみつの たきのカーテン — 実装メモ

実装: `site/games/e02/index.html`（HTML＋CSS＋JS の1ファイル、Three.js は同梱版を importmap で読み込み。外部画像・モデル・音声・CDN なし）

## 実装の要点

- **舞台**: 湖の中の石の操作台（三本レバーの回転台）→ 約90m先の岩壁にあるアーチ状の大きな岩の門 → その門をふさぐ巨大な滝（幅48m・高さ41m）→ 門の奥に、最初から作ってある草原（小川・花・針葉樹・鹿・蝶）と高台の湖、雪山、空。
- **滝（主役）**: 左右二つに分けたグリッドメッシュを3層重ねたもの。頂点シェーダーで、開口率 `uOpen` とアーチ量 `uArch` から各列の x 位置を計算するので、水は中央から左右へ実際に押しのけられる（中央を透明にする表現ではない）。寄せられた側は密度 `dens` が上がり、厚み・白さ・流速・泡・飛沫が増える。落下は放物線（リップから前へ張り出す）。フラグメント側は時間でスクロールする縦筋ノイズ（落下に合わせて加速）、泡のマスク、逆光の透過、きらめき。最終段階では開口部の形が岩のアーチの曲線に沿い、「水のアーチ」になる。
- **滝の周り**: GPU だけで動く飛沫パーティクル（着水位置は同じ開口関数で計算）、水煙スプライト、着水点の泡（シェーダー）、湖の波紋と光の輪。
- **湖**: 自前のシェーダー。3方向の波＋ノイズの法線、Fresnel、空のグラデーション反射、太陽の光の道、反射レイと滝の面との交差による「滝・岩壁・門の奥の草原」の近似反射、波紋・金色の光の輪（最大10個）。
- **光と色**: 指示文の3段階の色（空・地平線・太陽・湖・草・水煙・太陽/半球光の強さ・Bloom）を、18回の進捗に合わせて連続補間（急な切り替えなし）。太陽は奥の斜め上（逆光）。半球光と前からの補助光で岩とレバーが黒くつぶれないようにしている。ACES トーンマッピング、露出 1.05（クライマックスで最大 1.10）、Bloom の threshold 0.98、強度はクライマックスでも最大 ~1.03（上限 1.2 で頭打ち）。
- **操作**: Pointer Events（pointerdown/move/up/cancel、Pointer Capture、二本目の指は無視）。当たり判定は、画面に投影した握り＋レバー軸からの距離（半径 max(56px, 短辺の11%)）。下方向（またはどの方向でも長め）に 30〜50px 引くと成立。タップだけでも自動で引き切る。途中で離しても進捗は失わず、レバーが静かに戻るだけ。成立後 0.26 秒で残りを回転し、0.8 秒で戻る。戻れば水の変形中でも次を受け付ける。
- **ゲームの流れ**: 各水門6回×3。開口率 0.04→0.20→0.46→0.78（中央開口の幅に対する比率）。第2→第3水門の間は回転台が 2.6 秒で回り、次のレバーが手前に来る（使い終わったレバーは外側へ倒れる）。第1水門の完了で湖に金色の光の輪。第1段階5回目から蝶、第2段階で鹿が歩き出し光の筋が増え、5回目で小さな虹、第3段階3回目で鳥の群れ、5回目で虹が濃くなる。
- **クライマックス**（約14秒）: 0.0s 重い開放音 → 0.2s 水が左右へ → 1.0s Bloom をゆっくり上げる → 2.0s 太陽光と光の筋 → 3.0s 大きな虹 → 4.0s 湖に金色の光の輪4つ → 5.0s 白い鳥の群れ → 6.5s 落ち着いた輝き。カメラは動かさない。その後 17 秒の余韻 → レバーが再び金色に光り、触ると水門が順に閉じて最初に戻る。
- **誘導**: 3秒操作がないと握りに金色の光が走り、続けてレバーが5度ほど揺れる（5秒周期）。文字・矢印・手のアイコンなし。
- **カメラ**: 固定。画面の縦横比から、滝のアーチ全体（左右・上端に余白）とレバーが入るように距離・ピッチ・FOV（横 46°、縦画面は最大 60°）を計算し、回転時は約1秒で補間。操作台はカメラと一緒に動く。
- **音**: すべて WebAudio で合成。最初のタップで AudioContext を作成/再開。滝（低い轟き・左右の中音・高い飛沫）、風、遠くの鳥、小さな持続音。歯車のカチカチ、成立時の「ゴトン」＋「ザーッ」、段階ごとの澄んだ和音（C/E/G → 三和音 → C,E,G,A,D）、クライマックスのハープ風アルペジオと持続和音。マスターに DynamicsCompressor。
- **画質**: `?q=low|mid|high` で固定。指定なしは mid で開始し、1秒ごとの FPS を監視して 48fps 未満が続くと下げ、58fps 以上が約9秒続くと上げる（クールダウンあり、クライマックス中は上げない、非表示タブは除外）。PixelRatio 0.75/1.0/1.5、Bloom なし/半解像度/通常、飛沫 250/700/1500、草 800/2000/4000、花 500/1200/2400、水煙 8/14/22、影 なし/1024/2048。地形・岩壁・滝の分割数は開始時の画質で決める。
- **デバッグ**: `window.__ready`（初期化と最初の描画のあと true）、`window.__errors`（error / unhandledrejection / 初期化エラー）。`?autotest` は、握りの画面位置に本物の PointerEvent（pointerdown→pointerup＝タップ）を送るので、通常と同じ当たり判定・レバー・水流・段階移行・クライマックスを通る。`window.__game` で状態を読める（画面には何も出さない）。

## 確認結果（このクラウド環境、ヘッドレス Chromium + SwiftShader）

詳細は `logs/e02/test.txt`。

- `games/e02/index.html?autotest&q=low` を 1024x768（横）と 768x1024（縦）で実行:
  - `__ready` = true（約3.6秒）、`__errors` = []、コンソールエラーなし。
  - 18回の操作・3段階を通ってクライマックスに到達（SwiftShader で約134秒）。
  - 1024x768 では続けて再プレイも確認: マウスのドラッグで水門が閉じて最初の状態（ready）に戻り、タッチのタップで次の1回目が成立。
- スクリーンショット: `shot-1.jpg`（序盤）、`shot-2.jpg`（中盤、第2水門）、`shot-3.jpg`（クライマックス、横）、`shot-3-portrait.jpg`（クライマックス、縦）。最大の光の瞬間でも、水のアーチの輪郭・草原・青空・山が見えていて白飛びしていない。レバーの握りは横で画面高さの約65%、縦で約58%の位置、左右中央。滝とアーチは縦横どちらでも端で切れていない。
- 768x1024 を mid でも短時間起動して描画を確認。
- 640x480 を **high**（Bloom 通常解像度・飛沫1500）で autotest し、クライマックス到達・エラーなしを確認。この画面をサムネイル `site/thumbs/e02.jpg`（640x480, 約41KB, 文字なし）に使用。
  - 途中で一度、high のクライマックスで飛沫と水煙が重なって Bloom の閾値を超え、画面が白っぽくかすむのを見つけた。Bloom threshold を 0.98 に上げ、飛沫・水煙の色を抑え、粒子数・水煙の数に応じて不透明度を下げて直した（修正後のスクリーンショットで、アーチ・虹・草原・空・山が見えることを確認）。
- 禁止語の grep: 該当なし。
- 共通スクリプト `gf-playlog.js` が外部ホストへ送信しようとするが、このサンドボックスは外へ出られないためテストではそのホストだけローカルで 204 を返すようにした（ゲーム本体のエラーではない）。

## 未解決・未検証の点

- iPad 実機・iPhone 実機・Safari での動作と FPS は未検証（ここでは GPU のないソフトウェア描画のみ）。画質の自動切替は実装済みだが、実機での切り替わり方は未確認。
- 1194x834 / 834x1194 / iPhone 縦長は計算上の構図調整のみで、スクリーンショットでは未確認。
- High の平面反射（レンダーターゲット）は入れず、全画質で解析的な近似反射を使っている。
- 草原の鹿・蝶・鳥は遠くて小さいため、低解像度では点に近い。木と岩壁は低画質ではやや平板に見える。
- 小さな虹（第2段階）は位置によって湖面近くに見えることがある。
