# E08 きんいろの おかの かざぐるま — 実装メモ

実装: `site/games/e08/index.html`（HTML + CSS + JS を1ファイル。Three.js r0.187.0 同梱版を importmap で読み込み。CDN・外部画像・外部モデル・音声ファイルなし）

## 実装の要点

- **遊び**: 黄金の丘に白い風車15基（5基×3段階）。中央の止まった風車の羽根をタップ／スワイプすると即座に回り始め（押した瞬間に角速度を与える）、慣性で約16〜18rpmへ加速。直下から風の輪が広がり、草が根元からしなって穂が光り、丘を越えていく。約5.6秒後（段階の終わりは9秒）にカメラが次の風車へ3秒以上かけて移動し、中央に収まってから誘導を始める。
  - 回っている風車に触れると一時的に加速＋新しい風の波（進行は増えない）。連打は0.45秒以内なら波を出さず少し加速だけ。
  - 誘導: 中央に収まった時に羽根の根元→先端へ光が流れる。無操作3秒で光を繰り返し、6秒で羽根を±3°ゆっくり揺らす。自動成功はしない。
  - 当たり判定: 羽根の回転円の1.32倍（最低64px）＋塔の周り48px、さらに羽根メッシュへの Raycast。外しても救済。背景タップは何も起きない（不快な音なし）。最初の指だけ追跡、2本目以降は無視。
  - 段階: 5基目で回った風車が順番に波を出す（上昇音）。第2段階以降は新しく回すたびに近くの回っている風車（4基／6基）へ波が届くタイミングで連動。波は第2段階で約1.3倍速く・約1.5倍広く。
  - クライマックス（15基目で開始、18秒）: 全風車が徐々に加速、全基から輪の波、前方へ5本・逆向き3本・横1本の大きな平面波が交差。種子が空へ舞い上がる。Cmaj9 の和音とアルペジオ。カメラは6秒かけて引き、全15基が入る位置へ。→ 余韻10秒（勢いを落とし、最後の風車へ戻る）→ フリープレイ（触ると黄金の波、その後隣の風車へ順に移動。端で折り返す。小さな波が残り続ける）。終了画面なし。
- **風の波（本質部分）**: 32スロットの波（輪／平面波）を uniform で GPU に渡し、草の頂点シェーダーと地面のフラグメントシェーダーで同じ関数 `windAt` を評価。波の中心で最大、後ろに弾性の揺り戻し、合計の傾きは上限（通常0.70rad、最高潮0.78rad≈45°）。通常の風（2〜6°、周期約4秒）も常時。草は傾き・法線・太陽方向・視線から光沢を計算し、波の先端で穂が金色に光る。地面も同じ波で明暗の帯が出るため遠くの丘まで「黄金の海」になる。
- **草**: InstancedBufferGeometry（1株＝曲がった葉3枚＋茎＋穂（十字の2枚））。近景層と遠景層の2層、カメラ注視点の周りに GPU 上でラップ配置（端はフェード）、高さは地形の高さテクスチャ（HalfFloat）から取得。本数: low 18000株 / mid 40000 / high 80000。
- **風車**: 塔（Lathe）、ナセル、スピナー、翼断面でねじれのある3枚羽根（根元が丸く厚く、先端0.15へ細くなる）、金属部とコンクリート基礎。塗装 roughness 0.34〜0.4 / metalness 0.1〜0.12、金属 0.78。羽根の光はシェーダーで縁に沿って流す。
- **光と色**: 指示文の3段階パレットを進行に合わせて連続補間（午後→夕方、太陽仰角 38°→28°→18°、夜にはしない）。空はシェーダー（グラデーション＋太陽＋ノイズ雲、日の当たる側が金色）。環境マップは空から PMREM で生成。太陽はカメラの右前72°（草に逆光、風車が黒くならないよう正面寄りの弱い補助光あり）。
- **白飛び対策（前回の反省）**: ACESFilmic、露出1.0（最大+0.03）、ブルームしきい値0.93・強さ 通常0.32／成功時〜0.62／最高潮0.95（上限1.2以内）。風車の塗装の反射率を抑え、地面の色に上限、地面の鏡面反射を抑制。クライマックス最大時の画像で風車の形・丘の輪郭・空の色が見えることを確認（`site/thumbs/e08.jpg` は high 品質のクライマックス約11秒時点）。
- **カメラ**: 毎フレーム、縦横の画角から「羽根の回転円＋塔＋基礎」がすべて画面の76%に入る距離を二分探索（回転軸＝画面中央固定、ロール0、FOV46）。手前の丘で基礎が隠れる場合はカメラを上げる。クライマックスは全風車の点群が80%に入る向き・距離を候補13方向から選び、群れの中心を画面中央に再調整。縦横・iPhone 390x844 で確認。
- **入力/音/画質**: Pointer Events、touch-action/選択/長押し/ダブルタップ/ピンチ抑止。WebAudio は最初のタップで生成（風・回転の風切り音（羽根の通過で脈動）・始動音・草の「サァー」・ペンタトニック成功音・段階和音・Cmaj9、リバーブ、コンプレッサー）。画質は `?q=low|mid|high` で固定、指定なしは mid 開始で48fps未満3秒で下げ、58fps超15秒で上げる（下げ2回後は上げない）。
- **テスト用**: `window.__ready`, `window.__errors`, `window.__test`。`?autotest` は通常と同じ onDown/onMove/onUp に合成イベントを流す（タップ／スワイプ／端の外しタップ、回転中の追加タップ、2本目の指、6.6秒放置で誘導確認）→ クライマックス → フリープレイで2回移動まで。補助として `?jump=N`（N基回した状態から開始）、`?dbg` がある（画面表示なし）。

## 確認結果（このクラウド環境）

- `python3 -m http.server 8765`（ルート `site/`）＋ Playwright ヘッドレス Chromium（SwiftShader）で `games/e08/index.html?autotest&q=low` を 1024x768 と 768x1024 で全工程実行。結果は `logs/e08/test.txt`（スクリプト `logs/e08/run-test.js`）。
- **横・縦とも PASS**: `__ready === true`、`__errors` 空、コンソールエラーなし、15基 → クライマックス（最高潮に到達）→ フリープレイで2回移動まで完了。各約7分（SwiftShader 約1.5fps のため autotest は1フレームの時間刻みを最大0.34秒にしている）。
- スクリーンショット: `shot-1.jpg`（序盤・2基目）、`shot-2.jpg`（中盤・8基目）、`shot-3.jpg`（クライマックス約9.5秒）、`shot-4.jpg`（フリープレイ）、`p-shot-1〜3.jpg`（縦）。すべて300KB以下。目標の風車は縦横とも中央で羽根の先端・基礎まで入っている。
- mid/high は `?jump=` で途中から開始して見た目を確認（ブルーム有効時のクライマックスで白飛びなし）。iPhone 相当 390x844 のクライマックスも群れが画面内に入ることを確認。
- 禁止語（ひらがな・カタカナ表記を含む）が `site/games/e08/` と `logs/e08/` にないことを grep で確認。

## 未解決・注意点

- iPad Safari 実機での動作・FPS・タッチ感触・音は未確認（SwiftShader の FPS は性能の指標にならない。記録上の fpsNormal 1.5 / fpsClimax 1.2 は CPU 描画の値）。
- test.txt の `backgroundTap=false` は、テストの「背景タップ」(画面左上)が画面端に見えている前の風車の回転円に当たり「回っている風車への追加操作」として扱われたため（仕様どおりの動作）。背景タップでエラーや不快な演出が出ないことは別途確認済み。
- 地形の分割数は起動時の画質で決まり、実行中の画質変更では作り直さない（草の本数・影・ブルーム・種子・雲は切り替わる）。
- 太陽の方位はカメラの向きに合わせてゆっくり追従させている（常に逆光気味の構図にするため）。
- クライマックスでは全15基を入れるためカメラが遠く（横で約330、縦で約450ユニット）、草1本1本ではなく地面シェーダーの波で黄金の海を表現している。空は夕方の段階のため上部のみ青。
- 長時間フリープレイでのメモリは、波・種子・音ノードを使い回し／使い捨てる構成で増え続けない設計だが、長時間計測はしていない。
- テスト結果は `tee` ではなくファイルへリダイレクトして保存した。
