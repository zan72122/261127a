# E01 実装指示文：たいようの こおりのはな

## 1. ゲームの狙い

5歳の女の子が、太陽の光が降り注ぐ氷河の峡谷で、巨大な氷の結晶を自分の指で組み立てる、写実3Dウェブゲームを制作してください。

- **夢×写実：** 本物の氷河に見られる気泡、亀裂、屈折、濡れた岩肌を精密に表現しながら、巨大な氷の結晶が太陽光を集める幻想的な光学装置として存在する世界を作る。
- **高揚感：** 氷晶を一つはめるたびに巨大な結晶が輝きを増し、最後には峡谷全体が巨大な宝石の内部に変わったかのような感動を生み出す。
- **爽快感：** 指で運んだ氷晶が吸い込まれるように所定の位置へ収まり、透明感のある音とともに氷の内部を光が瞬時に駆け抜ける、気持ちのよい操作感を実現する。

本作は、氷河の中を探索するゲームではない。自分の手で巨大な光学装置を完成させ、周囲の世界まで変化させることが遊びの中心である。

景色を鑑賞するだけの作品にも、正しい形を探すことが中心のパズルゲームにもしてはいけない。子どもが迷わず操作でき、操作するたびに確かな変化が起こることを最優先する。

## 2. 絵から借りる光と色

### 2.1. 美術の方向性

フレデリック・エドウィン・チャーチの『The Icebergs』（1861年）から、以下の自然現象と素材表現の方向を借りる。

- 氷河の圧倒的な大きさと奥行き。
- 氷の内部から透けて見えるエメラルドブルー。
- 厚い氷と薄い氷で異なる透明度と色彩。
- 白い氷、青緑色の氷、濡れた岩肌の対比。
- 太陽光によって氷の内部まで照らされるような透明感。

元作品の構図、輪郭、配置、絵柄を再現する必要はない。

クリスチャン・リース・ラッセンの作品に通じる、現実の自然と想像上の現象が溶け合う世界を、物理的な説得力のある3D描画で表現する。長編ファンタジー映画のように、光そのものが驚きや感動を生み出す演出を目指す。

既存の映画のキャラクター、城、ロゴ、衣装、作品固有の意匠は一切使用しない。

### 2.2. 時間帯と色彩設計

時間帯は午前から午後の陽光を基本とする。ゲームの進行に伴って太陽光の色が少しずつ変化するが、夕闇や夜には移行しない。

以下の値をThree.jsでの初期調整値とする。

| 項目 | 第1段階 | 第2段階 | 第3段階・完成時 |
|---|---|---|---|
| 空の上部 | `#4399DC` | `#388FD9` | `#3188D2` |
| 地平線付近 | `#D5F2F8` | `#C9F1FF` | `#FBEBD2` |
| 太陽光 | `#FFF5DF` | `#FFF1D0` | `#FFE6AD` |
| 色温度の目安 | 5800K | 5400K | 4800K |
| 氷河の基本色 | `#70D5E4` | `#55CBE2` | `#40BFD9` |
| 氷の深部 | `#197B9F` | `#16799D` | `#146F9E` |
| 霧の色 | `#D1EBF4` | `#CBE9F6` | `#D5EAF1` |
| 水面 | `#258EAB` | `#239FBC` | `#2BAFC6` |

完成時には、氷を通過した太陽光が分光され、青、緑、金、桃色、紫の光が峡谷の各所に現れる。

氷そのものを不自然な虹色に塗り替えるのではなく、透明な氷を通った光によって色彩が生まれているように見せる。

### 2.3. ライティングとポストエフェクト

- DirectionalLight：強度2.5〜3.5。斜め上方から照射する。
- HemisphereLight：強度1.2〜1.8。空側は淡い青白色、地面側は青灰色。
- 環境マップ強度：0.8〜1.3。
- 氷晶内部の発光強度：通常0.05〜0.2、装着時0.8〜1.5を目安に局所調整。
- Fog：開始距離24、終了距離110を初期値とする。
- トーンマッピング：ACESFilmicToneMapping。
- Exposure：0.95〜1.15。
- 出力色空間：SRGBColorSpace。
- ブルーム強度：通常0.25〜0.45、完成時0.8〜1.1。
- ブルーム半径：0.25〜0.4。
- ブルームしきい値：0.85〜1.0。

各強度は同梱されているThree.jsのバージョンと実際の描画結果に合わせて調整する。

ブルームを氷全体に適用するのではなく、氷の稜線、内部を移動する光、太陽光が集中する箇所を中心に発生させる。完成時でもブルーム強度は1.2を超えないこと。

画面全体を白く覆うフラッシュ演出は禁止する。光量が最大になる瞬間にも、結晶の六角形構造、氷河の輪郭、空の色、水面が明瞭に認識できるようにする。

## 3. 舞台と登場するもの

### 3.1. 氷河の峡谷

広大な氷河の峡谷を制作する。中央には比較的平坦な岩場があり、左右と遠方を巨大な氷壁が囲む。

Three.jsのワールド座標では、1単位をおおむね1mと想定し、以下の寸法を目安とする。

| 対象 | 寸法の目安 |
|---|---|
| 氷河の峡谷 | 幅45〜65m、奥行き100m |
| 左右の氷壁 | 高さ12〜25m |
| 遠方の氷山 | 高さ20〜40m |
| 中央の岩場 | 直径12〜16m |
| 完成した巨大結晶 | 直径7〜8m |
| 氷晶を運ぶ台 | 幅8〜10m |

氷河は単純な青色の立方体を並べたような外見にしない。

BufferGeometryの頂点を低周波ノイズで変形させ、氷壁の大きなうねり、鋭い稜線、浸食された断面、縦方向に伸びる氷の筋を形成する。近景には細かな形状変化を与え、遠景ではポリゴン数を減らす。

氷壁の上部には白い雪を部分的に残し、下部には青緑色の厚い氷が露出しているようにする。

### 3.2. 氷のマテリアル

氷は本作の最重要素材である。プラスチックや単なる青色のガラスに見えないようにする。

MeshPhysicalMaterialを基本として、以下を初期値とする。

| パラメータ | 目安 |
|---|---|
| color | `#BCECF4` |
| metalness | 0.0 |
| roughness | 0.08〜0.25 |
| transmission | 0.65〜0.95 |
| ior | 1.31 |
| thickness | 0.2〜1.2 |
| attenuationColor | `#67C8E5` |
| attenuationDistance | 1.5〜4.0 |
| clearcoat | 0.15〜0.4 |

すべての氷に高負荷の透過処理を使う必要はない。高品質な透過表現は中央の結晶と操作中の氷晶を優先し、遠景の氷河にはPBRと疑似的な透過色を組み合わせる。

氷の内部には次の要素を加える。

- 微細な気泡の集まり。
- 細長く不規則な内部亀裂。
- 氷の成長による層状の模様。
- 厚みのある部分で濃くなる青緑色。
- 稜線に沿って生まれる白色の反射。
- 表面の細かな法線のゆらぎ。

亀裂は自然な素材表現として用い、氷が崩壊したり破壊されたりする演出には使用しない。

### 3.3. 水面と岩場

中央の岩場の周囲に、透明度の高い氷河湖を配置する。

水面はプロシージャルな波のシェーダーで表現する。周期と方向が異なる3〜4種類の波を合成し、微細な波紋と太陽光の反射を作る。

波の振幅は0.015〜0.06m程度。激しい波や飛沫は不要である。

フレネル反射を利用して、遠方ほど空や氷河を反射し、近景では浅い水底が透けて見えるようにする。毎フレームの高負荷な鏡面反射は必須とせず、環境マップと法線の変化による疑似反射を積極的に利用する。

岩場には灰青色の岩を配置する。凹凸、濡れた箇所の反射、水際の色の変化を加え、現実の自然環境としての説得力を高める。

### 3.4. 空と雲

空は球状のスカイドームまたはシェーダーによるグラデーションで生成する。

太陽は画面中央を遮らない斜め上方に置く。太陽の周囲には控えめな光の散乱を加える。

雲はプロシージャルなノイズと半透明の面を組み合わせ、遠方に少数配置する。雲がゆっくり移動することで、ゲーム世界が静止画ではなく、実際に存在する空間であることを感じさせる。

### 3.5. 巨大な氷の結晶

中央の主役は、雪の結晶を模した六回対称の巨大な立体構造物とする。

初期状態では六角形の中心核と短い六本の枝があり、各枝の先に氷晶を装着できる接続部がある。

完成時には次の構造となる。

- 中央の六角形の核。
- 放射状に伸びる六本の主枝。
- 主枝から分岐する規則的な側枝。
- 外周に形成される鋭く美しい結晶の先端。
- 内部を通る六方向の光の経路。

平面的な雪の結晶のマークではなく、厚みのある透明な結晶としてモデリングする。六角柱、切頭形状、多面体、面取りされた結晶形状を組み合わせて生成する。

結晶の下には透明な氷と自然岩で作られた台座を置く。工業製品のような金属製装置や操作パネルは使用しない。

### 3.6. 操作する六つの氷晶

各段階の開始時に、六つの氷晶を台座の周囲に用意する。

六つのうち、次に運ぶ一つだけが強調される。残りの氷晶はその場に静かに待機し、順番が来ると中央下部の操作位置に移動する。

氷晶の形状は段階ごとに変更する。

- 第1段階：六角柱を主体とした短い結晶。
- 第2段階：側枝を持つ細長い結晶。
- 第3段階：多面体の先端を持つ光学プリズム状の結晶。

氷晶は指で扱いやすい大きさとし、細すぎる部品は作らない。

本作には人間、動物、乗りものを登場させない。巨大結晶と氷河の存在感に描画予算と演出を集中させる。

すべてのジオメトリ、マテリアル、テクスチャ、環境マップ、パーティクルはプログラム内で生成する。外部の画像、3Dモデル、音声ファイルは使用しない。

## 4. 指1本のゲームループ

### 4.1. 開始

ロード完了後、氷河の峡谷と未完成の巨大結晶を表示する。

画面中央下部には最初の氷晶があり、稜線がゆっくりと輝いている。この氷晶に触れることでゲームを開始する。

独立したタイトル画面、開始ボタン、説明画面は設けない。最初に触れる氷晶を、そのまま最初の遊びに使用する。

### 4.2. 1回の操作

毎回、以下の流れを繰り返す。

**課題の提示**

巨大結晶の装着箇所が淡く発光する。同時に、運ぶべき氷晶の稜線に同系統の光が現れる。

次に触るものと、持っていく場所の関係が、文字による説明なしに理解できるようにする。

**取り組み**

氷晶に指を置くと、氷晶がわずかに持ち上がる。小さな高音が鳴り、指の移動に合わせて氷晶が滑らかに移動する。

氷晶を運ぶ際には、その向きを自動的に装着箇所に合わせる。子どもに回転操作や角度調整を要求してはいけない。

画面上の指の座標からRaycasterを使用し、カメラ正面に設定した操作平面へ投影する。指が上下左右に移動するだけで目的の位置まで運べるようにする。

**吸着と装着**

氷晶が装着箇所へ近づくと、磁石のように引き寄せられる。

装着箇所の見た目よりも十分に大きい吸着範囲を設け、厳密な位置合わせを不要にする。

吸着範囲に到達した時点で、指を離すのを待たずに成功を確定してよい。

- 吸着アニメーション：180〜300ms。
- 最後の位置補正：Ease-out系の補間。
- 装着時の音：高く澄んだ「カチン」という音。
- 装着時の動き：ごく短い停止と小さな光の放出。

**結果**

装着された氷晶から白青色の光が発生し、巨大結晶の中心核へ向かって内部を駆け抜ける。

中心核に到達した光は、既に完成している枝へ広がる。同時に、水面や近くの氷壁にも反射光が走る。

光の移動は0.4〜0.8秒程度とする。装着から最初の光が発生するまでに長い待ち時間を設けてはいけない。

### 4.3. 失敗を作らない

指が途中で離れた場合や、装着箇所から離れた場所に氷晶を運んだ場合は、氷晶を0.4〜0.6秒程度で元の位置へ戻す。

間違いを示す音、赤色の警告、破損、減点、時間切れは存在しない。

指がうまく動かせない場合に備え、氷晶を一度タップして選択し、その後に装着箇所をタップする補助操作にも対応してよい。

### 4.4. 無操作時の誘導

約2.5秒間操作がなければ、次に運ぶ氷晶がゆっくり上下に動く。

約5秒間操作がなければ、氷晶から装着箇所へ微細な光の粒が流れる。この演出を繰り返し、次の操作を自然に伝える。

矢印、手のアイコン、文字、数字、説明用の吹き出しは使用しない。

自動誘導だけで装着を完了させることは避ける。最終的には子ども自身の操作によって世界が変化することが重要である。

## 5. 盛り上がりの設計

全3段階、各段階6回、合計18回の装着を基本とする。

六つの氷晶を3層にわたって組み立てる方式を採用し、最初に装着した氷晶も最後まで残す。自分が作ったものが少しずつ大きくなっていく実感を重視する。

通常のプレイ時間は約3〜5分を想定する。ただし、操作が速い子どもを強制的に待たせたり、操作が遅い子どもを急がせたりしてはいけない。

### 第1段階：こおりの核

想定時間：開始から約50〜70秒。

中心核の周囲に六つの短い氷晶を装着する。

一つ装着するたびに、白青色の光が中心核に集まる。最初は小さな光だけだが、六つそろうと中心核全体が内部から照らされる。

六つ目の装着後、中心核から円形の光の波が岩場と水面へ広がる。

完成した六つの氷晶はそのまま残し、次の六つの氷晶が現れる。

この段階では、子どもが操作方法を自然に理解することを優先する。

### 第2段階：ひろがる結晶

想定時間：約60〜80秒。

第1段階で作った六本の枝に、側枝を持つ新たな結晶を装着する。

氷の結晶は外側へ成長し、雪の結晶特有の複雑な幾何学構造が見えるようになる。

成功時の光は中心核だけでなく、隣接する枝にも伝播する。水面には青緑色の光の模様が現れる。

六つ目の装着後、結晶全体の稜線が順番に発光し、左右の氷河に反射光が広がる。

音には三度や五度の和音を加え、第1段階より豊かな響きを持たせる。

### 第3段階：たいようの光

想定時間：約60〜80秒。

六本の枝の先端に、太陽光を分光するプリズム状の氷晶を装着する。

一つ装着するたびに、結晶の先端から細い光の帯が現れる。

六つの方向には、それぞれ青、青緑、緑、金、桃色、紫の光を割り当てる。

光はレーザー光線のような人工的な直線ではなく、氷を通過した太陽光が広がる自然な光学現象として表現する。

後半になるほど光の移動速度、反射範囲、成功音の響きを増し、完成が近づいていることを感覚的に伝える。

### クライマックス：巨大な光の解放

想定時間：約18〜22秒。

最後の氷晶が装着された瞬間から、以下の演出を連続して行う。

| 経過時間 | 演出 |
|---|---|
| 0〜1秒 | 最後の装着音。六方向から光が中心核へ集中する。 |
| 1〜3秒 | 中心核の内部に金色の光が満ちていく。 |
| 3〜6秒 | 中心核から六本の枝へ一斉に光が駆け抜ける。 |
| 6〜10秒 | 巨大結晶が垂直軸を中心にゆっくり回転し始める。 |
| 10〜15秒 | 六方向の光が氷壁と水面に広がり、峡谷全体が色彩豊かな反射に包まれる。 |
| 15〜22秒 | 回転と光の動きが次第に穏やかになり、完成した結晶が画面中央に残る。 |

光の解放は、爆発や破壊ではなく、巨大なプリズムが太陽光を峡谷全体へ届ける現象として表現する。

クライマックスでは、音楽的にも最も豊かな和音を鳴らす。ただし突然の大音量は禁止する。

### 余韻とフリープレイ

完成後は約8〜12秒の余韻を設ける。

その後、フリープレイへ移行する。

完成した結晶の六本の枝を自由にタップできるようにする。触れた枝から中心核へ光が走り、対応する色の反射光と音が生まれる。

複数の枝を順番に触ると、巨大な光の楽器を演奏しているような体験になる。

一定時間操作がなければ、完成した結晶から光の粒が空へ舞い上がり、場面が穏やかに初期状態へ戻る。再び最初の氷晶が輝き始め、そのまま繰り返し遊べるようにする。

## 6. カメラ

### 6.1. 通常時

PerspectiveCameraを使用する。垂直FOVは38〜44度を目安とする。

カメラは巨大結晶の正面に置き、プレイ中の視点移動を原則として行わない。

巨大結晶は常に画面中央に配置する。完成前から全体の形が把握できる構図とし、子どもが自分の作業結果を確認できるようにする。

次に運ぶ氷晶は画面中央下部に配置する。

装着箇所については、必要に応じて巨大結晶を正面に沿って60度ずつ緩やかに回し、次の接続部が中央下寄りに来るようにする。この回転は操作中には行わず、前回の成功演出の終了後に行う。

次の氷晶と装着箇所の双方が画面中央付近に収まり、指を短い距離だけ動かせば装着できる構図を維持する。

### 6.2. 縦向き・横向きへの対応

以下の領域を目安に画面内の配置を制御する。

- 巨大結晶の中心：画面幅の50%、高さの42〜48%。
- 次に触る氷晶：画面幅の50%、高さの68〜76%。
- 装着箇所：画面中央から大きく離れない位置。
- 巨大結晶全体：画面幅と高さの85%以内。

画面比に応じて水平FOVと垂直FOVを計算し、巨大結晶と操作する氷晶を含む必要領域が収まるようにカメラ距離を調整する。

固定のカメラ座標をすべての画面比で使い回してはいけない。

### 6.3. クライマックス

完成時のみ、カメラを6〜8秒程度かけてゆっくり後退させる。

通常時の距離の約1.35〜1.6倍を上限の目安とし、峡谷全体と水面に広がる光を見せる。

巨大結晶は最後まで画面中央に置き、遠景を見せるために主役を小さくしすぎない。

カメラの急旋回、急加速、揺れ、ロール回転、急激なズーム、被写界深度の急変は禁止する。

回転するのは巨大結晶であり、カメラが結晶の周囲を高速で回る演出にはしない。

## 7. 操作

iPad SafariとPCの両方に対応する。

Pointer Eventsを利用し、`pointerdown`、`pointermove`、`pointerup`、`pointercancel`を適切に処理する。

- 操作中のpointerIdを保持し、二本目以降の指は無視する。
- setPointerCaptureを利用し、ドラッグ中に指が氷晶の見た目から外れても操作を継続する。
- タッチ対象の当たり判定は、見た目の1.3〜1.6倍を目安とする。
- 当たり判定は画面上で最低56〜64 CSSピクセル程度を確保する。
- 装着判定には位置の許容範囲を設ける。
- 装着演出中の連続タップによる二重成功を防止する。
- マウスでもタッチと同じ操作体系を使用する。

指の位置に対して氷晶を直接追従させる。追従にはわずかな補間を使用してよいが、操作が遅れて感じられるほどの慣性は付けない。

氷晶は指で完全に隠れないよう、必要に応じて指の位置より少し上に表示する。

CSSの`touch-action: none`、`overscroll-behavior: none`、`user-select: none`、`-webkit-touch-callout: none`などをゲーム領域に適用する。

viewport設定、Safariのジェスチャーイベントへの対応も組み合わせ、ピンチズーム、ダブルタップによる拡大、スクロール、長押しメニュー、テキスト選択がゲーム操作を妨げないようにする。

## 8. 音

音声ファイルは一切使用せず、WebAudio APIによって手続き的に合成する。

最初の有効なタップのイベント内でAudioContextを生成またはresumeする。

### 8.1. 氷の音

氷の音は、ガラスやクリスタルを軽く打ったような透明感のある音を目指す。

OscillatorNodeの正弦波と三角波を主体とし、高次倍音を少量加える。

- 氷晶に触れたとき：短い高音。
- 氷晶を移動するとき：控えめな澄んだ持続音。
- 吸着直前：わずかに上昇する音。
- 装着時：輪郭が明瞭な短い打音。
- 内部を光が走るとき：音程が連続的に変化する音。

装着音のアタックは3〜10ms程度、減衰は0.3〜0.8秒程度を目安とする。

### 8.2. 段階ごとの音楽的変化

Cメジャー・ペンタトニックを基本とし、不協和音が生じにくい音程構成とする。

| 段階 | 成功音 |
|---|---|
| 第1段階 | 単音を主体とした澄んだ響き |
| 第2段階 | 単音に三度・五度を加えた響き |
| 第3段階 | オクターブを含む豊かな和音 |
| 完成時 | Cmaj9などを用いた広がりのある和音 |

各段階の六回の成功が、自然な音楽のフレーズとしてつながるようにする。

### 8.3. 環境音

フィルター処理したノイズから、峡谷を通る風と穏やかな水の音を生成する。

環境音は成功音を妨げない音量とする。風を強くしすぎて寒さや恐怖を感じさせないこと。

マスターゲインとDynamicsCompressorNodeを使用して、複数の音が重なっても過大な音量にならないようにする。

## 9. 画面の文字

ゲーム画面には文字、数字、記号による説明、ボタンのラベルを一切表示しない。

進捗は巨大結晶の形そのものによって伝える。残りの装着回数を表示する必要はない。

ロード中は中央で静かに輝く氷晶など、文字を使用しない表示にする。

終了画面やスコア画面も作らない。完成した結晶と峡谷の変化が、そのまま達成の証となる。

HTMLのtitleなど、ゲーム画面外の管理用情報は必要に応じて設定してよい。

## 10. 画質の自動調整

2020年世代のiPad ProのSafariで、50fps以上を目標とする。写実性と操作の滑らかさが競合する場合は、操作の滑らかさを優先する。

以下の3段階の画質設定を実装する。

| 項目 | high | mid | low |
|---|---:|---:|---:|
| 最大ピクセル比 | 1.75 | 1.25 | 1.0 |
| 影マップ | 1024〜2048 | 512〜1024 | 無効または疑似影 |
| ブルーム | 有効 | 低解像度 | 無効または疑似発光 |
| パーティクル上限 | 500 | 240 | 100 |
| 氷の透過処理 | 主役と操作部品 | 主役の主要部分 | 疑似透過 |
| 水面の波の合成数 | 4 | 3 | 2 |
| 遠景の形状精度 | 高 | 中 | 低 |

起動時は端末情報や描画能力を参考に、midを基準として初期画質を決定する。

実行中はrequestAnimationFrameの実測フレーム間隔からFPSを計測する。

- 約3秒間、平均FPSが48未満の場合は画質を一段階下げる。
- 約10秒間、平均FPSが57以上で安定している場合は上位画質への変更を検討する。
- 頻繁な切り替えを防ぐため、変更後にクールダウン時間を設ける。
- 指で操作している最中やクライマックスの途中には、負荷が許す限り画質変更を避ける。
- バックグラウンド復帰直後などの異常なフレーム間隔は計測から除外する。

`?q=low`、`?q=mid`、`?q=high`で画質を強制指定できるようにする。強制指定時は自動画質変更を無効にする。

lowでも、装着時の光の伝播、完成時の色彩、中央結晶の立体感は維持すること。画質を下げることによって遊びの核を失ってはいけない。

InstancedMesh、BufferGeometryの共有、マテリアルの共有、パーティクルの再利用を積極的に使用する。毎フレームの不要なオブジェクト生成や環境マップの再生成は避ける。

## 11. 技術構成

### 11.1. ファイル構成

ゲームの実装先は以下とする。

`site/games/e01/index.html`

HTML、CSS、JavaScript、シェーダーをこの1ファイルにまとめる。

Three.jsはリポジトリに同梱されている以下のファイルを使用する。

| importmapの指定 | 相対パス |
|---|---|
| `three` | `../../vendor/three/build/three.module.min.js` |
| `three/addons/` | `../../vendor/three/examples/jsm/` |

CDN、外部API、外部アセット、追加のネットワークサービスへの依存は禁止する。

必要に応じて同梱されているEffectComposer、RenderPass、UnrealBloomPass、OutputPassなどを利用する。

HTMLのhead内には以下を必ず含める。

```html
<meta name="robots" content="noindex">
```

bodyの終了タグの前には、以下を必ず含める。

```html
<script src="../../gf-playlog.js" defer></script>
```

### 11.2. 状態管理

ゲームの状態を明確に分離する。

- `LOADING`：初期化と素材生成。
- `WAIT_START`：最初の氷晶への入力待ち。
- `WAIT_INPUT`：次の操作待ち。
- `DRAGGING`：氷晶の移動中。
- `SNAPPING`：吸着と装着。
- `SUCCESS_EFFECT`：光と音の成功演出。
- `STAGE_TRANSITION`：次の段階への移行。
- `CLIMAX`：完成演出。
- `AFTERGLOW`：余韻。
- `FREE_PLAY`：自由操作。
- `RESETTING`：初期状態への復帰。

通常操作と自動テストで同じ状態遷移処理を使用する。

ステージ進行、装着数、装着済みの部品、現在操作できる氷晶を一元管理する。再プレイ時にはすべての状態が正しく初期化されるようにする。

### 11.3. 準備完了とエラー管理

`window.__ready`を用意する。

初期値はfalseとし、Three.jsの初期化、必要なジオメトリ生成、画面表示、入力イベント登録が完了した時点でtrueとする。AudioContextのユーザー操作待ちは準備完了の妨げにしない。

`window.__errors`を配列として用意する。

windowのerrorイベント、unhandledrejectionイベント、ゲーム内で捕捉した重大な例外を記録する。

エラー内容は開発者向けの情報として扱い、ゲーム画面には表示しない。

### 11.4. 自動プレイ

`?autotest`が指定された場合は、ユーザー操作がなくても以下の全工程を自動で進める。

1. 初期化と開始。
2. 第1段階の6回の装着。
3. 第2段階の6回の装着。
4. 第3段階の6回の装着。
5. クライマックス。
6. 余韻。
7. フリープレイへの到達。

内部変数だけを直接変更するのではなく、通常のプレイと同じ装着処理、吸着アニメーション、成功演出、段階移行を通過させる。

自動テストでは入力待ち時間を短縮してよいが、各演出が実際に描画されることを確認できる時間を確保する。

ユーザー操作がないためAudioContextを起動できない場合は無音で続行し、音声の自動再生制限をゲームの異常として扱わない。

テスト完了後は、到達した段階、装着数、FPS、エラー数、完了状態をJavaScriptから確認できるようにする。

### 11.5. 実装上の注意

ゲーム画面、ソースコード、コードコメントには別紙の禁止語を使用しない。表記違いについても同様とする。

既存のキャラクター、ブランド固有のデザイン、作品固有の意匠は取り入れない。

不要なライブラリの追加、他のゲームの変更、共通ファイルの不用意な改変を行わない。

## 13. 最も重要な完成基準

本作で最も重要なのは、子どもが氷晶を一つ装着するたびに、確実に気持ちよさを感じられることである。

氷晶の吸着、澄んだ装着音、氷の内部を走る光、巨大結晶の成長。この四つを妥協なく作り込むこと。

最後には、自分の指で一つずつ組み立てた結晶によって、峡谷全体に美しい光が解き放たれる。

その瞬間に、自分がこの世界を変えたという実感が生まれるゲームに仕上げてください。
