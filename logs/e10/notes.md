# E10 ほうせきいろの ハチドリレストラン — 実装メモ

実装: `site/games/e10/index.html`（HTML + CSS + JS を1ファイル。Three.js r0.187.0 同梱版を importmap で読み込み。CDN・外部画像・外部モデル・音声ファイルなし。テクスチャは Canvas / DataTexture / シェーダーで生成）

## 実装の要点

- **遊び（2タップで1回の給餌）**: 画面中央の空のガラスピッチャー（または注ぎ口）をタップ → 注ぎ口のバルブが回り、金色の蜜が連続した流れ（毎フレーム頂点を更新する細いチューブ＋液滴）で注がれ、液面が約1.8秒で上昇して自動停止、縁を光が一周して澄んだ音。→ カメラが花形のガラス給餌器へ移動（ピッチャーも画面内）→ 給餌器をタップ → ピッチャーが浮かんで給餌器の上で傾き、蜜が弧を描いて流れ込む（ピッチャーの液面が下がり、給餌器の液面が上がる）→ 元の位置へ戻る。注ぎ終わり0.3秒でハチドリが飛来、空中静止→くちばしを飲み口へ→約1.5秒飲む（給餌器の蜜が減る、構造色の膜厚が変化、羽音と成功音）→ 近くのつぼみへ飛び、くちばしが触れてから開花（触れる前には開かない）→ 次の補充へ。
- **進行（定数 `CFG.feeds = [5, 6, 7]`、計18回）**: 第1段階は手前の切り株のランが1〜2輪。第2段階で桃色・紫色の給餌器が花のように開いて加わり、青紫・赤紫のハチドリ（計4羽）、1回に3〜5輪。第3段階で金緑・サファイア（計9羽）、2〜3羽が同時に飲み、それぞれ別のつぼみへ→1回に7〜10輪が連鎖。空は朝→昼→黄金色の夕刻へ約14秒の時定数で連続変化（夜にしない）。成功音は単音→和音→アルペジオ＋高音。
- **クライマックス（約14秒）→ 余韻10秒 → フリープレイ**: 最後の給餌で3羽が飲み、全9羽が中央の大きなランの群生へ。1羽が中央のつぼみに触れると中央の大輪→桃→紫→黄の順に開き、残りの全つぼみが距離に応じた波（小川の向こう岸まで）で開花、光の粒が舞い上がり、水面と水滴が金色に反射、ハチドリたちが群生の上を旋回、短いオリジナルの音楽（和音進行＋ハープ＋ベル）。余韻で給餌台へ戻り、フリープレイでは訪れる鳥・給餌器・色の順がランダム、咲いた花を訪れると花が揺れて光る。
- **ハチドリ**: 胴（Lathe・流線形、背／腹／喉の頂点色）、頭（楕円体）、細く尖るくちばし、黒い光沢の目、初列9枚＋次列6枚＋雨覆いの翼、尾羽7枚（扇状に開閉）、脚。MeshPhysicalMaterial の iridescence（0.82〜1.0 / IOR 1.4 / 120〜400nm）＋羽毛の鱗状法線マップ。羽ばたきは本体の翼（半透明）＋位相をずらした残像の翼＋ストローク範囲の半透明の扇で、ちらつかないようにしている。空中静止は上下の微動、飛行は CatmullRom スプラインでイーズ、給餌台は越えるよう経路を持ち上げる。飲む時はくちばしの先端位置を毎フレーム計算して飲み口に合わせる。5配色（エメラルド／青紫／赤紫／金緑／サファイア）。
- **ガラスと蜜**: 容器は外形プロファイルから厚みのある LatheGeometry（ピッチャーは注ぎ口を変形で作り取っ手は Tube）。mid/high は transmission 0.86〜0.93・roughness 0.07〜0.1・ior 1.47・thickness 0.025、low は環境反射＋透明度。蜜はガラスと別メッシュで、内径に沿ったリング状の頂点を毎フレーム更新（液面の上昇、傾けた時の水平な液面、注いだ直後の揺れ、メニスカス）。
- **ラン**: 萼片3・花弁2・唇弁・ずい柱を1つのジオメトリにまとめ InstancedMesh（約280〜590輪）。開花は頂点シェーダーで各花弁を付け根の軸回りに展開（萼片→花弁→唇弁の順に時間差、つぼみの時はねじれ・先端の巻き込み）、1.5〜2.0秒。自作の照明（巻き込み拡散＋背面からの透過光＋縁の光＋葉脈・喉の斑点・花弁上の水滴）、開花後に光の帯が中心から先端へ流れる。
- **庭園**: 多重ノイズの高さ場（極座標メッシュで遠いほど粗い）、側方の小川（複数方向の波・フレネル・浅瀬の色・クライマックスで金色）、山腹の滝2本、空シェーダー（グラデーション・太陽・流れる雲）、空から PMREM の環境マップ（空が一定以上変わった時だけ再生成）、熱帯の葉・シダ・草・ヤシ・森・岩（InstancedMesh、大きさ・角度・間隔をばらつかせる）、地面・葉・木部に低コストの木漏れ日模様（ゆっくり変化）、太陽方向の淡い光の筋。
- **カメラ**: 毎フレーム、操作対象と同時に見せる物の点群から縦横両方の画角で必要距離を計算（四辺に約12%の余白、ロールなし、FOV 40）。中心は対象に置き、周辺物に寄せるのは画面幅の一定割合まで。時間依存の指数補間（通常約1秒、全体は約2〜3秒）。クライマックスも同じ処理で、縦画面では横方向の広がりを詰めて群生を大きく保つ。
- **白飛び対策（前回の反省）**: ACESFilmic・露出1.0固定（変化させない）。ブルームは threshold 0.9、radius 0.45、強さ 朝0.2→夕0.55、クライマックス最大0.95。光の表現は花ごとの開花・花弁の光の帯・粒子・水面反射で行う。
- **誘導**: 対象の縁に淡い光（ピッチャーの縁リング・注ぎ口の光、給餌器のリングと中央の金色の光）。2.7秒無操作で縁を光が走り、5秒で対象が小さく揺れる（以後繰り返し）。文字・矢印・手のアイコンなし。関係ない場所のタップは何も起きない。待っているだけでは給餌は進まない。
- **入力**: Pointer Events（タッチ・マウス共通）、pointerdown で即反応、同時は1本のみ、pointercancel・回転・タブ切替で解除。Raycaster＋不可視の当たり判定（見た目の約1.5倍）＋画面上の最小64px半径＋中央付近は対象扱い。touch-action / overscroll / user-select / callout / ダブルタップ・ピンチ・長押しメニューを抑止。状態機械（INITIAL / WAIT_FILL / FILLING / WAIT_POUR / POURING / FEEDING / BLOOMING / TRANSITION / CLIMAX / AFTERGLOW / FREEPLAY）で、待ち状態以外の入力は無視。給餌回数は FEEDING 完了時に1回だけ加算。
- **音**: WebAudio のみ（最初のタップで生成／resume）。小川（帯域ノイズ）、葉擦れ、補充（ノイズ＋上昇する滴音）、ガラスの音、注ぐ音、羽音（周期変調した低音）、開花のハープ、ペンタトニックの成功音、控えめなパッド、クライマックスの音楽。マスターゲイン＋DynamicsCompressor。音が無くても進行に影響しない。
- **画質**: `?q=low|mid|high` で固定。指定なしは mid で開始し、3秒平均50fps未満で1段下げ、57fps超が約15秒続けば上げる（10秒以上のクールダウン、下げ2回後は上げない、注入・開花中は切り替えない）。ピクセル比上限 1.6/1.2/0.9、影 2048/1024/なし、粒子 500/250/100、翼の羽枚数、ガラス（透過／簡略透過／反射＋透明度）、ブルーム（通常／半解像度／なし）、水面の詳細度。
- **テスト用**: `window.__ready`, `window.__errors`, `window.__test`（状態・回数・画面内の位置など、画面表示なし）。`?autotest` は通常と同じ pointerdown/pointerup ハンドラーに合成イベントを流して18回の給餌を実行（背景タップ、補充中の連打、2本目の指、pointercancel、5.8秒の放置による誘導も確認）→ クライマックス → 余韻 → フリープレイ1回まで。`&speed=2..4` は autotest 時のみ時間を速める開発用。

## 確認結果（このクラウド環境）

- `python3 -m http.server`（ルート `site/`）＋ Playwright ヘッドレス Chromium（SwiftShader: `--use-angle=swiftshader --enable-unsafe-swiftshader`）で `games/e10/index.html?autotest&q=low` を 1024x768（横）と 768x1024（縦）で全工程実行。結果は `logs/e10/test.txt`（`tee` で保存、スクリプトは `logs/e10/run-test.js`）。
- **横・縦とも PASS**: `__ready === true`、`__errors` 空、コンソールエラーなし、18回の給餌 → クライマックス（最高潮に到達）→ 余韻 → フリープレイ1回まで完了。全281輪が開花。背景タップで何も起きない／補充中の連打を無視／2本目の指を無視／pointercancel で解除／2.7秒で縁の光・5秒で揺れの誘導、すべて true。各約6.5分（SwiftShader 約4〜5fps）。
- 操作待ち状態（カメラ到着後）の操作対象の画面中心からのずれは最大 NDC 0.16〜0.18（横）／0.18・0.15（縦）。クライマックスは群生が中央（tx 0）、全点が画面内。
- `?q=mid`（横）と `?q=high`（縦）は短時間の起動・操作確認で PASS（`logs/e10/test-quality-smoke.txt`）。
- スクリーンショット（すべて JPEG・300KB以下）: `shot-1.jpg`（序盤・給餌器への注入待ち）、`shot-2.jpg`（中盤・9回目の給餌中）、`shot-3.jpg`（クライマックス約10秒＝光が最も多い時間帯）、`shot-4.jpg`（フリープレイ）、`p-shot-1〜3.jpg`（縦）。クライマックスでも白飛びせず、花の形・小川・山・滝・空が見える。
- サムネイル: `site/thumbs/e10.jpg`（640x480、約69KB、q=mid のクライマックス約9.6秒、文字なし）。
- 禁止語（ひらがな・カタカナ表記を含む）が `site/games/e10/` と `logs/e10/` にないことを grep で確認。

## 未解決・注意点

- iPad Safari 実機での動作・FPS・タッチ感触・音は未確認。SwiftShader（CPU描画）の FPS（low で約4〜5fps）は性能の指標にならない。
- ランの本数・地形の分割数・草の本数は起動時の画質で決まり、実行中の画質変更では作り直さない（影・粒子・ガラス・ブルーム・水面・翼は切り替わる）。
- 森の樹冠は遠景用の簡略形状のため、広い画面では質感が単純に見える。遠景はやや霞が強く、近景の画面では空の青は上端に少し見える程度（広い画面・クライマックスでは空と山・滝が見える）。
- 自動画質調整は autotest 中は無効（`q` 固定で検証）。実機での切り替えの挙動は未確認。
- 長時間のフリープレイは使い回し（粒子・液滴はプール、音ノードは使い捨て）で増え続けない設計だが、10分以上の計測はしていない。
