# E14 実装指示文：あめあがりの ほうせきパラソル

## 1. ゲームの狙い

雨が上がったばかりの瑞々しい草原を舞台に、宝石のような水滴をまとった大きなパラソルを、自分の指で次々と開いていく写実3Dウェブゲームを実装する。

- **夢×写実：** 濡れた草の質感、精巧な傘の骨組み、水滴の表面張力と光の反射を写実的に再現しながら、現実には存在しないほど美しいパラソルが並ぶ幻想的な草原を作る。
- **高揚感：** 一つのパラソルを開く小さな喜びから始まり、やがて草原一面のパラソルが回転し、水滴が光を受けて舞う壮大な祭典へと発展させる。
- **爽快感：** 閉じていた傘が張力によって一気に広がり、蓄えられていた大量の水滴が放射状に飛び散る瞬間に、強い視覚的・聴覚的な快感を生み出す。

対象は、文字をまだ読めない5歳の子どもである。説明を受けなくても、目の前のパラソルを触り、開き、結果を楽しめるようにする。

本作の主役は、光の演出そのものではなく、**傘が開く機械的な動きと、その動きによって水滴が飛び散る物理現象**である。鑑賞するだけの映像作品にせず、自分の操作によって美しい現象が起こることを最優先する。

## 2. 絵から借りる光と色

### 2.1 美術の基本方針

提示されたアルヒープ・クインジの作品から、雨上がりの草原に陽光が差し込み、大地の緑色が鮮烈に浮かび上がる光の仕組みを借りる。

原画の構図、筆致、暗い空は再現しない。

現実と想像が溶け合う海洋幻想絵画のような写実性と、上質なファンタジー映画に見られる魔法の光、色彩、驚きの空気感を、独自の3D空間として構築する。

幻想性は次の要素から生み出す。

- 雨によって洗われた鮮やかな草原。
- 雲の切れ間から差し込む金色の陽光。
- 真珠、オパール、色ガラスを思わせるパラソル。
- 空や草原の色を映し込む透明な水滴。
- 水滴が太陽光を受けた瞬間に生じる鋭い輝き。
- 遠くまで続く草原と、風によって揺れる草や傘。

画面全体に発光処理をかけるのではなく、濡れた物体の表面に光が集中することで、幻想的な印象を作る。

### 2.2 色彩と光源の設定

ゲームの進行に伴い、雨上がりの午前から黄金色の午後へと光を変化させる。時間帯の変化は演出上のものであり、夜には移行しない。

以下の数値をThree.jsにおける初期調整値とする。

| 項目 | 第1段階：雨上がり | 第2段階：陽光の草原 | 第3段階：黄金の草原 |
|---|---|---|---|
| 空の上部 | `#70BDEB` | `#59BBF1` | `#77B9E8` |
| 地平線付近 | `#DCECEF` | `#DEF5FA` | `#FFE8BC` |
| 草の基本色 | `#45972D` | `#65B53D` | `#83B849` |
| 草の影 | `#285D39` | `#316E42` | `#407047` |
| 太陽光の色 | `#FFF4DF` | `#FFF1D2` | `#FFDBA0` |
| 太陽光の色温度 | 約5800K | 約5400K | 約4400K |
| DirectionalLight強度 | 2.0 | 2.4 | 2.7 |
| HemisphereLight強度 | 1.3 | 1.5 | 1.6 |
| 霧の色 | `#D7EBE8` | `#D5EEF4` | `#F2E4CC` |
| Fog開始距離 | 35 | 45 | 50 |
| Fog終了距離 | 150 | 180 | 200 |
| ブルーム強度 | 0.30 | 0.45 | 0.65 |
| 露出 | 1.0 | 1.05 | 1.10 |

光源の強度は同梱Three.jsのバージョンや環境マップとの組み合わせに応じて調整する。

太陽は画面に対して斜め前方または斜め後方に配置し、傘の縁や水滴に輪郭光が生じる位置を選ぶ。真正面から強い逆光を当てて、操作対象が見えなくなることは禁止する。

月光は使用しない。夜景や暗転による場面転換も不要である。

### 2.3 発光と反射

トーンマッピングには `ACESFilmicToneMapping` を基本として使用する。出力色空間とポストエフェクトの設定を適切に組み合わせ、二重のトーンマッピングを避ける。

ブルームのしきい値は0.85〜1.0、半径は0.2〜0.4程度とする。

クライマックスでもブルーム強度は最大1.2程度とし、露出を急激に上げない。最も光が強くなる瞬間でも、傘の骨組み、パラソルの色、空の青、草原の緑が識別できること。

光の筋を表現する場合は、雲の切れ間から地面へ伸びる低不透明度の半透明メッシュなど、処理負荷の小さい手法を使用する。画面全域のボリューメトリックレイマーチングは必須としない。

## 3. 舞台と登場するもの

### 3.1 草原と地形

舞台は、緩やかな起伏を持つ広大な草原とする。

地形はPlaneGeometryを分割し、複数の低周波ノイズや三角関数を組み合わせてプロシージャル生成する。

世界の1単位をおおむね1mとして扱い、次の規模を目安とする。

| 対象 | 大きさの目安 |
|---|---:|
| 草原 | 220 × 220m |
| 草原の起伏 | 0.2〜2.5m |
| パラソルの高さ | 2.5〜4.5m |
| 展開後の傘の直径 | 2.8〜5.5m |
| パラソル同士の間隔 | 5〜8m |
| 全パラソルの数 | 18本 |

草は細長い三角形または曲面メッシュをInstancedMeshで大量配置する。一本ずつ独立したMeshを作らない。

草の高さ、傾き、色、太さには個体差を与える。頂点シェーダーによる風の揺れを実装し、草原全体を風の波が通り抜けるようにする。

雨上がりの質感を出すため、草の先端に小さな鏡面反射を設ける。草のすべてに水滴メッシュを配置する必要はない。

地面が単一の緑色の平面に見えないよう、低周波の色むら、草の密度差、わずかな湿潤度の変化を与える。

### 3.2 水たまり

草原の低い場所に、大小の浅い水たまりを配置する。

水たまりは不規則な輪郭を持つ平面メッシュとして生成する。水面シェーダーには以下の要素を取り入れる。

- フレネル反射。
- 複数方向の微細な法線のゆらぎ。
- 空や雲を近似した環境反射。
- 水底の草や土を思わせる色。
- 落下した水滴によって広がる同心円状の波紋。

水面全体を常時別カメラで描画する必要はない。環境マップや解析的な反射表現を優先する。

### 3.3 空と雲

空は大型の球体または背景シェーダーを使い、天頂から地平線に向けて自然な色の勾配を作る。

雲はプロシージャルなノイズ、半透明メッシュなどを組み合わせて生成する。雨雲の名残を遠方に少量配置してもよいが、空の大部分は青空と白い雲で構成する。

雲はゆっくり移動し、草原への陽光がわずかに変化するようにする。

### 3.4 宝石のパラソル

パラソルは本作で最も精巧に作り込む対象である。

単なる円錐や半球として作らず、実際の傘の構造を参考に、以下の部品を独立してプロシージャル生成する。

- 中央の支柱。
- 上下に移動する持ち手兼スライド機構。
- 8〜12本の親骨。
- 親骨を押し広げる受骨。
- 親骨の先端部品。
- 傘の頂点にある金属製の飾り。
- 骨と骨の間に張られた曲面状の傘生地。
- 傘生地の縫い目と縁の細い装飾。

開閉時には、受骨が親骨を押し上げ、傘生地が徐々に張っていく構造を再現する。

開閉率を0〜1の連続値として管理し、その値から親骨の角度、受骨の位置、生地の曲面形状を一貫して計算する。

閉じた状態と開いた状態のモデルを瞬時に切り替える実装は禁止する。

### 3.5 パラソルの素材

複数の素材を用意し、開くたびに異なる美しさを楽しめるようにする。

| 素材 | 基本色 | Roughness | 特徴 |
|---|---|---:|---|
| 真珠 | `#F5ECEA` | 0.22 | 白銀色と淡い桃色の反射 |
| 桜色の色ガラス | `#F19AC5` | 0.15 | 光が透過する花弁状の生地 |
| アクアマリン | `#71D9D9` | 0.12 | 水色と青緑色の透過感 |
| アメジスト | `#B79CEB` | 0.18 | 紫色の深みと繊細な反射 |
| シャンパンゴールド | `#F4D08E` | 0.24 | 金色の光沢 |
| オパール | `#DDECF6` | 0.20 | 視線の角度による色の変化 |

`MeshStandardMaterial` および `MeshPhysicalMaterial` を使用する。

真珠やオパールには、対応するバージョンであればClearcoatやIridescenceを利用する。色ガラスの表現にはTransmissionを利用してもよいが、iPadでの負荷を考慮し、フレネル反射や色の勾配による近似表現を用意する。

環境マップは、空、太陽、雲、草原の色を含む独自の環境シーンから生成し、PMREMなどで処理する。外部HDRIは使用しない。

### 3.6 宝石のような水滴

閉じた傘の表面には、多数の水滴が付着している。

水滴は完全な球体ではなく、傘生地と接する部分がわずかに平らになった形状とする。大きな水滴には重力方向への変形も加える。

大きさは直径0.02〜0.09m程度とし、実物より少し強調することで、子どもにも運動が見えるようにする。

水滴の材質の目安は以下のとおり。

- IOR：1.333。
- Roughness：0.03〜0.10。
- Metalness：0。
- フレネル反射：視線が浅い角度になるほど強くする。
- 内部色：ほぼ無色。周囲の空や草原の色をわずかに取り込む。
- 鏡面反射：太陽の方向に応じて小さく鋭い輝きを発生させる。

すべての水滴に重い屈折計算を適用せず、InstancedMeshと専用シェーダーを使用して透明感を近似する。

水滴はあくまで水であり、実際の宝石が傘から飛び出す表現にはしない。

### 3.7 その他の登場物

人間、動物、乗りものは登場させない。草原とパラソル、水滴だけで魅力的な世界を成立させる。

すべての形状、模様、音をプログラムによって生成し、外部の画像、3Dモデル、テクスチャ、音声ファイルを使用しない。

## 4. 指1本のループ

### 4.1 ゲーム開始

起動直後から草原が表示され、画面中央には閉じた真珠色のパラソルが1本立っている。

傘の持ち手には陽光が当たり、数秒間隔で金色の反射が走る。傘の表面には水滴が付着しており、風に反応してわずかに揺れている。

開始専用のボタンやメニューは設けない。パラソルに触れること自体をゲームの開始操作とする。

### 4.2 1回の基本ループ

| 経過 | 子どもの操作 | 画面内の反応 |
|---|---|---|
| 課題提示 | 次の傘を見る | 閉じた傘が中央に配置される |
| 接触 | 傘の持ち手に触る | 持ち手が輝き、短い金属音が鳴る |
| 取り組み | 指を上へ動かす | 受骨が動き、傘が徐々に広がる |
| 解放 | 一定の高さまで押す | 傘が勢いよく完全に開く |
| 結果 | 飛び散る水滴を見る | 水滴が弧を描いて飛び、陽光を反射する |
| 余韻 | 開いた傘を見る | 傘がゆっくり回転し始める |
| 次の課題 | 次の傘に触る | カメラが次の傘を中央に収める |

画面の短辺に対して約8〜12％の上方向ドラッグで、傘が完全に開く仕組みとする。

開閉率が0.55〜0.65に達した段階で、残りの動作を自動的に補助する。指を大きく動かしたり、正確な方向に動かしたりする必要はない。

途中で指を離しても、現在の開閉率を保持する。タップだけでも、少し間を置いて持ち手が自動的に上昇し、傘を開けるようにする。ただし、ドラッグした場合は指の動きと傘の動きが直接連動する体験を優先する。

### 4.3 傘が開く瞬間の手ごたえ

この瞬間を本作で最も重要なアニメーションとして扱う。

開閉率が一定値を超えたら、約0.3〜0.45秒かけて傘が一気に広がる。

完全展開の直前に親骨がわずかにしなり、傘生地が張る。完全展開後は、親骨と生地が約0.4秒かけて小さく振動し、静止する。

それと同期して、次の演出を実行する。

- 親骨が固定される瞬間の小気味よい「カチッ」という音。
- 傘生地が広がる際の「シュパッ」という空気音。
- 傘の縁を一周する鏡面反射。
- 水滴が生地から離れ、放射状に飛び散る動き。
- 水滴が陽光を横切る瞬間のきらめき。

操作から結果までに不自然な遅延を設けない。

### 4.4 水滴の飛散

水滴は傘が開く速度と方向に応じて飛び出す。

各水滴の初期位置を傘表面から取得し、外向きの速度、上方向の速度、傘の回転による接線方向の速度を与える。

初期値の目安は次のとおり。

- 外向き速度：2.0〜5.5m/s。
- 上向き速度：0.8〜3.0m/s。
- 重力加速度：7.0〜9.8m/s²。
- 空気抵抗：わずかに付加する。
- 飛行時間：約0.8〜1.8秒。
- 1本あたりの水滴数：80〜240個。

大きな水滴は弾道がはっきり見え、小さな水滴は霧に近い飛沫となる。

地面に落ちた水滴は小さな飛沫を発生させ、水たまりに落ちた水滴は波紋を作る。

水滴が傘と無関係な位置から出現したり、花火のように爆発したりする表現は禁止する。

### 4.5 操作に迷った場合

操作が2.5〜3秒間行われなければ、持ち手に陽光の反射が走る。

さらに操作されなければ、持ち手が上下に2〜3cm動き、金属製のスライド機構が操作可能であることを自然に示す。

文字、矢印、手のアイコンは使用しない。

操作対象以外を触っても、悪い結果は発生しない。時間制限、減点、失敗音、ゲームオーバー、やり直しの強制は一切設けない。

## 5. 盛り上がりの設計

通常の操作速度で約3〜5分、全3段階、合計18本のパラソルを開く構成とする。

各段階では同じ開閉操作を維持し、傘の大きさ、素材、開いたときの水滴の量、周囲の景色、音楽を変化させる。新しい操作方法を覚えさせる必要はない。

| 段階 | 本数 | 主な体験 |
|---|---:|---|
| 第1段階 | 6本 | 傘を開く楽しさを知る |
| 第2段階 | 6本 | 色ガラスと大量の水滴を楽しむ |
| 第3段階 | 6本 | 巨大な傘と草原全体の変化を楽しむ |
| クライマックス | 全18本 | パラソルの祭典 |
| 余韻 | 約12〜18秒 | 光と水滴の静かな舞 |

### 5.1 第1段階：雨上がりの小さな喜び

真珠色、淡い桃色、水色のパラソルが点在する草原から始まる。

1本開くごとに、次の傘が見える位置へカメラを移動する。開いた傘は閉じず、背景に残して達成の積み重ねを見せる。

傘の直径は約2.8〜3.5m。水滴は1本あたり80〜120個程度とする。

6本目を開いたところで、雲の切れ間が広がり、草原に差し込む陽光が増す。

### 5.2 第2段階：色ガラスの草原

色彩豊かなパラソルを開いていく。

傘の直径を3.5〜4.5m程度に拡大する。水滴は120〜180個程度とし、傘から飛び出した水滴が以前より遠くまで届くようにする。

すでに開いた傘もゆっくり回転する。傘を開くたびに、草原の濡れた表面へ色付きの反射が広がる。

陽光が傘を透過する印象は、地面に投影した低不透明度の色付き模様などで近似してもよい。

### 5.3 第3段階：黄金の光と大きなパラソル

直径4.5〜5.5mの大型パラソルが中心となる。

オパールやシャンパンゴールドの素材を登場させる。開く際の動作には、それまでより大きな張力と重量感を持たせる。

水滴は180〜240個程度とし、傘の縁全体から一斉に飛び散る。

18本目は草原の中心に配置した特別な大型パラソルとする。この傘を開く操作が、そのままクライマックスの開始条件になる。

### 5.4 クライマックス：パラソルの祭典

最後の傘を開くと、次の一連の演出を約10〜12秒かけて実行する。

| 経過時間 | 演出 |
|---|---|
| 0〜1秒 | 中央の大型パラソルが勢いよく開く |
| 1〜3秒 | 中央から外側へ、順番に傘の回転が始まる |
| 3〜5秒 | 全パラソルの縁から水滴が弧を描いて飛び出す |
| 5〜8秒 | 水滴が草原全体に広がり、陽光を反射する |
| 8〜12秒 | 光の輝きと音楽が次第に落ち着く |

全18本のパラソルは、通常の開閉とは別に、頂点や傘生地の縁に少量の水滴が残っている状態とする。これらが回転によって放出されることで、クライマックスの現象に物理的な説得力を持たせる。

回転速度は通常時2〜4rpm、クライマックス時5〜8rpm程度を上限の目安とする。

水滴の放出は全18本を完全に同時とせず、中心から外側へ時間差をつける。草原を光の波が伝わる印象を作りながら、描画負荷も分散する。

最も光が強い瞬間でも、ブルーム強度1.2程度、しきい値0.8以上を守る。白一色の画面、閃光、激しい点滅は使用しない。

### 5.5 余韻とフリープレイ

クライマックス後は、草原の風、水滴の落下、傘のゆっくりした回転を約12〜18秒楽しめる状態とする。

その後、中央のパラソルをゆっくり閉じ、再び水滴が付着した状態に戻す。

子どもがその傘を触れば、再度開いて遊べる。その後も別の傘が順番に操作対象となる、回数無制限のフリープレイへ移行する。

終了画面、成績表示、再開ボタンは不要である。

## 6. カメラ

カメラは自動制御とし、子どもに視点操作を要求しない。

通常時はPerspectiveCameraを使用し、垂直FOVは38〜48度を目安とする。

現在のパラソルを常に画面中央に配置し、持ち手が画面の中央付近から下寄りに位置するよう調整する。

閉じた傘だけでなく、完全展開後の傘の大きさまで考慮して撮影距離を決定する。開いた瞬間に傘の端が見切れてはならない。

カメラ制御では次を徹底する。

- 次の操作対象の中心を画面中央に置く。
- 操作中はカメラを原則として固定する。
- 傘が開く前後で急なズームを行わない。
- 次の傘への移動は1.5〜2.5秒程度とする。
- イージングによる滑らかな加減速を使用する。
- 地平線を傾けない。
- カメラの振動や急旋回を使用しない。
- 開いた傘も背景に残し、達成の積み重ねを見せる。

クライマックスでは、中央の大型パラソルを注視しながらカメラをゆっくり引き、全18本を見渡せる斜め上方の視点へ移行する。

縦向きと横向きでは単純な画面の切り抜きを行わず、完全展開時の傘またはクライマックス対象全体のBoundingBoxを基準に、水平・垂直両方向のFOVから必要な撮影距離を計算する。

主役の外形が画面の中央80〜85％程度の範囲に収まることを目安とする。

画面サイズ変更時にも、カメラのアスペクト比、描画サイズ、撮影距離を再計算する。

## 7. 操作と入力処理

iPad Safari、iPhone Safari、PCブラウザのタッチおよびマウス操作に対応する。

Pointer Eventsを使用し、`pointerdown`、`pointermove`、`pointerup`、`pointercancel` を適切に処理する。

最初に接触したpointerIdだけを操作対象とする。2本目以降の指は無視する。

持ち手の当たり判定は見た目より広く設け、傘の支柱や生地を触った場合でも現在のパラソルを操作できるようにする。

Canvas上のRaycaster判定に加え、画面座標による拡張判定を使用してもよい。操作対象の最小当たり判定は直径70〜100CSS px程度を目安とする。

ドラッグ開始時にはPointer Captureを使用する。指が対象から少し外れても操作を継続できるようにする。

ゲーム領域には `touch-action: none`、`user-select: none`、`-webkit-touch-callout: none` などを適用し、ページのスクロール、ダブルタップズーム、ピンチズーム、長押しメニューを可能な範囲で抑止する。

必要に応じてSafariのジェスチャーイベントや非passiveイベントリスナーも使用する。

`pointercancel` や画面外への指の移動が発生しても、ゲームが操作不能にならないこと。

## 8. 音の設計

すべての音をWebAudio APIで手続き的に合成する。

最初のユーザー操作でAudioContextを生成またはresumeし、以降の音を再生する。

| 音 | 合成方法 |
|---|---|
| 持ち手の接触音 | 短い正弦波と高周波成分 |
| 骨組みの動作音 | フィルターを通した短いノイズ |
| 傘が開く音 | 帯域を変化させた空気音と金属音 |
| 水滴の飛散音 | 細かなノイズと短い高音 |
| 水面への落下音 | 周波数が下降する正弦波 |
| 草原の風 | ローパスフィルターを通したノイズ |
| 水滴の輝き | 短いベル系の倍音 |

成功音は第1段階では単音、第2段階では2〜3音、第3段階では豊かな分散和音へ発展させる。

クライマックスでは、傘の回転と水滴の放出に同期して、複数の音が一つの協和音へ集まる演出を行う。

BGMは風の音と控えめな持続音を中心とする。操作音を妨げるほど大きくしない。

大量の水滴それぞれに音源を作らず、複数の水滴を一つの飛沫音にまとめる。マスター出力にはDynamicsCompressorNodeを使用し、音量の急増を防ぐ。

## 9. 画面の文字とUI

ゲーム画面には文字、数字、タイトル、説明、得点、進捗バー、ボタンラベルを一切表示しない。

進行状況は、開いたパラソルの本数と草原の変化によって自然に伝える。

操作対象そのものをUIとして機能させる。画面上に操作パネルや装飾的なHUDを重ねない。

開始からクライマックス、フリープレイまで、文字を読む必要が一度もないこと。

## 10. 画質の自動調整

iPad Safariで50fps以上を目標とする。特に、傘が開く瞬間と水滴が大量に飛び散る瞬間のフレームレートを重視する。

| 設定 | high | mid | low |
|---|---:|---:|---:|
| 最大ピクセル比 | 1.5 | 1.1 | 0.85 |
| 草のインスタンス数 | 28,000 | 15,000 | 6,000 |
| 同時水滴数上限 | 1,600 | 800 | 350 |
| シャドウマップ | 2048 | 1024 | 512または簡易影 |
| 生地の分割数 | 多 | 中 | 少 |
| ブルーム | 通常 | 低解像度 | 簡易発光で代替 |
| 水滴の屈折表現 | 高精度近似 | 簡易近似 | フレネル中心 |
| 傘の透過表現 | 一部有効 | シェーダー近似 | 不透明素材で近似 |

自動設定ではmidを基本として起動時に描画負荷を測定する。

実行中もFPSを継続的に監視し、約3秒間48fpsを下回る場合は1段階品質を下げる。約10秒間57fps以上を維持した場合は、余裕があると判断して品質を上げてもよい。

頻繁な品質変更を防ぐため、切り替え後は一定時間の待機期間を設ける。

品質設定は `?q=low`、`?q=mid`、`?q=high` で強制指定できるようにする。強制指定時には自動変更を停止する。

品質を下げても、パラソルの開閉機構、飛散する水滴、クライマックスの全体構成は維持する。

ジオメトリとマテリアルの共有、InstancedMesh、オブジェクトプールを積極的に活用する。アニメーションの各フレームで大量のオブジェクトを生成・破棄しない。

## 11. 技術構成

### 11.1 ファイルとライブラリ

ゲーム本体は以下の1ファイルに実装する。

`site/games/e14/index.html`

HTML、CSS、JavaScriptをこのファイル内にまとめる。

Three.jsはリポジトリに同梱されている以下のファイルを使用する。

- `site/vendor/three/build/three.module.min.js`
- `site/vendor/three/examples/jsm/`

importmapで `three` を `../../vendor/three/build/three.module.min.js` に、`three/addons/` を `../../vendor/three/examples/jsm/` に対応させる。

同梱バージョンで利用できるAPIを確認して実装する。CDN、外部API、外部素材、追加のネットワーク依存は禁止する。

`<head>` 内には次の要素を必ず入れる。

`<meta name="robots" content="noindex">`

`</body>` の直前には次のスクリプトを必ず入れる。

`<script src="../../gf-playlog.js" defer></script>`

指定されたゲームファイル以外の既存ゲームや共通ライブラリを、不必要に変更しない。

### 11.2 状態管理

次の状態を明示的に管理する。

`START → TARGET_READY → OPENING → SPLASH → NEXT_TARGET → CLIMAX → AFTERGLOW → FREE_PLAY`

傘ごとに開閉率、付着水滴、開閉済みフラグ、回転角度を管理する。

同一の傘を連続タップしても、進行回数が重複加算されないようにする。

ページが非表示になった場合はアニメーションと音を一時停止する。復帰時に時間差が一度に適用されないようにする。

### 11.3 準備完了とエラー監視

初期化前に `window.__ready = false` とし、`window.__errors` を空配列として用意する。

グローバルエラーと未処理のPromise rejectionを捕捉し、`window.__errors` に記録する。

シーン、カメラ、入力処理、主要モデルの初期化が完了し、最初の描画が成功した時点で `window.__ready = true` とする。

### 11.4 自動プレイ

`?autotest` を指定すると、全18本の傘を自動的に開き、全段階、クライマックス、余韻、フリープレイへの移行まで確認できるようにする。

自動プレイでは通常操作と同じ開閉処理と状態遷移を使用する。完成状態へ直接書き換える方法でテストを省略しない。

ユーザー操作がないためAudioContextを起動できない場合は、無音で自動プレイを継続する。

自動プレイの結果、完了した傘の本数、最終状態、FPS、エラーの有無を開発者がコンソールから確認できるようにする。

### 11.5 禁止事項

別紙の禁止語は、コード、コードコメント、変数名、画面表示、実装に付随する説明文に使用しない。表記を変えた使用も禁止する。

既存のキャラクター、ブランド、映画の意匠、城などを模倣しない。不穏な生き物や超自然的な存在も登場させない。
