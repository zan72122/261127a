# E05 ひかりの ガラスおんしつ — 実装メモ

実装: `site/games/e05/index.html`（HTML + CSS + JS を1ファイル。Three.js r0.187.0 同梱版を importmap で読み込み。CDN・外部画像・外部モデル・音声ファイルなし）

## 実装の要点

- **遊び**: 巨大なガラス温室（幅18m・奥行34m・軒高9m・頂部14m、真鍮のアーチ・柱・母屋・トラス・ボルト）。天井の内側に吊った「色ガラスの天井（4区画×5枚＝20枠）」に、指1本で色ガラスをはめていく。
  - 開始時は中央にローズ色のガラス1枚と、その奥で金色に光る空の枠だけ。タイトル・説明・ボタンなし。ガラスに触れると開始。
  - 以後は画面中央下寄りに色ガラスが3枚浮かぶ（第1段階: ローズ・アクア・アンバー／第2段階: ＋エメラルド・サファイア／第3段階以降: ＋アメジスト）。どの色でも成功。
  - ドラッグ: 候補の位置と枠を結ぶ仮想平面上を指に追従。進み具合に応じて、ガラスの向きが「こちら向き」から「天井と平行」へ自動補正される。枠に画面上で近づく（短辺の12%か74px以内）と磁石のように吸着（240ms）。途中で離すと0.7秒で元の位置へ戻る（失敗表現なし）。
  - タップ操作も可: ガラスをタップ → 少し持ち上がり、枠の方向へ少し傾く → 枠のあたりをタップで装着。
  - 放置時: 3秒で縁のきらめきが強まる／6秒でガラスが数cm持ち上がって戻る／10秒で枠とガラスが同じリズムで光る（自動装着はしない）。
  - 装着の手ごたえ: 真鍮の金属音（0ms）→ ガラスの縁を光が一周（80〜480ms）→ 床に色の波が広がる（100〜500msで半径7m）→ さらに葉・柱・水路へ伝わる（〜1.1sで半径17m）→ 光の粒と和音の余韻（800ms〜）。
  - 4段階（5枚ごと）: 時間帯が午前10時 → 正午 → 午後2時 → 午後4時へ約6.5秒かけて連続変化（空・太陽色・太陽高度・方位・霧・環境マップ・ブルーム）。太陽が動くので、完成した色の列が床の上をゆっくり移動する。15枚目のあとは完成した区画が数度だけ揺れて、クライマックスを予感させる。最後の1枚は天井中央（真鍮の歯車機構のとなり）。
  - クライマックス（24秒）: 0〜3秒 20枚の縁を順番に光が走る → 3〜7秒 真鍮の機構（中央の歯車）が回り始め、4区画が動き出す → 7〜20秒 各区画が軸まわりに最大18°傾き、軸方向に最大0.9mスライド。床・植物・柱の色模様が実際のパネルの動きに連動して流れる → 15〜20秒 最も豊かな和音 → 20〜24秒 穏やかに停止。その後10秒の余韻 → フリープレイ。
  - フリープレイ: 中央の3枚のガラスを好きな枠へ運ぶと色を交換できる。中央の真鍮の歯車をタップすると天井の開閉（約9.5秒）をもう一度楽しめる。温室は消さない。
- **最重要: 色ガラスを透過する光**（共通シェーダー関数 `glassLight`）
  - 床・植物（葉・花・実・茎・鉢）・柱・真鍮・水路の各マテリアルに `onBeforeCompile` で同じ関数を注入。各ピクセルのワールド座標から太陽方向へ光線を伸ばし、最大24枚のガラス（天井の20枚＋手元の候補3枚）の矩形と交差判定する。ガラスの中心・2軸・色は毎フレーム、実際のガラスの world 行列から作るので、ガラス本体と光の位置が常に一致する（ドラッグ中も、クライマックスで傾くときも）。
  - 光の境界は 0.05m＋距離×0.011m の半影、真鍮の縁の影の帯、ガラスの厚みむらによるゆらぎあり。重なった色は平均して混色、被覆率は上限ありで過露出しない。床の色は「照明の乗算」で付けるため大理石の鉱脈・目地・影（mid/high のシャドウマップ）が透過光の下でも見える。
  - 植物・建築への届き方は段階で増やす（第1段階 0.4 → 第2段階 0.8 → 第3段階以降 1.0。床は常に 1.0）。
  - 光芒: ガラスの4隅から床まで太陽方向に伸ばした半透明の筒（加算合成、ごく弱い・ちりのゆらぎ付き）。1メッシュで描画。
  - 光の粒: 光芒の中にちりの粒（プール方式、上限 high 450 / mid 180 / low 60）。
- **絵作り**: 空はグラデーション＋太陽＋流れる雲のシェーダー。白い大理石の床は手続き生成（鉱脈・タイル目地・法線マップ、roughness 0.28、metalness 0）。植物は葉脈テクスチャ付きの湾曲メッシュ（中央の折れ・先端の垂れ・色の個体差）を InstancedMesh で配置: 鉢植えのシクラメン（ピンク・白）、赤い実のトマト、大きな葉の観葉植物、シダ、ヤシ、つる植物（上から垂れる）、小さな白い花。頂点シェーダーで揺れ。葉は太陽側から見ると透けて見える項あり。両側に細い水路（2〜3波の法線、フレネル、透過光の映り込み）。外は芝生・低木・遠景の木（大気遠近）。
  - 色ガラス: 1.4m×1.8m、面取り付き、真鍮の縁。high は MeshPhysicalMaterial（transmission 0.9、ior 1.5、roughness 0.06）、mid/low は環境反射＋フレネルの軽量な透明表現。表面を周期的に光の帯（太陽の反射）が横切り、縁がきらめく。環境マップは手続き生成シーンから PMREM で作成（段階が変わったときだけ再生成）。
  - トーンマッピング ACESFilmic、出力 sRGB（ポストプロセス時は OutputPass のみで1回だけ適用）。露出 1.0（クライマックス最大 1.04）。ブルーム強度は段階ごと 0.20〜0.65、クライマックス最大でも `Math.min(1.1, …)`。
  - **白飛び対策（前回の反省）**: 画面全体のフラッシュなし。ブルームのしきい値はリニア HDR 値 1.9（指示文の 0.85〜1.0 だと日なたの白い床全体がにじむため）。最初の試作ではクライマックスで光芒（加算合成）が20本重なって画面中央が白くかすんだため、光芒の濃さを約1/3に下げた。最終のクライマックス最大時のスクリーンショットで、空の青、真鍮の骨組み、ガラスの色と輪郭、植物が見えることを確認。
- **カメラ**: 高さを固定（通常 4.0m、全体 4.3m）し、「天井の枠＋候補ガラス」をひとつの注視対象として、上下の角度が画面中央にそろうように仰角と距離を計算（毎フレーム、画面比から縦横の視野角を計算）。縦画面は視野角を広げて横幅を確保。ロール 0、ドラッグ中はカメラを動かさない。次の枠へは約1.5秒でなめらかに移動。クライマックス・フリープレイは天井全体と床を収める引きの構図（ゆっくり後退）。
- **音**: WebAudio のみ（最初のタップで AudioContext 生成/resume）。ガラス音（正弦波＋非整数倍音、0.2〜0.8秒で減衰）、真鍮の接触音、上昇する倍音、機構の低い音、Cメジャー・ペンタトニック（第1段階 単音 → 第2段階 二音 → 第3段階 三和音 → 第4段階 広い和音）。風・水・葉の環境音（フィルターしたノイズ）、ドラッグ中の空気音。マスター 0.2＋DynamicsCompressor＋簡易リバーブ。タブ非表示で suspend。
- **入力**: Pointer Events、最初の pointerId だけ追跡（2本目以降は無視）、setPointerCapture、pointercancel で元に戻す。当たり判定は画面上でガラスの見た目より大きく（最小半径48px＝直径96px）。タップとドラッグの境は10px。タッチ時はガラスを指より少し上に表示。touch-action / overscroll / user-select / callout を無効化、gesture・dblclick・contextmenu・2本指 touchmove を抑止。同じガラスの二重装着・二重加算を防止（装着開始時にポインタから切り離す）。
- **画質**: `?q=low|mid|high` で固定（自動調整なし）。指定なしは mid から開始し、描画間隔の EMA で 3秒 50fps 未満なら1段階下げ、9秒 57fps 超なら上げる（10秒の再変更抑制、ドラッグ中・クライマックス中は変更しない）。
  - high: PR 1.75 / 影 2048 / ブルーム（フル）/ 粒 450 / 植物 100% / transmission ガラス
  - mid: PR 1.25 / 影 1024（3フレームに1回更新）/ ブルーム半解像度 / 粒 180 / 植物 75%
  - low: PR 1.0 / 影 512（`?q=low` 強制時は影なし）/ ブルームなし（縁の光の帯が疑似発光）/ 粒 60 / 植物 50% / 水面は波を弱く
  - どの画質でも「床と植物への色の投影」は同じシェーダーで維持。
- **状態**: READY / SELECT / DRAG / SNAP / CELEBRATE / TRANSITION / CLIMAX / AFTERGLOW / FREEPLAY。`window.__ready`、`window.__errors`、`window.__test`（state, placed, stage, climaxReached, climaxT, afterglowReached, freeplayReached, replaced, wheel, done, fps, q など）。`?autotest` は通常と同じ onDown/onMove/onUp に合成イベントを流して20枚を装着（4枚に1回はタップ→タップ操作）、クライマックス・余韻・フリープレイ（色の交換1回・歯車タップ1回）まで進む。無音でも進行する。
- **画面の文字**: なし（ロード中は CSS の色ガラス風の四角が揺れるだけ）。

## 確認結果（このクラウド環境）

- `python3 -m http.server`（ルート `site/`）＋ Playwright のヘッドレス Chromium（SwiftShader: `--use-angle=swiftshader --enable-unsafe-swiftshader`）で `games/e05/index.html?autotest&q=low` を 1024x768（横）と 768x1024（縦）で実行。結果は `logs/e05/test.txt`（tee で保存）。
- **横・縦とも PASS**: `__ready === true`、`__errors` 空、コンソールエラーなし。20枚装着（4段階・時間帯の変化）→ クライマックス（24秒）→ 余韻（10秒）→ フリープレイ（色の交換1回、歯車タップで天井の開閉）まで到達。1回あたり実時間 約6分。
- `q=mid`・`q=high`（transmission ガラス＋ブルーム）は開始〜1枚目の装着まで実行し、表示・エラーなし・コンソールエラーなしを確認（全工程は未実行）。
- スクリーンショット: `shot-1.jpg`（序盤・横、2枚目装着の瞬間）、`shot-2.jpg`（中盤・横、12枚目のあと・ガラスが枠へ吸着する途中）、`shot-3.jpg`（クライマックス約16秒＝最大の光の瞬間・横）、`p-shot-1〜3.jpg`（同じ場面・縦）。すべて 300KB 以下の JPEG。
  - 縦横とも、操作中の天井枠は画面中央から上へ約20%、候補ガラスは下へ約18%の位置で見切れない。クライマックスは天井4区画全体が縦横とも画面中央に収まり、空の青・真鍮の骨組み・ガラスの色と輪郭・床と植物の色模様が見え、白飛びしていない。
- 試作中に見つけて直したもの: (1) クライマックスで光芒が重なり中央が白くかすむ → 光芒の濃さを下げた。(2) high 画質で候補ガラスが太陽を正反射して白くにじむ → 候補ガラスの傾きを変え、鏡面反射を弱めた。(3) フリープレイで1回のドラッグが複数回の装着として数えられる → 装着開始時にポインタから切り離すよう修正。(4) 床の色が温室の奥の壁の外に落ちる → 色ガラス天井を手前に移し、太陽高度を調整（指示文の初期値 55/65/50/38° → 58/68/58/50°）。
- サムネイル: `site/thumbs/e05.jpg`（クライマックスの画面を 640x480 に縮小、約100KB、文字なし）。
- 指定の禁止語4語（ひらがな・カタカナ表記を含む）が `site/games/e05/` と `logs/e05/` に含まれないことを grep で確認。
- 外部通信: ゲーム本体は外部に一切アクセスしない。必須の共通スクリプト `../../gf-playlog.js` だけが外部へビーコンを送る（このサンドボックスでは届かないため、テストではそのリクエストだけ 204 で代用）。
- FPS: SwiftShader（CPU 描画）では 1.5〜3fps で、性能の指標にはならない。

## 未解決・注意点

- iPad Safari 実機での動作・FPS・タッチ感触は未確認（ヘッドレス Chromium＋SwiftShader のみ）。SwiftShader は CPU 描画のため 1〜3fps しか出ず、性能の指標にならない。**実機で50fps以上かどうかは未検証。** 各ピクセルで最大24枚のガラスとの交差判定をしているので、iPad では mid → low への自動切り替えが早めに起きる可能性がある。
- 全工程の自動テストは q=low で実施。mid / high は開始〜1枚目装着までの表示とエラーなしを確認（下記）。
- 低 FPS 環境では1フレームのゲーム時間を最大0.1秒（autotest は0.25秒）に制限しているため、極端に遅い端末では演出がゆっくりになる。
- デバッグ用に `?autotest` または `?dbg` のときだけ `window.__dbg` を公開している（画面表示はなし）。
