# E15 実装指示文：たきのうえの きょだいなビーだまこうぼう

## 0. 実装の基本方針

5歳の女の子が、文字を一切読むことなく、指1本で巨大なからくり装置を動かして楽しめる、写実的な3Dウェブゲームを実装する。

舞台は、壮大な滝が流れ落ちる山岳地帯に建てられた、真鍮・木材・ガラスでできた巨大なビーだま工房である。

小さなガラス玉を一つ送り込むだけで、レール、鐘、歯車、水車、観覧輪などが次々に動き出す。最終的には建物全体が一つの巨大な機械として連動する。

**「こんなに小さなビーだま一つで、こんなに大きなものが動いた！」という驚きこそが、このゲームの中心である。**

単なるビーだま転がしや装置の鑑賞ゲームにしてはならない。子どもの操作が原因となり、目の前の世界が変化する因果関係を、視覚と音で実感できるようにする。

## 1. ゲームの狙い

- **夢×写実：** 実在するかのような山岳建築、透明なガラス玉、使い込まれた真鍮製歯車、木製レール、壮大な滝を組み合わせ、現実には存在しない巨大な工房に物理的な実在感を与える。
- **高揚感：** 一個のビーだまが小さな鐘を鳴らすところから始まり、次第に巨大な歯車や観覧輪、工房全体へと連鎖運動が拡大していく喜びを作る。
- **爽快感：** ガラス玉の滑走、鐘の響き、歯車の噛み合う音、玉が受け皿に収まる音を気持ちよく連続させ、小さな指の動きで巨大な装置を動かす快感を生み出す。

## 2. 絵から借りる光と色

### 2.1 美術の方向性

参照として提示されたジェームズ・ガーニーの山岳都市画から、巨大な自然と精巧な人工建築が物理的な説得力を持って共存するという発想を借りる。

構図や絵柄、特定の建築物は模倣しない。借りるものは、以下の美術的な仕組みに限定する。

- 岩壁に沿って積み重なる建築物の立体感。
- 巨大な滝と人工物のスケール差。
- 水しぶきを通過する太陽光。
- 遠景ほど青みを帯びる空気遠近法。
- 石材、木材、金属、ガラスの素材ごとの光の反応。
- 現実的な光学現象に、幻想的な色彩と魔法のような驚きを加える演出。

写実性を土台とし、現実と想像が自然に溶け合った世界を作る。既存のキャラクター、映画の場面、城、ロゴ、ブランド意匠は使用しない。

### 2.2 時間帯と色彩設計

ゲームの進行に合わせ、太陽の位置と空の色を少しずつ変化させる。昼夜の変化そのものではなく、工房の活動が増すことによる祝祭感を主役とする。

| 項目 | 第1段階：朝 | 第2段階：昼 | 第3段階：黄金の午後 | 第4段階：夕暮れ |
|---|---|---|---|---|
| 空の上部 | `#65B5EF` | `#389DE6` | `#689FD9` | `#777DC7` |
| 地平線 | `#E3F3FF` | `#D7F4FF` | `#FFE1AA` | `#FFD0BA` |
| 太陽光 | `#FFF0CF` | `#FFF8EE` | `#FFD18A` | `#FFC5A1` |
| 太陽の色温度 | 約5200K | 約6000K | 約4000K | 約3500K |
| 霧の色 | `#C9E4F0` | `#D1ECF5` | `#E8D9C4` | `#D5C6E6` |
| 装置の発光色 | 金色 | 金色・水色 | 金色・虹色 | 虹色・金色 |

夕暮れでも暗闇にはしない。空、岩壁、装置の細部が十分に識別でき、ガラス玉の色が鮮やかに見える露出を維持する。

### 2.3 Three.js の照明・描画設定

以下を初期調整値とする。実際の見え方は使用する Three.js のバージョンとマテリアルに応じて調整する。

| 設定 | 推奨値 |
|---|---|
| DirectionalLight intensity | 2.0〜3.5 |
| HemisphereLight intensity | 1.2〜1.8 |
| HemisphereLight skyColor | `#D8EDFF` |
| HemisphereLight groundColor | `#A38A6D` |
| 工房内の補助光 | `#FFE3AE`、intensity 0.5〜1.2 |
| toneMapping | ACESFilmicToneMapping |
| toneMappingExposure | 0.95〜1.15 |
| outputColorSpace | SRGBColorSpace |
| 霧の開始距離 | 25〜40ワールド単位 |
| 霧の終了距離 | 130〜180ワールド単位 |
| 通常時のブルーム強度 | 0.20〜0.40 |
| ブルームのしきい値 | 0.85〜1.0 |
| ブルーム半径 | 0.25〜0.50 |
| クライマックス時のブルーム強度 | 0.8〜1.2以下 |

装置の全高を約12ワールド単位とした場合の目安である。

空間全体にブルームをかけて白く曇らせるのではなく、金属の縁、ガラスの反射、発光するビーだま、水しぶきなど、光が集中する箇所に限定して輝かせる。

光の筋は半透明メッシュや軽量なシェーダーで表現し、本格的なボリュームレンダリングは必須としない。

## 3. 舞台と登場するもの

### 3.1 全体の空間構成

工房は巨大な滝の手前に突き出した、岩壁のテラスに建てられている。

画面中央にからくり装置、手前にビーだまの供給台と投入口、奥に滝と山岳建築を配置する。装置全体が一つの建築物として美しくまとまって見えるように設計する。

奥行きは、以下の5層で構成する。

1. 前景：ビーだまの供給台、投入口、透明な受け皿。
2. 中景：曲線レール、鐘、歯車、昇降機。
3. 中景上部：巨大な観覧輪、ガラス製の光の塔。
4. 背景：石造りのテラス、アーチ橋、巨大な滝。
5. 遠景：山々、雲、青空、遠方の建築物。

背景の建築物にも細部を設けるが、操作対象と誤認するような発光や動きは与えない。

### 3.2 山岳建築と岩壁

すべてプロシージャル生成とする。

岩壁は頂点をノイズで変位させたメッシュを組み合わせ、地層の方向や侵食の跡を表現する。

石造りの建築には、アーチ、柱、石段、張り出したバルコニー、真鍮製の手すりなどを配置する。規則的な建築物と不規則な自然地形を対比させる。

石材には灰褐色、砂岩色、淡いベージュを混在させ、単色の箱に見えないようにする。

- 石材：roughness 0.75〜0.95、metalness 0。
- 微細な凹凸はノイズによる法線変化で表現する。
- 石材の継ぎ目や角の摩耗をプロシージャルテクスチャで表現する。
- 遠景の建築物は形状を簡略化し、霧によって奥行きを作る。

### 3.3 巨大な滝と水面

滝の高さは工房の約2〜3倍とし、自然の壮大さを強調する。

一枚の白い板で表現するのではなく、半透明の水流、流速の異なる複数の層、流れ落ちる白い筋、滝つぼの水煙を組み合わせる。

水のシェーダーには以下の要素を実装する。

- 時間経過に伴って下方向へ移動するノイズ。
- 流速の異なる複数の波紋パターン。
- 視線角度に応じたFresnel反射。
- 空の色を反映した青緑色の透過光。
- 太陽光による細長い反射。
- 滝つぼで発生する放射状の波紋。

水煙のパーティクルは低速で上昇させ、寿命と透明度を連続的に変化させる。

水しぶきには虹を部分的に出現させてもよい。ただし、常時大量の虹を表示せず、太陽光の方向と水煙の位置に説得力を持たせる。

### 3.4 ビーだま

ビーだまは最も重要な操作対象である。小さな単色球体ではなく、実際のガラス製ビーだまを手に取りたくなるような品質で作る。

透明な外殻と、内部の螺旋状の色ガラスを別メッシュで構成する。

色は赤、桃色、青、水色、緑、黄色、紫、虹色などを用意する。内部の模様は曲線メッシュや帯状のジオメトリで生成する。

外殻のマテリアルは以下を目安とする。

| 項目 | 推奨値 |
|---|---|
| Material | MeshPhysicalMaterial |
| transmission | 0.85〜1.0 |
| roughness | 0.04〜0.12 |
| metalness | 0 |
| ior | 1.45〜1.52 |
| thickness | 直径の0.5〜1.0倍 |
| clearcoat | 0.8〜1.0 |
| envMapIntensity | 1.0〜1.5 |

環境マップも、空と建築物、光源を簡略化したシーンから生成する。外部HDRIは使用しない。

ガラス表面には周囲の建築物や空が映り込み、回転に応じて反射位置が変化すること。内部の色ガラスも球体と一緒に回転させる。

low設定では高負荷な透過処理を省略し、Fresnel反射、内部の色模様、表面のハイライトによってガラスの質感を維持する。

### 3.5 レールとからくり装置

工房の内部には以下の装置を組み込む。最初から全装置が稼働していてはならない。

| 装置 | 役割・動き |
|---|---|
| 木製曲線レール | ビーだまが加速しながら転がる |
| 真鍮製の二本レール | 透明な玉が空中を滑走しているように見える |
| 小さな鐘 | 玉が接触すると揺れ、音が鳴る |
| 大小の歯車 | 玉の通過をきっかけに連動して回転する |
| シーソー | 玉の重みによって傾く |
| 螺旋レール | 玉が何周も回りながら下降する |
| 分岐ゲート | 次の玉を新しい経路へ送り出す |
| バケット式昇降機 | 玉をすくい上げて上層へ運ぶ |
| 巨大な観覧輪 | ガラス製のゴンドラが玉を持ち上げる |
| 透明な受け皿 | 成功した玉が蓄積される |
| ガラス製の光の塔 | 蓄積したエネルギーを最終演出で解放する |

レールはCatmullRomCurve3などの曲線を基礎に生成する。レールの形状とビーだまの移動経路は共通の曲線データから作り、玉がレールから浮いたり、木材に埋まったりしないようにする。

歯車はExtrudeGeometryなどで実際の歯を持つ立体形状として生成する。隣接する歯車の回転方向、歯数と回転速度の比率、噛み合う位相を整合させる。

真鍮には以下の材質を使用する。

- baseColor：`#C5A15A`〜`#E1BD78`
- metalness：0.85〜1.0
- roughness：0.22〜0.42
- 歯の先端や接触部分には摩耗した金属の反射を加える。

木材には`#9F6B3E`、`#BD8B55`、`#D4A975`などを使い、木目をCanvasTextureまたはシェーダーで生成する。木目はレールの長手方向に沿わせる。

人物、動物、独立した乗りものは今回の遊びに必要ないため登場させない。機械の運動そのものを主役にする。

## 4. 指1本のゲームループ

### 4.1 基本操作

画面中央手前の供給台に、一個のビーだまが置かれている。そのすぐ上には、ビーだまより少し大きな真鍮製の投入口がある。

子どもはビーだまを指で投入口へ滑らせる。

厳密なドラッグ操作を要求しない。ビーだまを一度タップするだけでも、投入口へ自然に転がっていくようにする。

ドラッグの場合も、投入口付近に到達した時点で吸着させる。指を離す位置が多少ずれていても成功できること。

### 4.2 一回の成功の流れ

| 経過時間の目安 | 起こること |
|---|---|
| 0秒 | ビーだまに触れる |
| 0〜0.5秒 | 玉が投入口へ吸い込まれる |
| 0.5〜2秒 | 玉が曲線レールを加速する |
| 2〜4秒 | 鐘、歯車などの仕掛けが順に作動する |
| 4〜7秒 | 玉が次のレールを滑走する |
| 7〜8秒 | 透明な受け皿に玉が到着する |
| 到着直後 | 受け皿が光り、次のビーだまが供給される |

初期段階では経路を短くし、1回約6秒を目安とする。後半では経路と連鎖反応を増やし、約8〜9秒に延ばす。

玉が仕掛けに触れる瞬間と、装置が動き出す瞬間、効果音が鳴る瞬間を一致させる。成功の手ごたえを曖昧にしてはならない。

### 4.3 ビーだまの運動

本格的な剛体物理エンジンは必須としない。決められた曲線に沿った運動を基礎とし、重力加速、回転、接触時の小さな跳ね返りを再現する。

移動距離と球体の回転角度は、玉の半径に基づいて対応させる。斜面で加速し、上り坂では減速させる。

ビーだまが脱線したり、装置から落下したり、途中で停止して進行不能になることはない。

### 4.4 操作に迷わせない設計

次に触れるべきビーだまは、他の物体よりも目立つ反射と周期的な輝きを持つ。

2秒間操作がなければ、ビーだまの表面を光の筋が横切る。4秒間操作がなければ、玉が供給台の上でわずかに揺れ、投入口の縁も順に光る。

誘導は文字、矢印、手のアイコンを一切使わず、物体そのものの変化だけで行う。

操作対象ではない場所を触れても、失敗音、警告、減点、やり直しは発生しない。進行中の連打や複数指による入力も無害に処理する。

## 5. 盛り上がりの設計

全4段階、各6個、合計24個のビーだまを基本構成とする。

子どもの操作時間を含め、通常のプレイ時間は約3〜5分を目標とする。時間制限は設けない。

重要なのは、同じ動作を24回繰り返すだけにしないことである。ビーだまを送り込むたびに新しい仕掛けが開放され、以前に起動した装置も低速で動き続けるようにする。

### 第1段階：小さなからくりが動き出す

1〜6個目のビーだま。所要時間の目安は約45〜55秒。

最初の玉は短い木製レールを転がり、小さな鐘を一回鳴らして受け皿に到着する。

玉を追加すると、シーソー、小歯車、二つ目の鐘、曲線レールが順に作動する。

6個目の玉で最初の大きな歯車が回転を始め、連動する小歯車も動き出す。真鍮製の装置の縁に金色の光が走る。

この段階で、子どもが「ビーだまを入れると機械が動く」という基本ルールを理解できるようにする。

### 第2段階：レールが広がる

7〜12個目のビーだま。所要時間の目安は約45〜60秒。

分岐ゲートが切り替わり、ビーだまがこれまでとは異なる経路に進む。

螺旋レール、空中に張り出した二本レール、複数の鐘を追加する。玉が螺旋レールを回るたびに、次の歯車へ回転が伝わる。

12個目の玉でバケット式昇降機が起動し、受け皿に蓄積された玉の一部が上層へ運ばれる。

工房の中に、下へ転がる玉と上へ運ばれる玉の循環が生まれる。

### 第3段階：巨大な観覧輪が回り出す

13〜18個目のビーだま。所要時間の目安は約50〜65秒。

上層に運ばれたビーだまが、巨大な観覧輪の透明なゴンドラに収まる。

ゴンドラはゆっくり上昇し、頂点付近で別のレールに玉を送り出す。観覧輪は玉が一つ増えるごとに稼働範囲を広げる。

歯車、昇降機、観覧輪、レールが一つの循環機構としてつながっていく。

18個目では装置上部の鐘が順に鳴り、機械の外周を金色の光が巡る。背景の滝の水煙に虹が現れる。

### 第4段階：工房全体が一つの機械になる

19〜24個目のビーだま。所要時間の目安は約50〜65秒。

複数の経路を異なる色の玉が同時に走る。以前に蓄積された玉も循環に参加させる。

大歯車が小歯車を回し、昇降機が玉を持ち上げ、観覧輪が玉を別のレールへ運ぶ。異なる速度の運動が規則的に噛み合い、工房全体が生きているかのように動く。

玉の速度は第1段階の約1.3〜1.6倍を上限の目安とする。速すぎて玉を見失わないようにする。

23個目が到着すると、次の供給台に特別な虹色のビーだまが現れる。

### クライマックス：虹色のビーだま

24個目の虹色のビーだまを送り込むと、約15〜20秒間の最終演出が始まる。

1. 虹色の玉が工房内の主要な仕掛けを順に通過する。
2. 通過するたびに鐘が鳴り、真鍮製レールに虹色の光が走る。
3. 蓄積されたビーだまが複数のレールに送り出される。
4. 巨大な観覧輪と歯車が調和した速度で回転する。
5. 装置中央のガラス製の光の塔に色とりどりの光が集まる。
6. 光の塔から光の帯が放射状に広がり、滝の水煙に大きな虹が形成される。
7. 最後の鐘が響き、工房全体が金色と虹色の反射に包まれる。

光の帯は既存のレールや建築物の曲線に沿って広がるようにする。単に画面を発光パーティクルで埋め尽くす演出にしない。

ブルーム強度は最大1.2以下、しきい値は0.8以上とする。最高潮でも歯車、観覧輪、ガラス玉、空の色が識別できること。

画面全体の白飛び、急激な露出上昇、激しい点滅、爆発音は禁止する。

### 余韻とフリープレイ

クライマックス終了後は約8〜10秒かけて機械の回転を穏やかに減速させる。

鐘の余韻と滝の音を残し、受け皿に集まったビーだまが美しく輝く状態を見せる。

その後、中央の供給台に新しいビーだまを出現させる。子どもは引き続き玉を送り込み、完成した工房の全機構を何度でも動かせる。

タイトル画面への強制遷移や終了ボタンは設けない。

## 6. カメラと画面構成

### 6.1 基本視点

からくり装置の全景を中央に収める、斜め正面からの固定視点を基本とする。

カメラは工房の前方から、装置の正面と側面、レールの奥行きが同時に見える位置に設置する。

- 水平方向の角度：正面から約15〜25度。
- 俯角：約10〜18度。
- PerspectiveCameraの垂直FOV：38〜45度程度。
- カメラのロール角：常に0度。

望遠寄りの自然なパースを採用し、広角レンズによる歪みを避ける。

### 6.2 中央に置くもの

供給台と投入口は画面中央付近の手前に配置する。透明な受け皿と光の塔も装置の中央軸付近に設置し、基本視点を変えずに重要な出来事が見える設計にする。

次の操作対象は、原則として画面中央から横方向±10%、縦方向±15%以内に収める。

ビーだまの移動中にカメラで玉を追いかけてはならない。子ども自身が、装置の中を転がる玉を目で追う楽しさを残す。

### 6.3 縦横画面への対応

装置の主要部分を含むバウンディングボックスを定義し、縦横の視野角のうち狭い方を基準に、カメラ距離を自動調整する。

画面の四辺には約8〜12%の余白を確保する。特に巨大な観覧輪と光の塔が見切れないこと。

縦向きでは背景建築を省略するなどして、主要装置の表示サイズと操作性を優先する。

段階移行時に装置全体を見せるための緩やかなズームアウトは許可する。ただし、1.5〜3秒程度かけて滑らかに移動し、操作対象の見え方を維持する。

クライマックス時にもカメラは回転させず、光の塔を画面中央に保持する。

## 7. 操作と入力処理

iPad SafariおよびPCブラウザの双方に対応する。

Pointer Eventsで入力処理を統一し、タッチ操作とマウス操作で同じゲーム体験を提供する。

- タップとドラッグの双方を有効にする。
- 操作中は最初のpointerIdだけを追跡する。
- 二本目以降の指は無視する。
- pointercancel時は安全に操作状態を解除する。
- 当たり判定は見た目の直径の1.5〜2倍程度とする。
- タップ可能領域は最低56〜64 CSS px程度を確保する。
- 同じ玉を連続入力しても二重に発射しない。

ドラッグ中は必要に応じてPointer Captureを使用する。

CSSの`touch-action: none`、`overscroll-behavior: none`、`user-select: none`などを設定し、ブラウザのスクロール、ピンチズーム、ダブルタップズーム、長押しメニュー、テキスト選択を可能な範囲で抑止する。

iOS固有のジェスチャーについては、必要に応じてキャンセル可能なイベントを適切に処理する。

## 8. 音響設計

すべてWebAudioによる手続き的な音響合成とする。外部音声ファイルは使用しない。

最初のユーザー操作でAudioContextを生成またはresumeする。

音は画面内の物理現象と同期させる。特に、ガラスと金属の音の違いを明確にする。

| 音 | 合成方法の目安 |
|---|---|
| ビーだまに触れる音 | 700〜1400Hzの短い正弦波 |
| 玉が転がる音 | 帯域制限したノイズと短い接触音の連続 |
| 木製レールの接触音 | 200〜500Hz付近の短い打音 |
| 真鍮レールの接触音 | 1000〜2500Hz付近の金属的な倍音 |
| 鐘 | 複数の正弦波と0.5〜1.2秒程度の減衰 |
| 歯車 | 回転速度に同期する規則的なクリック音 |
| 昇降機 | 低音量の機械的な周期音 |
| 受け皿への到着 | 透明感のある複数の短い音 |
| 滝 | フィルターを通した連続ノイズ |
| 光の解放 | 上昇するアルペジオと持続する和音 |

成功音は段階が上がるにつれ、単音、二音、三和音、豊かなアルペジオへと発展させる。

音階は長音階または長調系のペンタトニックスケールを基本とする。既存楽曲の旋律は使用しない。

BGMは控えめにし、ビーだまの転がる音や鐘の音を覆い隠さない。DynamicsCompressorNodeとマスターゲインを使用し、複数の音が同時に鳴っても急激に音量が上がらないようにする。

## 9. 画面の文字と開始演出

ゲーム画面に文字、数字、スコア、ボタンのラベル、説明文を一切表示しない。

開始画面から完成した3Dの舞台を表示する。中央手前に置かれたビーだまの反射が周期的に変化し、子どもの操作を誘う。

最初のタップでゲームを開始すると同時に、最初のビーだまを送り込む。

進捗は数値ではなく、透明な受け皿に蓄積されるビーだまの数、動き始めた装置の数、光の塔の発光範囲によって伝える。

## 10. 画質の自動調整とパフォーマンス

2020年世代のiPad ProのSafariでも、50fps以上で安定して遊べることを目標とする。

| 設定 | high | mid | low |
|---|---:|---:|---:|
| DPR上限 | 1.75 | 1.25 | 1.0 |
| シャドウマップ | 2048² | 1024² | 簡易接地影 |
| ブルーム | 有効 | 低解像度 | 原則無効 |
| 水しぶき粒子数 | 400〜600 | 180〜300 | 60〜120 |
| ガラス透過処理 | 有効 | 操作対象を優先 | 簡易反射 |
| 水面反射 | 高品質 | 簡略化 | Fresnel近似 |
| ドローコール目標 | 150以下 | 100以下 | 70以下 |

起動時はmidを基本とし、実際のシーンを描画した際のフレーム時間を測定する。

実行中もFPSの移動平均を取得し、45fps未満が数秒間続いた場合は一段階下げる。57fps以上で十分な描画余力が継続した場合は、上位設定を検討する。

頻繁な切り替えを防ぐため、変更後は最低10秒程度のクールダウンを設ける。

`?q=low`、`?q=mid`、`?q=high`で画質を固定できるようにする。強制指定時は自動切り替えを行わない。

歯車、レールの支柱、石材、非操作中のビーだまなどにはInstancedMeshやジオメトリの共有を活用する。

毎フレームのオブジェクト生成、不要なテクスチャ更新、過剰な動的シャドウ、全装置に対するリアルタイム環境反射は避ける。

**画質を下げても、操作対象の視認性、装置の動き、ビーだまの軌道、成功音、クライマックスの内容は削らないこと。**

## 11. 技術構成

### 11.1 ファイル構成

実装先は以下とする。

`site/games/e15/index.html`

HTML、CSS、JavaScriptはこの1ファイルにまとめる。

Three.jsはリポジトリに同梱されている以下のファイルを使用する。

- `site/vendor/three/build/three.module.min.js`
- `site/vendor/three/examples/jsm/`

importmapで`three`および`three/addons/`を解決する。対象HTMLからの相対パスを正しく設定する。

CDN、外部画像、外部3Dモデル、外部音声ファイル、外部フォントは使用しない。

`<head>`内には以下を必ず追加する。

`<meta name="robots" content="noindex">`

`</body>`の直前には以下を必ず追加する。

`<script src="../../gf-playlog.js" defer></script>`

既存の共通ファイルや他のゲームには不要な変更を加えない。

### 11.2 内部構造

単一HTML内でも、以下の責務を分離する。

- シーン、照明、環境マップの初期化。
- 地形と山岳建築の生成。
- 水と滝の描画。
- からくり装置の生成と連動制御。
- ビーだまの経路と運動制御。
- タッチ・マウス入力処理。
- 段階進行とクライマックス管理。
- WebAudioの管理。
- カメラと画面サイズの管理。
- 画質とFPSの管理。
- 自動テストとエラー記録。

進行状態は、入力待ち、玉の投入、レール滑走、仕掛け作動、受け皿到着、段階移行、クライマックス、余韻、フリープレイに分ける。

各経路の仕掛けの発動地点をあらかじめ定義し、ビーだまがその地点を通過したことをトリガーとして、機械の運動、光、音を同期させる。

### 11.3 準備完了とエラー記録

`window.__ready`は初期状態でfalseとし、シーン構築と初回描画が完了し、入力可能になった時点でtrueにする。

`window.__errors`は空の配列として初期化する。

初期化時の例外、実行時エラー、未処理のPromise rejectionなどを捕捉し、診断可能な形式で記録する。

エラー監視はThree.jsの読み込みより前に設定する。

### 11.4 自動プレイ

`?autotest`を指定した場合、自動的にビーだまを一個ずつ投入し、全4段階、24個目の投入、クライマックス、余韻、フリープレイまで進行する。

通常プレイと同じ状態遷移、ビーだまの経路、仕掛けの作動処理を使用すること。成功回数だけを直接書き換えるテストは禁止する。

必要に応じてテスト時のみ演出時間を短縮してよいが、各仕掛けの発動と到着処理は省略しない。

ブラウザの自動再生制限によって音声が起動できない場合も、自動テストは正常に進行できるようにする。

### 11.5 禁止事項

不気味な生物、人物、怪物、恐怖演出、不穏な造形、既存キャラクター、既存作品の意匠、ブランドロゴは使用しない。

別紙の禁止語は、実装コード、コメント、変数名、画面表示、生成される関連文書のいずれにも使用しないこと。表記を変更した場合も同様とする。

## 13. 最終的な品質基準

本指示文の装置構成、全4段階・24個という進行回数、照明設定、演出時間などの数値は、実装のために具体化した初期設計値である。実際の描画品質、遊びやすさ、端末性能を確認しながら調整してよい。

ただし、最も優先すべきものは機械の数やグラフィックの豪華さではない。

**指先で一個のビーだまを送り込んだことが、巨大な機械を動かす原因になっていると、5歳の子どもが直感的に理解できること。**

ビーだまが転がり、鐘が鳴り、歯車が回り、次の仕掛けへ運動が伝わっていく。その連鎖自体を気持ちよく作り込むこと。

最後には、巨大な滝を背景に、何十個もの美しいガラス玉と壮大なからくり装置が調和して動く、現実には存在しない夢の工房を完成させる。
