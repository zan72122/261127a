# E05 実装指示文：ひかりの ガラスおんしつ

## 1. ゲームの狙い

5歳の女の子が、巨大なガラス温室の天井に好きな色のガラスを取り付け、自分の手で建築空間全体を光の万華鏡へと変えていく、写実的な3Dウェブゲームを制作してください。

- **夢×写実：** 植物の繊細な葉脈、磨かれた真鍮、白い大理石、透明なガラスという現実的な素材の中に、幻想的な透過光が広がる世界を作る。
- **高揚感：** 最初は一枚の色ガラスによる小さな変化から始まり、最後には巨大な温室全体が動く光の万華鏡へと変貌する。
- **爽快感：** 指先で小さなガラスを滑らせるだけで、広大な床や植物、建築物の色彩が瞬時に変化する、操作と結果のスケールの差を楽しませる。

このゲームの本質は、ガラスを集めることでも、パズルを解くことでもない。**自分で空間の色を着せ替えること**である。

子どもの操作によって、現実では簡単に体験できない規模の美しい変化が起こることを最優先とする。

単なるステンドグラス作りや、完成した風景を鑑賞するだけのゲームにはしないこと。

## 2. 絵から借りる光と色

### 2-1. 美術的な方向性

提示された参考絵画からは、以下の要素だけを抽出する。

- 温室の規則的な骨組みと、植物の有機的な形状との対比。
- ガラス越しに降り注ぐ自然光。
- 植物の豊かな緑と、花や果実の鮮やかな色彩。
- 建築物の反復構造によって生まれる視覚的なリズム。
- 日常的な建築空間が、光によって特別な場所に変化する感覚。

参考絵画の構図、筆致、画風は再現しない。自然写真や高品質な建築CGに近い写実3Dを基礎とし、現実には存在しにくい規模の色彩と透過光によって幻想性を加える。

映画的な魔法の光、壮大な空間、驚きに満ちた演出を目指す。ただし、既存のキャラクター、城、作品名、ロゴ、ブランド固有の意匠は使用しない。

### 2-2. 時間帯と照明

ゲームの進行に合わせて、午前から黄金色の午後へと時間帯を変化させる。夜には移行させず、常に温室の全体像を見通せる状態とする。

以下の数値を初期調整値として使用する。実際の描画結果を見ながら調整してよい。

| 項目 | 第1段階 | 第2段階 | 第3段階 | 第4段階 |
|---|---|---|---|---|
| 時間帯 | 午前10時 | 正午 | 午後2時 | 午後4時 |
| 空の上部 | `#72B9EE` | `#529FEC` | `#70B6EA` | `#849FDB` |
| 地平線 | `#DDF4FF` | `#E8F8FF` | `#FFF0D6` | `#FFDAAB` |
| 太陽光 | `#FFF3DC` | `#FFF9EF` | `#FFE5BF` | `#FFD29B` |
| 色温度目安 | 5600K | 6500K | 4800K | 3800K |
| 太陽高度 | 55° | 65° | 50° | 38° |
| DirectionalLight強度 | 2.5 | 3.0 | 2.8 | 2.6 |
| HemisphereLight強度 | 1.3 | 1.4 | 1.3 | 1.4 |
| Bloom強度 | 0.20 | 0.35 | 0.50 | 0.65 |

時間帯の移行は5〜8秒程度かけて連続的に行う。太陽の位置や空の色を突然切り替えないこと。

### 2-3. 基本カラーパレット

温室そのものは上品な自然色で統一し、色ガラスによる変化を引き立たせる。

| 素材・色 | HEX |
|---|---|
| 白い大理石 | `#F3F0E8` |
| 真鍮の骨組み | `#C5A36A` |
| 若葉 | `#78AD45` |
| 深い緑の葉 | `#326A37` |
| シクラメンの花 | `#EF6DAB` |
| 赤い果実 | `#DD493D` |
| ローズ色ガラス | `#F875B8` |
| アクア色ガラス | `#49D7E7` |
| サファイア色ガラス | `#648EFF` |
| エメラルド色ガラス | `#50DFA1` |
| アンバー色ガラス | `#FFD15C` |
| アメジスト色ガラス | `#B28AF5` |

色ガラスは高彩度にするが、温室全体を単一色で塗りつぶさない。複数の色の境界、自然光が残る部分、植物本来の色が共存するようにする。

### 2-4. 霧・露出・光芒

Three.jsのワールド単位を、おおむね1単位＝1mとして設計する。

- Fog：`#DCEEF4`、near 35、far 110。
- トーンマッピング：ACESFilmicToneMapping相当。
- 露出：0.95〜1.10を基本範囲とする。
- Bloom threshold：0.85〜1.0。
- Bloom radius：0.35〜0.50。
- クライマックス時のBloom strength：最大1.15。
- 出力色空間：sRGB。
- 光芒は半透明の細長いメッシュやシェーダーで近似し、実際のボリュームレンダリングは行わない。

ポストプロセスを使用する場合は、トーンマッピングや色空間変換を重複適用しないこと。

光の筋は空気中の微細な水分や埃によって見える程度に抑え、レーザー光線のような不自然な外観にしない。

光の最大の瞬間でも、ガラスの輪郭、真鍮の骨組み、植物の葉、空の青さが識別できること。

## 3. 舞台と登場するもの

### 3-1. 巨大なガラス温室

ゲームの舞台は、緑豊かな庭園に建つ巨大なガラス温室とする。

建築物には、実際に存在しても不思議ではない構造的な説得力を持たせる。

寸法の目安：

- 幅：18m
- 奥行き：30m
- 軒高：9m
- 天井最高部：14m
- 中央通路の幅：5m

温室の骨組みは、真鍮製の柱、梁、アーチ、細いガラス支持材によって構成する。接合部にはボルトや継ぎ目を設ける。

天井中央には、色ガラスを取り付けられる空の枠を20枚分用意する。5枚ずつ4区画に分け、ゲームの進行に合わせて完成させる。

20枚・4段階という構成は実装上の初期仕様とし、プレイ時間や操作感を確認して必要に応じて調整する。

残りの天井や側面には透明ガラスを設置し、外の空や庭園が見えるようにする。

### 3-2. 白い大理石の床

床は色ガラスによる透過光を最も美しく見せるスクリーンとして機能させる。

- MeshStandardMaterialを基本とする。
- Roughness：0.22〜0.35。
- Metalness：0.0。
- 大理石の細い鉱脈をノイズやCanvasTextureで手続き的に生成する。
- タイルの継ぎ目を細く表現する。
- 法線の微細な変化によって石材の質感を作る。
- 植物や真鍮の色がわずかに映り込むようにする。

鏡のような床にはしない。色ガラスの透過光と床面反射が混同されないようにする。

### 3-3. 植物

温室の左右には、以下の植物を立体的に配置する。

- ピンクや白のシクラメン。
- 赤い実をつけたトマト。
- 大きな葉を持つ観葉植物。
- シダ植物。
- 上方から垂れ下がるつる植物。
- 小さな白い花をつけた植物。

葉は単純な平面板ではなく、中央の葉脈に沿って湾曲したメッシュを生成する。葉の縁、厚み、葉脈、先端の曲がり、色の個体差を表現する。

葉のRoughnessは0.35〜0.65を目安とし、透過光を受けたときに葉の薄さを感じられるシェーダー表現を加える。

葉や花の大量配置にはInstancedMeshを使用する。植物の揺れは頂点シェーダーなどで低負荷に実現する。

植物の高さや密度は、中央通路と操作対象の視認性を損なわないように制限する。

### 3-4. 空・雲・水

空はグラデーションシェーダーによって生成する。雲はノイズを用いた半透明メッシュなどで表現し、ゆっくり移動させる。

温室の外には芝生、低木、遠方の樹木を配置する。遠景は簡略化した形状と大気遠近法で表現する。

温室の左右には、建築の一部として細い装飾用水路を設けてもよい。水面は以下の仕様とする。

- 2〜3種類の正弦波による微細な法線変化。
- Fresnel効果による視線角度依存の反射。
- 青緑色の環境反射。
- 色ガラスによる透過光の映り込み。
- 波の振幅は0.005〜0.02m程度。

水路は主役ではないため、負荷が高い場合は省略してよい。

このゲームでは乗りもの、動物、人物を登場させない。建築、植物、ガラス、光そのものを主役とする。

### 3-5. 色ガラス

色ガラスは、このゲームで最も重要な操作対象である。

平面的な色付きパネルではなく、厚さのある高級な建築用ガラスとして制作する。

- 大きさ：1.4m × 1.8m程度。
- 厚さ：0.015〜0.025m。
- IOR：1.45〜1.52。
- Roughness：0.04〜0.12。
- Metalness：0.0。
- High設定でのTransmission：0.8〜0.95を目安とする。
- 縁に微細な面取りを設ける。
- ガラス内部にごく弱い屈折や厚みの変化を表現する。
- 真鍮製の細い縁取りを設ける。

ガラス表面には温室の骨組みや空の反射が見えるようにする。角度が変わると縁が輝き、透明な物体を動かしている感覚が伝わること。

環境反射用のテクスチャは、手続き的に生成した環境シーンからPMREMGeneratorなどを用いて作成する。外部HDRIは使用しない。

多数のガラスを描画する際は、Transmissionによる負荷や透明物体の描画順序に注意する。Mid・Lowでは環境反射とFresnelを利用した軽量な透明表現に置き換える。

## 4. 最重要技術：色ガラスを透過する光

Three.jsの標準的な透明マテリアルだけでは、床や植物に色付きの透過光を正しく投影できない。そのため、この表現を専用に実装すること。

### 4-1. 床への色彩投影

各ガラスの四隅から太陽光の進行方向へ仮想的な光線を伸ばし、床面との交点を求める。

得られた四角形の領域に、ガラスの色に対応した透過光を描画する。

実装方式は、ワールド座標を用いた投影シェーダー、または床面に沿った投影メッシュとする。

- 光の形状は、太陽の位置とガラスの角度に連動する。
- 光の境界には0.05〜0.20m程度の減衰領域を設ける。
- ガラス支持材の影も投影模様に含める。
- 大理石の鉱脈や継ぎ目は透過光の下でも見えるようにする。
- 複数の色彩が重なる場合は、光の混合を近似する。
- 光量の累積には上限を設け、過露出を防ぐ。

単純に床のマテリアル色を切り替える方式は禁止する。ガラスの位置と床に現れる光の位置には、明確な空間的対応が必要である。

### 4-2. 植物や建築物への投影

床だけでなく、植物の葉、植木鉢、柱、壁面にも色彩が届くようにする。

可能であれば、ワールド座標から太陽方向へ逆投影し、どのガラスの領域を通過するかによって照明色を変化させる。

完全な光線追跡は不要である。植物群単位の色付き照明や、共通の投影シェーダーによる近似でよい。

Low設定でも、床への透過光と、周辺植物の色彩変化は必ず維持すること。

### 4-3. ガラス移動中のリアルタイム変化

ガラスを指で移動させている最中にも、その位置に対応した色彩が床の上を移動するようにする。

これにより、子どもはガラスを取り付ける前から、光を動かすこと自体を楽しめる。

ガラスの位置、光の投影位置、ガラスの縁の反射を同期させること。

装着直前まで何も起こらず、装着後に初めて色彩が現れる仕様にはしない。

## 5. 指1本のゲームループ

### 5-1. 開始画面

起動直後から、美しい温室の内部を表示する。

中央付近に、まだ取り付けられていないローズ色のガラスを一枚配置する。その奥には、対応する空の天井枠が見えている。

ガラスの縁が周期的にきらめき、太陽光の反射がガラス表面を横切る。

このガラスに触れるとゲームが始まる。

タイトル画面、開始ボタン、説明画面は作らない。

### 5-2. 1回の基本ループ

1. 天井の空の枠が、真鍮の縁に沿って金色に輝く。
2. 画面中央下寄りに、選択可能な色ガラスが3枚並ぶ。
3. 子どもが好きなガラスに触れる。
4. ガラスが指に追従して持ち上がり、天井枠へ滑らせられる。
5. 移動に合わせて、床や植物の上を色付きの光が移動する。
6. ガラスが枠の近くに到達すると、磁石に吸い付くように正しい位置へ収まる。
7. 心地よい金属音とガラス音が鳴り、温室に大きな色彩が広がる。
8. 次の空の枠が輝き、次のガラスが用意される。

色の正解は設けない。どの色を選んでも成功する。同じ色を繰り返し選んでもよい。

### 5-3. 操作の補助

ドラッグ操作を基本とするが、ガラスをタップしてから天井枠をタップする操作にも対応する。

色ガラスを触ったあと、操作が止まった場合には、ガラスが枠の方向へわずかに傾き、取り付け位置との関係を示す。

- 吸着判定は枠の見た目より十分に広くする。
- 正確な角度合わせは要求しない。
- ガラスの回転は自動で補正する。
- 途中で指を離した場合は、その場で待機するか、元の位置へ穏やかに戻す。
- ガラスを落下させたり、割ったりしない。
- 画面の別の場所を触っても、失敗音や警告を出さない。

### 5-4. 成功時の手ごたえ

ガラスが枠に収まる瞬間を、毎回気持ちのよい体験にする。

| 経過時間 | 演出 |
|---|---|
| 0〜80ms | 真鍮の枠への吸着と金属音 |
| 80〜180ms | ガラスの縁を走る光 |
| 100〜500ms | 床へ広がる大きな色彩 |
| 300〜900ms | 周囲の葉や柱への色彩の伝播 |
| 800〜1500ms | 微細な光の粒子と和音の余韻 |

ガラス自体を過度に発光させるのではなく、太陽光がガラスを通り抜けた結果として空間が変化するように見せる。

### 5-5. 放置時の誘導

操作がない時間を計測し、次のように誘導する。

- 3秒後：操作対象の縁がきらめく。
- 6秒後：ガラスが数cm相当持ち上がり、元の位置へ戻る。
- 10秒後：天井枠とガラスが同じリズムで輝く。

文字、矢印、手のアイコン、チュートリアル用キャラクターは使用しない。

誘導によって勝手にガラスが装着されることは避け、子ども自身が空間を変えたという感覚を守る。

## 6. 盛り上がりの設計

全20枚、4段階を基本とし、標準的なプレイ時間を約3〜5分とする。

時間制限は設けない。操作が速い子どもは短時間で完成でき、ゆっくり遊ぶ子どもは好きなだけ時間をかけられるようにする。

### 第1段階：最初の光（1〜5枚目）

午前の温室。

白い大理石の床に、最初の色彩が現れる。自然光が主体であり、装着したガラスによる変化が特にはっきりわかる段階とする。

主な色はローズ、アクア、アンバー。

ガラスが5枚そろうと、一列の色付きの光が中央通路に並ぶ。

### 第2段階：光の庭園（6〜10枚目）

正午の温室。

光が床だけでなく、花や大きな葉、柱にも届き始める。

色彩の種類にエメラルド、サファイアを加える。装着時の音には二音の和音を取り入れる。

10枚目の装着後、太陽光の移動に合わせて、完成した色彩の列が床の上をゆっくり移動する。

### 第3段階：光のオーケストラ（11〜15枚目）

午後の温室。

色彩の領域が増え、異なる色の光が重なり合う。

アメジスト色を追加し、ガラスの選択肢に変化を持たせる。

装着するたびに、床、葉、真鍮の柱、水面など複数の素材が連動して色を変える。

完成した天井区画が数度だけ動き、光の模様が広い範囲を移動する。最後に天井が大きく動くことを予感させる演出とする。

### 第4段階：巨大な光の万華鏡（16〜20枚目）

黄金色の午後。

温室の大部分がすでに色彩に包まれている。

ガラスを取り付けるごとに和音が豊かになり、光の伝播範囲が広がる。最後の一枚は温室中央の重要な位置に配置し、子どもが最後の操作をしやすいようにする。

20枚目のガラスが収まった瞬間から、クライマックスを開始する。

### 6-1. クライマックス

最大の見せ場は、完成したガラス天井そのものが巨大な光学装置として動き出すことである。

天井の4区画を独立した可動パネル群として設計し、真鍮のレール、ヒンジ、支持機構をあらかじめ建築構造に組み込む。

演出は約20〜25秒。

- 0〜3秒：完成した20枚のガラスの縁を順番に光が走る。
- 3〜7秒：真鍮の機構が動き、天井がゆっくり開き始める。
- 7〜15秒：天井の開閉と傾きに連動して、床や植物の上を巨大な色彩の模様が流れる。
- 15〜20秒：温室全体が光の万華鏡となり、最も豊かな和音が鳴る。
- 20〜25秒：天井の動きが穏やかになり、光の粒子が消えていく。

可動パネルの回転角度は最大15〜20°程度、スライド距離は最大0.8〜1.2m程度を目安とする。パネル同士や支持材が不自然に交差しないように設計する。

色彩の移動は実際のパネルの動きに連動させる。適当な虹色の画面エフェクトで代用しない。

Bloom強度は最大1.2未満とし、露出を急激に上げない。画面全体の白飛び、激しい点滅、カメラの振動は禁止する。

### 6-2. 余韻とフリープレイ

クライマックス後は、約8〜12秒の静かな余韻を設ける。

その後は完成した温室でフリープレイへ移行する。

中央に用意されたガラスを使い、既存の色ガラスを好きな色に交換できるようにする。また、中央に見える真鍮製の開閉機構に触れることで、完成した天井の開閉を再び楽しめるようにする。

完成した美しい温室を突然消去して、最初からやり直させない。

## 7. カメラ

### 7-1. 基本構図

温室中央の大理石の床とガラス天井を同時に見渡せる、建築写真のような広角視点を採用する。

初期の目安：

- PerspectiveCamera。
- 垂直FOV：50〜65°。
- カメラ高さ：床から3〜4.5m程度。
- カメラの傾き：天井と床の双方が視認できる角度。
- カメラのロール：常に0°。

一人称視点で歩き回る方式にはしない。カメラ操作を子どもに要求しない。

### 7-2. 操作対象の中央維持

現在操作すべき色ガラスと空の枠を、一つの注視対象として扱う。

空の枠は原則として画面中央付近に配置し、色ガラスの選択肢もその近くの中央下寄りに表示する。

操作対象の中心は画面中央から上下左右15〜20%以内を目安とする。操作対象の全体が画面内に収まり、周囲に十分な余白があること。

装着後は次の枠を注視対象に変更し、1〜2秒程度かけて滑らかにカメラを移動させる。

ドラッグ中にカメラが勝手に移動しないようにする。

### 7-3. 縦向き・横向きへの対応

画面のアスペクト比から水平・垂直の視野角を求め、操作対象とその周囲を包含できるカメラ距離を計算する。

- iPad横向き：温室の広がりと植物の豊かさを重視。
- iPad縦向き：床から天井への高さと光の筋を重視。
- iPhone相当の縦長画面：操作対象の見切れ防止を優先。
- PC横長画面：過度に引きすぎず、操作対象の大きさを維持。

画面回転時も進行状況を保持する。

### 7-4. クライマックスのカメラ

天井中央を注視点として、完成した4区画と床への色彩投影の双方を画面内に収める。

必要に応じて、3〜5秒かけてカメラを引く。

急なズーム、回転、上下動、視点の切り替えは行わない。主役である可動天井が画面外へ出ないよう、各アニメーション時点での外接範囲も考慮する。

## 8. 操作と入力処理

iPad Safariのタッチ操作とPCのマウス操作に対応する。

Pointer Eventsを使用し、入力処理を統一する。

- 最初の有効なpointerIdのみを追跡する。
- 2本目以降の指は無視する。
- setPointerCaptureを利用し、指が対象から外れても操作を継続する。
- pointercancel時は安全に待機状態へ戻す。
- Raycasterによる選択判定に、見た目より大きな補助判定領域を設ける。
- タップ対象は画面上で最低64 CSS px程度を目安とする。
- ドラッグとタップの区別には8〜12 CSS px程度の移動許容幅を設ける。
- 同じガラスの二重装着や、成功回数の重複加算を防ぐ。

ドラッグ時は、画面座標から操作用の仮想平面上の座標を求め、ガラスを追従させる。奥行き方向の移動や天井面への姿勢補正は自動処理する。

ゲーム領域では`touch-action: none`、`overscroll-behavior: none`、`user-select: none`などを設定する。

ピンチズーム、ダブルタップズーム、ページスクロール、長押しメニュー、テキスト選択をゲーム領域内で可能な限り抑止する。

## 9. 音響設計

音声ファイルは一切使用せず、WebAudio APIによって手続き的に合成する。

最初のユーザー操作でAudioContextを生成またはresumeする。

### 9-1. 効果音

| 操作 | 音の方向性 |
|---|---|
| ガラスへの接触 | 短い高音のガラス音 |
| ガラスの移動 | 微細な空気音 |
| 枠への装着 | 真鍮の接触音と澄んだ余韻 |
| 色彩の広がり | 上昇する倍音 |
| 天井の開閉 | 低く穏やかな機構音 |
| クライマックス | 広がりのある多音の和音 |

ガラス音はサイン波と複数の倍音を組み合わせ、0.2〜0.8秒程度で減衰させる。

### 9-2. 段階ごとの音楽的発展

Cメジャーペンタトニックなど、不協和音を生じにくい音階を基本とする。

- 第1段階：単音。
- 第2段階：二音の和音。
- 第3段階：三和音と倍音。
- 第4段階：広い音域の和音と長い余韻。

クライマックスの和音は、急激な音量増加ではなく、音の層が増えることによって壮大さを表現する。

### 9-3. 環境音

温室を通る風、葉のかすかな揺れ、水路を流れる水などを、フィルター処理したノイズや低振幅のオシレーターで生成する。

BGMは旋律を強調せず、環境音を主体とする。

Master Gainは0.15〜0.25程度から調整し、DynamicsCompressorNodeなどで突然の大音量やクリッピングを防ぐ。

タブが非表示になった場合は、音を停止または減衰させる。

## 10. ゲーム画面の文字とUI

ゲーム画面には文字、数字、スコア、ゲージ、ボタンラベルを一切表示しない。

進行状況は完成していくガラス天井そのもので伝える。

操作対象は実際の3D物体とし、一般的なゲーム用HUDを重ねない。

禁止するもの：

- スタート画面の説明文。
- 成功・失敗の文字表示。
- 残り枚数の表示。
- 矢印や手のアイコン。
- 広告やブランドロゴ。
- 画面を占有する設定メニュー。
- 不穏な生物、怪物、恐怖演出。
- 過度にデフォルメされた玩具風の造形。

色の選択だけでなく、ガラスの輪郭、空の枠、位置関係、動きによって操作の意味が理解できるようにする。

## 11. 画質の自動調整とパフォーマンス

2020年世代のiPad ProのSafariでも、50fps以上を目標に滑らかに動作するように設計する。

写実性と操作時の応答性が両立しない場合は、応答性を優先する。

| 項目 | High | Mid | Low |
|---|---|---|---|
| Pixel Ratio上限 | 1.75 | 1.25 | 1.0 |
| Shadow Map | 2048 | 1024 | 512または近似影 |
| ガラス | Transmission | 軽量透明表現 | 軽量透明表現 |
| Bloom | 有効 | 低解像度 | 疑似発光 |
| 光の粒子数上限 | 450 | 180 | 60 |
| 植物密度 | 100% | 75% | 50% |
| 水面 | 波・環境反射 | 簡易反射 | 固定色と微細な波 |
| 色彩投影 | 床・植物・建築 | 簡略化投影 | 床と植物の近似 |

### 自動画質切り替え

起動時はMidを基本とし、実際のシーンの描画時間を測定する。

- 3秒程度、50fpsを下回る状態が続く場合は一段階下げる。
- 8〜10秒程度、57fps以上の安定した状態が続く場合は一段階上げることを検討する。
- 画質変更後は10秒程度の再変更抑制期間を設ける。
- ドラッグ中やクライマックス中の頻繁な切り替えは避ける。

`?q=low`、`?q=mid`、`?q=high`による画質の強制指定に対応する。強制指定時は自動切り替えを停止する。

### 負荷軽減

- 繰り返し構造や植物にはInstancedMeshを利用する。
- ジオメトリとマテリアルを共有する。
- パーティクルはオブジェクトプールで再利用する。
- 毎フレームの不要なオブジェクト生成を避ける。
- 環境マップは毎フレーム生成しない。
- ポストプロセスの描画解像度を必要に応じて下げる。
- 非表示タブでは描画負荷を抑える。
- フリープレイを続けてもメモリ使用量が増加し続けないようにする。

影や細部を削減しても、ガラスを動かすと色彩が空間を移動するというゲームの核は絶対に削減しない。

## 12. 技術構成

### 12-1. ファイル構成

実装先は以下の1ファイルとする。

`site/games/e05/index.html`

HTML、CSS、JavaScript、シェーダー、手続き的なテクスチャ生成処理をすべてこのファイルに収める。

Three.jsはリポジトリに同梱されているものを使用する。

importmapには以下の対応を設定する。

| import名 | 相対パス |
|---|---|
| `three` | `../../vendor/three/build/three.module.min.js` |
| `three/addons/` | `../../vendor/three/examples/jsm/` |

CDN、外部画像、外部3Dモデル、外部音声、外部フォント、外部APIは使用しない。

必要なアドオンは同梱されているThree.jsのバージョンと互換性のあるものを使用する。

`<head>`内には以下を必ず含める。

`<meta name="robots" content="noindex">`

`</body>`の直前には以下を必ず含める。

`<script src="../../gf-playlog.js" defer></script>`

### 12-2. 状態管理

少なくとも以下の状態を明確に分離する。

| 状態 | 内容 |
|---|---|
| READY | 最初の操作を待つ |
| SELECT | 色ガラスを選ぶ |
| DRAG | ガラスを移動する |
| SNAP | 枠へ吸着する |
| CELEBRATE | 装着成功演出 |
| TRANSITION | 次の段階への移行 |
| CLIMAX | 天井の開閉と光の解放 |
| AFTERGLOW | 余韻 |
| FREEPLAY | 完成後の自由操作 |

装着枚数、装着位置、選択色、天井の可動区画、太陽位置、カメラの注視対象を一元的に管理する。

光の投影処理は、ガラスの位置・姿勢・色を共通の情報源として利用する。ガラス本体と投影結果が異なる状態にならないようにする。

### 12-3. 自動テスト

以下のグローバル変数を用意する。

- `window.__ready`：初期値false。描画と入力の準備が完了した時点でtrue。
- `window.__errors`：初期値は空の配列。実行時エラーや未処理のPromise rejectionなどを記録する。

`?autotest`を付けて起動すると、20枚すべてのガラスを順番に装着し、全4段階、クライマックス、余韻、フリープレイまで自動的に到達できるようにする。

自動テストでは通常プレイと同じ装着処理および状態遷移を利用する。成功回数だけを書き換える方式にはしない。

ユーザー操作なしではAudioContextを起動できない場合があるため、自動テストは無音でも正常に進行可能とする。

`?autotest&q=low`など、画質指定との併用にも対応する。

### 12-4. 禁止語

別紙の禁止語は、HTML、JavaScript、CSS、コードコメント、変数名、画面表示、デバッグ用メッセージを含め、実装内容のどこにも記載しないこと。表記を変更した同義の読み方についても禁止する。

## 14. 最終的な品質基準

このゲームの完成度は、植物の数やポリゴン数、エフェクトの派手さではなく、**小さな一枚のガラスを動かすことで、巨大な建築空間が自分の好きな色に変わる喜び**によって判断する。

特に、ガラスを移動させている途中の透過光、枠に収まる瞬間の手ごたえ、完成した天井が動き出すクライマックスの3点には、十分な実装工数を割くこと。

子どもが完成後も自分から別の色を選び、何度も温室の色彩を変えたくなる作品を目指す。
