# E12 きんいろ りんごの しゅうかくさい — 実装メモ

実装: `site/games/e12/index.html`（HTML + CSS + JS を1ファイル。Three.js 同梱版を importmap で読み込み。CDN・外部画像・外部モデル・音声ファイルなし。テクスチャ・環境マップ・音はすべて実行時に手続き生成）

## 実装の要点

- **舞台**: 中央に巨大な果汁製造機（幅約4m・高さ約4.5m）、右に巨大ガラス瓶（高さ2.5m・直径1.5m）と保存瓶6本のベンチ。収穫する木は3本（左手前・左奥・右奥）で、それぞれ「かご → 傾斜リフト → 木の樋 → 左右のホッパー」で機械につながる。背景に果樹約20〜38本（画質で変化）、遠景の丘に木立のシルエット。
- **1ループ（2操作）**
  - A 枝: 指で触れる（タップ／左右ドラッグ／長押し）と、2節に分かれた枝がばね運動でしなり、リンゴが 0.08〜0.18 秒間隔で落ちる。重力の放物線でかごの決まった位置へ着地し、小さく跳ねて静止、先に入った実も揺れる、かごがわずかに沈む。全部入ると木琴の音と金色の粒。
  - B かご: カメラがかごへ移り、取っ手が持ち上がる誘導。タップでかごが傾斜リフトを上がって傾き、リンゴが1個ずつ樋を転がる（重なり防止の間隔制御、ぶつかると減速と小さな音）→ ホッパー → 桟付きの傾斜コンベヤー → トレイ → 圧搾室。
  - 機械: リンゴが入ると歯車がゆっくり回り始め、段階ごとの回転数（12/19/26/34rpm）まで加速。歯車3枚（32/24/12歯、実際の歯形・かみ合い位相を計算、隣は逆回転）、大歯車の軸の真鍮プーリーから革ベルトで上部のクランクへ。クランク → 連接棒 → クロスヘッド → 圧搾板が上下し、圧搾室の実（最大3個）が少しつぶれてから縮み、果汁の滴が下のガラス受け皿へ。受け皿から透明な管（中身の位置を DataTexture で管理し、果汁の先端・後端が流れて見える）を通って瓶へ。
  - 瓶: 液面が実際に上がる内部メッシュ（深さで色が変わる、底の集光模様、流入点を中心とした波紋、縁の泡、上がる気泡、地面の集光模様）。収穫数 1 個 = 1/115 の液量で、20ループ（4/5/6/8個×5）で満杯（首の少し下）。液面の上昇が止まると反射光が走り、段階に応じた成功音（単音 → 2音 → 3音 → 和音）。
- **段階**: 5ループごとに光と空の色を表の値に沿って5秒かけて補間（午後 → 黄金の夕方、夜にはしない）。第2段階で最初の三角旗、第3段階で奥のランタンが順番に灯る、第4段階でさらに旗。
- **クライマックス（約12〜14秒）**: 最後の果汁が入り瓶が満杯 → 歯車がゆっくり止まり、瓶の底から金色の光が上がる → 瓶から地面に光の輪が広がり、届いた順に旗・リボン・ランタンが展開・点灯 → 金の粒と花びらが舞い上がる → 夕暮れの完成した収穫祭。余韻8秒 → 瓶の下の栓が開き、透明な管で保存瓶6本に移して瓶が空になる → 枝に新しい実が育ち、ループ1から再開（装飾は残る）。
- **白飛び対策（前回の反省）**: ACESFilmic、露出 1.0（クライマックスでも +0.04 まで）、Bloom しきい値 0.9・強さは表の 0.20〜0.65、クライマックスで最大約 0.95（上限 1.0 でクランプ）。光るのはランタン・粒・瓶の中の光の帯だけで、瓶内部に強い点光源は置かない（瓶の上方に弱い暖色光のみ）。クライマックスのスクリーンショット（高画質）で瓶の形・液面・空の色が見えることを確認。
- **カメラ**: 方位・俯角固定の三人称（ロール0、揺れなし）。工程ごとに注目対象の箱を決め、縦横の画角から「箱全体が余白10〜13%で収まる距離」を計算して注目点を画面中央に置く（縦画面は自動で引く、FOV 42°/縦 44°、俯角15〜18°）。工程の切り替えは 0.85〜1.3 秒の補間。誘導はカメラ到着後に開始。
- **操作**: Pointer Events、最初のポインターのみ（2本目は無視）。当たり判定は不可視の球メッシュへの Raycaster ＋ 画面上の円（見た目の約1.45倍、最小半径56px）。途中で指を離しても処理は完了。関係ない場所のタップ・処理中の連打は何も起きない（重複生成・二重加算なし）。touch-action / user-select / overscroll / 長押し / ダブルタップ / ピンチ / gesture イベントを抑止。タブ非表示で一時停止（音も停止）、復帰で再開。WebGL コンテキスト喪失時は停止し、復旧時に環境マップ等を作り直して進行状態を維持。
- **誘導**: 操作待ち 2.5 秒で枝が揺れる・実の周りに金色の粒が集まる・表面を反射光が通る（かごは取っ手が上がる）、以後約4秒ごと。最初のループだけは開始直後から誘導。文字・矢印・UI なし。
- **音**: WebAudio のみ（最初のタップで AudioContext を生成・再開、失敗してもゲーム続行）。葉擦れ（帯域ノイズ）、落下（100〜220Hz）、かご着地、転がり、歯車のクリック（回転速度に連動）、ピストン、果汁の流れと泡、成功音（ペンタトニック）、装飾展開、クライマックスの分散和音とベル。環境音は風・葉擦れ・遠くの小鳥。マスターゲイン＋コンプレッサー、短時間に重なる音は間引き。
- **画質**: `?q=low|mid|high` で固定（自動切替停止）。指定なしは mid で開始し、48fps 未満が3秒で下げ、57fps 以上が12秒で上げる（変更後10秒は固定、クライマックス前後・操作中は変更しない）。high: PR1.5・影2048・Bloom・ガラスは transmission・草20000・背景の木38、mid: PR1.0・影1024・半解像度 Bloom・半透明ガラス・草11000・木30、low: PR0.75・影512・Bloom なし（ランタンは加算の光の粒で代用）・草5000・木22。リンゴの数・機械の動き・充填・収穫祭の展開は全画質で同じ。
- **状態**: `HARVEST_READY → HARVESTING → BASKET_READY → TRANSPORTING → PROCESSING → FILLING`、最後だけ `FINALE → AFTERGLOW → RESET`。`window.__ready`、`window.__errors`（Three.js より前に監視開始）、`window.__test`（state, loop, stage, cycle, jarUnits, level, finale, full, peak, afterglow, reset, finished, centerErr, inFrame, fps など）。
- `?autotest`: 通常と同じ pointerdown/move/up を合成して20ループ（枝はタップ／左右ドラッグ／関係ない場所のタップ後にタップ／長押し＋2本目の指、を順に。かごは5回に1回3連打）→ クライマックス → 余韻 → 移し替え → 再開して操作待ちに戻ったら `finished`。
- 確認用の開発パラメータ: `?pre=N`（N ループ済みの状態から開始。スクリーンショット・サムネイル用）、`?view=jar|machine|finale…`（カメラ固定、autotest では無効）。

## 確認結果（このクラウド環境）

- `python3 -m http.server`（ルート `site/`）＋ Playwright ヘッドレス Chromium（SwiftShader: `--use-angle=swiftshader --enable-unsafe-swiftshader`）で `games/e12/index.html?autotest&q=low` を 1024x768（横）と 768x1024（縦）で全工程実行。結果は `logs/e12/test.txt`、スクリプトは `logs/e12/run-test.js`。
- **横・縦とも PASS**: `__ready === true`、`__errors` 空、コンソールエラーなし。20ループ（収穫 115 個）→ 瓶が満杯 → 光の輪 → 旗 99/99・ランタン 24/24 展開 → 余韻 → 保存瓶へ移し替え → リセットして次の周回の操作待ちに復帰（`finished`）。操作待ち・クライマックスでカメラ到着後の注目点の中心ずれ 0px、注目範囲が画面外に出たフレーム 0。合成の2本目の指（無視 5 回）、関係ない場所のタップ 5 回、処理中の連打 8 回はどれも進行に影響なし（重複なし）。所要 横 424 秒・縦 406 秒（SwiftShader で約 4fps）。
- スクリーンショット: `shot-1.jpg`（序盤の枝）、`shot-2.jpg`（中盤・第3段階の機械）、`shot-3.jpg`（クライマックス約10秒）、`p-shot-1〜3.jpg`（縦）。すべて 300KB 以下の JPEG。クライマックスで瓶全体・液面・空の色・機械の形が見え、白飛びなし。
- mid / high 画質は開発中のスクリーンショット（`?pre=` と `?view=`）で、エラーなしと見た目（Bloom・透過ガラス）を確認。
- サムネイル: `site/thumbs/e12.jpg`（high 画質のクライマックス、640x480、約 67KB、文字なし）。
- 禁止語（ひらがな・カタカナ表記を含む）が `site/games/e12/` と `logs/e12/` にないことを grep で確認。
- 途中で見つけて直した不具合: 自動テストの予約イベントが同じフレームに重なると逆順に実行され、離す→押すの順になって指が押されたままになる問題（時刻順に実行するよう修正）。

## 未解決・注意点

- iPad Safari 実機での動作・FPS・タッチの感触・音は未確認（SwiftShader は CPU 描画のため FPS は性能の指標にならない。自動テストでは音の発音そのものは検証していない）。目標の 50fps 以上は未検証。
- 自動テストの画面は low 画質（Bloom なし）。mid/high の見た目はスクリーンショットとサムネイルで確認。
- 機械は配管を自然流下にするため指示文の目安（高さ3.5m）より高い約4.5m。
- 指示文の照明値のうち HemisphereLight は画面が平板になるため表の値の約0.62倍で使用（太陽光は約1.05倍）。
- 水路は省略（優先度が低く負荷を抑えるため）。
- 1194×834 / 834×1194 / 390×844 の全工程テストは未実施（構図は同じ計算方式）。
