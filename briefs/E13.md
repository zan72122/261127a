# E13 実装指示文：そらいっぱいの シルクのドーム

## 0. 実装の目的と最重要方針

5歳の女の子が、文字を一切読まず、指1本で遊べる写実3Dウェブゲームを制作する。

舞台は、陽光が降り注ぐ白い石造りの中庭。頭上には巨大な円形の屋根骨組みがあり、その周囲に美しい絹織物が巻かれている。プレイヤーが布の端を少し引っ張ると、何メートルもの織物が一気に広がり、屋根の一部になる。これを繰り返し、最後には空を覆う巨大な絹のドームを完成させる。

本作の主役は、布そのものと、布によって変化する空間である。

単なる布の色塗りゲームや、指定された場所を順番にタップするゲームにしてはならない。指先の小さな操作によって巨大な物体が展開し、風を受け、陽光を透かし、空間全体の印象を変えていくことを遊びの中心に据える。

実装時間を配分する際も、装飾品の種類を増やすことより、布の質感、展開する動き、陽光の透過、完成時の空間の変化を優先すること。

## 1. ゲームの狙い

- **夢×写実：** 本物の絹の光沢、繊維、重さ、風によるたわみ、陽光の透過を写実的に表現しながら、現実ではなかなか見られない巨大な絹の建築を作り上げる。
- **高揚感：** 小さな巻物が次々と空へ広がり、何もなかった頭上が壮大で色彩豊かな天井へと変貌していく喜びを生み出す。
- **爽快感：** 指で布を少し引くだけで、長大な織物が勢いよく、かつ滑らかに展開する、操作の大きさを超えた反応を楽しませる。

本作では空へ飛び立つのではなく、自分の手で空間そのものを美しく作り変える体験を提供する。

## 2. 絵から借りる光と色

### 2.1 美術の方向性

参考画からは、白い布に反射する強い陽光、布の折り目に生じる青紫色の陰影、植物を通過する光、風による織物の動きを借りる。

元の構図、人物、建物の配置、筆遣いは再現しない。

布、石材、植物、空、金属は写真のような質感で制作する一方、完成する建築の規模や色彩、光の現象には幻想性を持たせる。魔法を題材とした映画のような驚きのある光の演出を目指すが、既存のキャラクターや建築物、作品固有の意匠は使用しない。

### 2.2 基本のカラーパレット

| 対象 | HEXの目安 |
|---|---|
| 白い石灰岩 | `#F0E7D8` |
| 石材の陰影 | `#A6B7CD` |
| 真珠色の絹 | `#FFF3E4` |
| 桃色の絹 | `#F4A5BD` |
| 水色の絹 | `#8DDCF1` |
| 金色の絹 | `#F2CD79` |
| 絹の反射光 | `#FFF5E3` |
| 真鍮の骨組み | `#C4A46C` |
| 植物の葉 | `#61994D` |
| 空の天頂 | `#58B5EE` |
| 地平線付近 | `#E1F2FF` |

単色で塗りつぶしたような質感を避け、照明、法線、反射、透過によって色に変化を生じさせること。

### 2.3 時間帯と照明の変化

ゲーム開始時は午前中の澄んだ陽光とし、進行に伴って午後から金色の陽光へ移行する。夜にはしない。

| 段階 | 空の色 | 太陽光 | DirectionalLight強度 |
|---|---|---|---:|
| 開始・第1段階 | `#58B5EE` | 約5800K・`#FFF4E5` | 2.6 |
| 第2段階 | `#70C2EE` | 約5400K・`#FFF0D5` | 2.8 |
| 第3段階 | `#83C8EF` | 約4700K・`#FFE2B2` | 3.0 |
| クライマックス | `#91CCEF` | 約4200K・`#FFD9A0` | 3.0 |
| 余韻 | `#A3D3F0` | 約4600K・`#FFE4BA` | 2.5 |

色温度とHEXは演出上の近似値であり、実際のレンダリング結果を見て調整すること。

- HemisphereLight：空側 `#D9EEFF`、地面側 `#E7D5B7`、強度1.2〜1.6。
- AmbientLight：強度0.15〜0.30。
- 環境反射：手続き的に生成した環境マップをPMREMで処理し、強度0.7〜1.0を目安とする。
- 霧：`#DDEEFF`、near 35m、far 100m程度。
- トーンマッピング：ACESFilmicToneMapping。
- 露出：通常0.95〜1.05、最大1.12程度。
- ブルーム：通常0.20〜0.40、成功時0.55〜0.75、クライマックス1.0〜1.2以下。
- ブルームのthreshold：0.85〜1.0。
- ブルームのradius：0.25〜0.45。

ブルームは光源や絹の強い反射部分に限定して効かせる。布の色や繊維の細部を発光で消してはならない。

## 3. 舞台と登場するもの

### 3.1 白い石造りの中庭

直径約30mの円形に近い中庭を制作する。中央は広く空け、その周囲に白い柱、回廊、植物、低い石造りの花壇を配置する。

地形には激しい起伏を設けず、床は白い石灰岩の石畳とする。

石畳はCanvasTextureまたは手続き的なシェーダーを用いて、石ごとのわずかな色差、細かな凹凸、目地を生成する。石材のroughnessは0.65〜0.85、metalnessは0とする。

柱は円筒を基本とし、柱頭、台座、縦溝を組み合わせて建築としての重量感を出す。細部を大量のポリゴンで作らず、反復する部品にはInstancedMeshを活用する。

植物は葉の形状と色を少しずつ変えたインスタンスで制作する。風によって葉先が小さく揺れるようにする。

### 3.2 巨大な屋根骨組み

屋根の直径は約18m、外周部の高さは約17.5m、中央頂部の高さは約22mとする。

高い位置に屋根を設置することで、見上げたときの壮大さと、縦画面でもドーム全体を収めやすい構造を両立する。

屋根を構成する要素は以下とする。

- 円形の外周リング。
- 中央頂部の円形接続部。
- 外周から中央へ伸びる24本の放射状の梁。
- 絹織物を巻いた24個の巻取り装置。
- 各織物を固定する真鍮製の留め具。

骨組みは細身の真鍮と白色金属を組み合わせ、布が取り付けられていない状態でも美しい建築物に見えるようにする。

金属のmetalnessは0.75〜0.90、roughnessは0.25〜0.40程度。金属全体が黄色一色にならないよう、環境反射で陰影を作る。

### 3.3 絹織物の構造と質感

本作で最も制作に力を入れるべき要素である。

24枚の絹織物を用意し、真珠色、桃色、水色、金色をそれぞれ6枚ずつ配置する。各織物は外周部が幅広く、中央の接続部へ向かって細くなる扇形のパネルとする。

巻取り装置は屋根の外周リングにあらかじめ取り付けておく。プレイヤーは布の端を引き出すことで、外周から中央に向かって布を展開する。

絹の材質にはMeshPhysicalMaterialを基本として使用する。

| パラメータ | 目安 |
|---|---:|
| metalness | 0.0 |
| roughness | 0.30〜0.45 |
| sheen | 0.8〜1.0 |
| sheenRoughness | 0.25〜0.40 |
| clearcoat | 0.03〜0.08 |
| normalScale | 0.12〜0.25 |
| opacity | 1.0 |

以下の特徴を必ず再現する。

- 視線の角度によって変化する絹特有の光沢。
- 縦糸と横糸による微細な繊維模様。
- 布の折り目に沿って移動する反射光。
- 布の表面と裏面で異なる光の見え方。
- 逆光を受けた部分から色を帯びて伝わる陽光。
- 自重によるたわみと、固定部付近の張力。

繊維模様は256〜512px程度の手続き的なテクスチャで生成する。縦糸と横糸の交差を微細な法線の変化として与え、太い格子模様にはしない。

絹の透過光は、透過率を上げたガラス状の材質ではなく、布の背面から入る光を近似するシェーダーで再現する。透明オブジェクトの大量重複による描画順序の問題を避けること。

### 3.4 布の動き

高負荷な汎用布物理シミュレーションは必須としない。分割したメッシュの頂点を手続き的に変位させる方式を推奨する。

展開中の布はhigh設定で長手方向40分割、幅方向16分割程度とする。

布の変位には以下を組み合わせる。

- 自重による下向きのたわみ：中央付近で15〜35cm。
- 大きな風の波：振幅10〜25cm、周波数0.3〜0.6Hz。
- 細かな波：振幅1〜4cm、周波数0.8〜1.5Hz。
- 展開時に布の進行方向へ伝わる張力の波。
- 布の縁に生じる細かな揺れ。

固定された端の変位はゼロに近づけ、中央部分ほど自由に動くようにする。

24枚の布を完全に同じ位相で動かしてはならない。隣接する布へ風の波が伝わるように、位相に差を設ける。

### 3.5 空・雲・水・その他の背景

空はグラデーションシェーダーによるSkyDomeを使用する。雲は手続き的なノイズによって生成し、ゆっくり移動させる。雲の陰影には白、淡い青灰色、金色を用いる。

中庭の外縁には小さな浅い水盤を設けてもよい。水面の反射は法線の変位、Fresnel反射、空の色の近似によって表現し、実時間の鏡面反射は必須としない。

乗りもの、動物、人物は登場させない。背景の仕掛けで主役である絹織物から注意をそらさないこと。

外部の画像、3Dモデル、音声、動画、フォント素材は一切使用せず、必要な素材はすべてプログラム内で生成する。

## 4. 指1本のゲームループ

### 4.1 開始画面

起動直後から中庭と屋根骨組みを表示する。タイトル画面やメニュー画面は設けない。

最初の絹織物の端が巻取り装置から少し垂れ下がり、風を受けて揺れている。布の縁を伝う金色の光によって、触るべき場所を自然に示す。

最初の布に触れた瞬間にゲームを開始する。

### 4.2 1回の課題と操作

1. 次に取り付ける布の端と、対応する中央の留め具を画面内に表示する。
2. 布の端に指を置くと、その部分が指に追従し、巻物がわずかに回転する。
3. 指を中央の留め具の方向へ少し動かすと、布が引き出される。
4. 画面短辺の8〜12％程度のドラッグ距離で展開を確定する。
5. 残りの布は自動的に勢いよく広がり、中央の留め具へ向かって伸びる。
6. 留め具が閉じ、布全体に張力の波が伝わる。
7. 布が屋根の一部となり、陽光を透かしながら風に揺れ続ける。
8. 次の布が光を帯び、次の課題へ自然に移行する。

指で布を引く距離と、実際に布が広がる距離には大きな差を持たせる。数cmの指の移動によって、約8mの織物が空へ広がる体験を作る。

### 4.3 布が展開する瞬間の演出

展開アニメーションは約1.2〜1.8秒とする。

最初の0.2秒で巻物が回転を始め、続く約1秒間で布が滑らかに伸び、最後の0.3〜0.5秒で固定される。

巻物の直径が小さくなる動きと、広がる布の長さを連動させる。展開中の布には一時的な大きな波を与え、固定と同時に波が布全体を走り抜けるようにする。

成功の瞬間には、真鍮製の留め具が閉じる動き、澄んだ成功音、布の縁を走る光、少数の金色の光粒を同期させる。

### 4.4 失敗のない操作設計

ドラッグの方向や距離を厳密に判定してはならない。中央の留め具へ正確に指を合わせる必要もない。

途中で指を離した場合も、一定量引き出されていれば自動で取り付けを完了する。短いタップだけでも展開を開始できる救済操作を用意する。

無関係な場所を触っても、警告音、減点、布の破損、最初からのやり直しは発生させない。

約2.5秒間操作がなければ、布の端が小さく持ち上がり、光の反射が移動する。約5秒間操作がなければ、布の端と留め具が順に光り、引っ張る方向を動きで示す。

文字、矢印、手のアイコンは使用しない。

## 5. 盛り上がりの設計

全24枚の絹織物を、8枚ずつの3段階に分けて取り付ける。

1回の操作と演出を合わせて約6〜9秒、段階間の演出とクライマックスを含めて、全体で約3〜5分を想定する。ただし、プレイヤーを急かすタイマーは設けない。

### 第1段階：空に布を広げる

開始時は屋根の骨組みから青空が見えている。

24区画のうち、約3区画おきに8枚の布を取り付ける。取り付けるたびに、何もなかった空間へ美しい色の面が生まれる。

- 風は穏やかで、布の展開速度は標準的。
- 成功音は澄んだ単音を中心とする。
- 石畳に布の形をした淡い色の光が現れる。
- 8枚目の取り付けで、完成済みの布を順に光が巡る。

### 第2段階：色彩で空を包む

さらに8枚の布を、すでに取り付けた布の間へ展開する。

空が少しずつ色彩豊かな天井に変化し、中庭全体が絹を通過した陽光に包まれていく。

- 展開速度を第1段階の約1.15倍にする。
- 風による波の振幅を約1.2倍にする。
- 成功音に2〜3音の和音を加える。
- 石畳や柱に映る色の変化をより鮮明にする。
- 16枚目の取り付けで、風の波が布から布へ伝わる演出を行う。

### 第3段階：巨大な絹のドームを完成させる

残り8枚の布を取り付け、空いていた部分を埋めていく。

最後の数枚では、ドームが完成へ近づいていることを文字なしで理解できるように、残された空の部分を視覚的に際立たせる。

- 展開速度を第1段階の約1.3倍にする。
- 布が固定される瞬間の張力の波を大きくする。
- 成功音に広がりのある和音と高音のきらめきを加える。
- 中央の接続部に金色の光が少しずつ集まる。
- 最後の布だけは通常より約1.5倍長い展開演出とする。

速度を上げる対象は布の展開と光の移動であり、カメラではない。

### クライマックス：絹の天井を駆け巡る陽光

最後の布が中央に固定された瞬間から、約10〜14秒間の特別演出を開始する。

1. 中央の円形接続部に金色の光が集まる。
2. 留め具が一斉に美しく反射する。
3. 中央から外周に向かって、24枚の絹織物を大きな風の波が駆け抜ける。
4. 真珠色、桃色、水色、金色の布を伝って、陽光の反射が連鎖する。
5. 中庭全体に色を帯びた透過光が広がる。
6. 金色の微細な光粒がゆっくりと舞い、壮大な和音が響く。
7. 風が徐々に穏やかになり、完成したドームを見上げる状態へ移行する。

光の解放は、白いフラッシュではなく、**巨大な絹の面を伝わって広がる色彩と反射光**として表現する。

ブルーム強度は最大1.2、thresholdは0.8以上を厳守する。光が最も強くなる瞬間でも、布の折り目、各色の違い、骨組みの形、背景の空の色を判別できなければならない。

### 余韻とフリープレイ

完成後は10秒程度、風に揺れるドームと美しい光景を楽しめる時間を設ける。その後はフリープレイへ移行する。

完成した布に触れると、触れた場所から周囲へ風の波が伝わり、絹の光沢が移動する。布の色に対応した音も鳴る。

中庭の一角に小さな未展開の絹の巻物を出現させ、そこに触れると再び最初から遊べるようにする。再開用の文字や記号は出さない。

完成した状態を楽しんでいる最中に、強制的に屋根を消してはならない。

## 6. カメラと画面構成

### 6.1 基本視点

中庭の中央付近、高さ約1.3〜1.6mから屋根を見上げる視点を基本とする。

画面内で最も大きな面積を占めるものは、現在展開している布、取り付け済みの織物、屋根骨組み、青空とする。

建物や石畳は画面の周辺に適度に映り込み、空間の大きさを伝える役割に徹する。

### 6.2 目標を画面中央に維持する

操作対象である布の端と、その取り付け先の留め具を一つの構図として扱う。

- 操作前：布の端を画面中央付近に置く。
- 操作中：布の端と取り付け位置の両方が見える構図を維持する。
- 展開中：広がっていく布を画面中央に収める。
- 固定時：固定される留め具と布全体を見せる。
- クライマックス：ドームの中央接続部を画面の中央に置き、完成したドーム全体を収める。

次に触る対象は、原則として画面中央50％の範囲に配置する。操作対象と展開する布が画面の外へ見切れないことを優先する。

対象の3D座標と外接範囲を画面座標へ投影し、必要に応じてカメラ位置とFOVを調整する仕組みを実装する。

### 6.3 縦横両対応

PerspectiveCameraを使用し、通常時の垂直FOVは45〜65度程度を出発点とする。

クライマックスでは横画面で55〜75度、縦画面で85〜100度程度を目安に、ドーム全体が収まるよう調整する。これらの値は固定せず、実際のアスペクト比と対象の投影範囲に基づいて補正する。

画面の上下左右に最低8％程度の余白を確保する。

カメラを引く場合も、床の下へ移動させたり、柱を貫通させたりしない。移動距離だけで収まらない場合はFOVで補う。

### 6.4 カメラ酔いの防止

カメラの移動時間は0.8〜1.8秒程度とし、滑らかな補間を使用する。

見上げる方向の変更は必要最小限とし、画面全体が回転するようなロールは行わない。天頂付近を向く際には、安定した画面上方向を明示的に管理する。

ドラッグ中はカメラを固定し、指と布の位置関係がずれないようにする。

カメラシェイク、急なズーム、急旋回、モーションブラー、強い被写界深度は使用しない。

## 7. 操作仕様

iPad SafariおよびPCブラウザに対応する。iPhoneの縦画面でも操作できるレスポンシブ設計とする。

入力はPointer Eventsで統一し、pointerdown、pointermove、pointerup、pointercancelを適切に処理する。

- 同時に受け付けるpointerIdは1個のみ。
- 2本目以降の指による入力は無視する。
- ドラッグ開始時にはPointer Captureを使用する。
- 布の端の当たり判定は見た目の約1.5〜2倍とする。
- 画面上で最低64CSS px程度の当たり判定を確保する。
- 展開アニメーション中の連打で処理が重複しないようにする。
- 画面回転やpointercancel時には安全に入力状態を解除する。

CSSの`touch-action: none`、`overscroll-behavior: none`、`user-select: none`、`-webkit-touch-callout: none`などを用い、必要なイベント処理も組み合わせる。

ゲーム領域でのピンチズーム、ダブルタップズーム、スクロール、長押しメニュー、テキスト選択、画像ドラッグを防止する。

ブラウザやOS固有のシステムジェスチャーまで完全に抑止できるとは限らないため、画面端を主要な操作場所にしないこと。

## 8. 音の設計

すべての音をWebAudioで手続き的に合成する。外部音声ファイルは使用しない。

最初のpointerdownでAudioContextを生成またはresumeし、Safariの自動再生制限に対応する。

| 場面 | 音の内容 |
|---|---|
| 布に触れる | 小さな澄んだ音 |
| 布を引く | 絹が擦れる音 |
| 巻物の回転 | 微細な連続音 |
| 布の展開 | 空気が流れる広がりのある音 |
| 留め具の固定 | 小さな金属音 |
| 第1段階の成功 | ベルに似た単音 |
| 第2段階の成功 | 2〜3音の和音 |
| 第3段階の成功 | 3〜4音の和音と高音の余韻 |
| クライマックス | 広がりのあるアルペジオと壮大な和音 |

布の摩擦音はフィルター処理したノイズ、成功音はサイン波と三角波を中心に制作する。

音階はCメジャー・ペンタトニックを基本とし、連続して操作しても不協和音が生じにくい構成にする。

クライマックスではCadd9などの開放感のある和音を使用してもよい。

環境音は中庭を通り抜ける風と、布が揺れる微細な音を中心とする。主旋律を繰り返すBGMは必須としない。

マスターゲインは0.25〜0.40程度を目安とし、DynamicsCompressorNodeなどで突発的な音量上昇を抑える。発音の開始と終了には短いエンベロープを設け、クリックノイズを防止する。

## 9. ゲーム画面の文字とUI

ゲーム画面には文字、数字、タイトル、スコア、進捗バー、説明文、ボタンラベルを一切表示しない。

開始画面、プレイ中、完成画面のすべてに適用する。

進捗は、頭上に取り付けられた布の枚数と、残されている青空の面積によって伝える。

次の操作は、布の揺れ、縁の反射光、留め具の動きによって案内する。

一般的なゲームUIではなく、3D空間そのものが操作画面として機能する設計にする。

## 10. 画質の自動調整と描画負荷

2020年のiPad ProのSafariで、50fps以上を維持することを目標とする。60fpsで動作することが望ましい。

high、mid、lowの3段階を実装する。

| 項目 | high | mid | low |
|---|---:|---:|---:|
| ピクセル比上限 | 1.75 | 1.25 | 1.0 |
| 展開中の布の分割 | 40×16 | 28×12 | 20×8 |
| 固定済みの布の分割 | 24×12 | 18×8 | 14×6 |
| シャドウマップ | 2048 | 1024 | 512または省略 |
| 光粒の最大数 | 240 | 120 | 48 |
| ブルーム | 有効 | 低解像度 | 省略・簡易表現 |
| 雲の描画 | 詳細 | 簡略 | 最小構成 |
| 水面表現 | 法線・環境反射 | 簡易反射 | 固定反射色 |

起動時はmidを基本とし、数秒間のFPS計測結果に基づいて自動調整する。

実行中もFPSを監視し、48fps未満が約2秒間続く場合は1段階下げる。57fps以上が約8秒間安定している場合は、1段階上げることを検討する。

頻繁な画質切り替えを防ぐため、切り替え後は一定の待機時間を設ける。

`?q=low`、`?q=mid`、`?q=high`による強制指定に対応する。強制指定中は自動画質調整を停止する。

固定済みの布は可能な限り頂点シェーダーで変形させ、CPU側で毎フレーム全メッシュの頂点や法線を更新する処理を避ける。

パーティクルはPointsまたはInstancedMeshで管理し、オブジェクトの使い回しを徹底する。

ドームによる色付きの透過光は、石畳に投影する手続き的な光の模様で近似してよい。高負荷な実時間の光輸送計算は行わない。

low設定でも、布が広がる動き、絹の基本的な光沢、風による波、完成時の光の連鎖は残すこと。画質を下げてもゲームの魅力の中心が失われないようにする。

## 11. 技術構成と実装要件

### 11.1 ファイル構成

実装先は以下の1ファイルとする。

`site/games/e13/index.html`

HTML、CSS、JavaScriptをすべてこのファイルに収める。

Three.jsはリポジトリ内に同梱されているものを利用する。CDN、外部API、外部アセットの取得は禁止する。

importmapでは以下の相対パスを使用する。

| import名 | パス |
|---|---|
| `three` | `../../vendor/three/build/three.module.min.js` |
| `three/addons/` | `../../vendor/three/examples/jsm/` |

必要に応じてEffectComposer、RenderPass、UnrealBloomPassなどを使用する。同梱されているThree.jsのバージョンとの互換性を確認すること。

`<head>` 内に以下を必ず入れる。

`<meta name="robots" content="noindex">`

`</body>` の直前に以下を必ず入れる。

`<script src="../../gf-playlog.js" defer></script>`

既存の共通ファイルや他のゲームのファイルは変更しない。

### 11.2 状態管理

ゲームの状態は明確に分離する。

| 状態 | 内容 |
|---|---|
| READY | 最初の布への入力待ち |
| WAITING | 次の布への入力待ち |
| DRAGGING | 布の引き出し中 |
| UNFOLDING | 布の自動展開中 |
| ATTACHING | 留め具への固定演出 |
| STAGE_CELEBRATION | 段階終了演出 |
| CLIMAX | ドーム完成演出 |
| FREE_PLAY | 完成したドームでの自由遊び |
| RESETTING | 初期状態への復帰 |

通常操作と自動テストは、同じ状態遷移とアニメーション処理を利用する。

布ごとに未展開、展開中、固定済みの状態を管理し、二重取り付けや成功回数の重複加算を防止する。

### 11.3 準備完了とエラー管理

以下のグローバル変数を用意する。

- `window.__ready`：初期値false。3Dシーン、必要な素材、入力処理、初期描画の準備完了後にtrueとする。
- `window.__errors`：初期値は空配列。実行時エラー、未処理のPromise rejection、初期化エラーなどを記録する。

ユーザー操作を受け付けられない状態で`window.__ready`をtrueにしてはならない。

### 11.4 自動テスト

`?autotest`を付けて起動した場合は、人間の操作なしで以下を順に実行する。

1. ゲーム開始。
2. 第1段階の8枚を取り付ける。
3. 第2段階の8枚を取り付ける。
4. 第3段階の8枚を取り付ける。
5. クライマックスを最後まで再生する。
6. フリープレイへ移行する。
7. 完成状態を維持する。

待機時間は短縮してよいが、布の展開や固定処理、段階遷移を省略して成功回数だけを増やす実装は禁止する。

自動テストでは、ブラウザのユーザー操作制限によってAudioContextを起動できない場合も正常に進行できるようにする。

検証用として現在の段階、取り付け枚数、ゲーム状態、FPS、画質設定をJavaScriptから取得できるようにしてよい。ただし、ゲーム画面には表示しない。

### 11.5 リソース管理

画面回転、ウィンドウのリサイズ、バックグラウンドへの移行、復帰、WebGLコンテキストの消失を考慮する。

非表示時は不要なアニメーションや音声処理を停止または抑制する。復帰時に大きなdeltaTimeをそのまま適用しない。

再プレイではGeometry、Material、Texture、AudioNode、イベントリスナーなどが無制限に増加しないようにする。

別紙の禁止語を、コード、コメント、変数名、文字列、関連文書に記載しないこと。表記を変えた使用も禁止する。

## 13. 最終的な品質基準

本指示文の24枚・3段階という構成、建築の寸法、照明強度、アニメーション時間、描画負荷の設定値は、実装のための初期設計値である。実際の描画結果を確認し、体験を損なわない範囲で調整してよい。実機で検証できなかった項目については、検証済みとせず、その旨を実装完了報告に記載すること。

本作の完成基準は、単に24枚の布を取り付けられることではない。

子どもが最初の布を引いた瞬間に驚き、次の布も自分で引きたくなり、最後には自分の作った巨大な絹の天井をしばらく見上げていたくなることが重要である。

特に、巻物が解ける瞬間、長大な織物が空へ伸びる瞬間、布が張って波が走る瞬間、陽光が絹を通過して空間全体の色を変える瞬間の品質を徹底的に高めること。

**指先の小さな動きで、空いっぱいの美しい建築が生まれる。**

この体験を本作の中心として、最後まで一貫させること。
