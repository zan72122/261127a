# E03 実装指示文：にじいろ おんせんオーケストラ

## 1. ゲームの狙い

文字がまだ読めない5歳の子どもが、指1本で大地に点在する間欠泉を操作し、最後には自然そのものを巨大な楽器として演奏できる、写実3Dウェブゲームを制作する。

- **夢×写実：** 温泉の鉱物沈着、透明な水、立ち上る蒸気、陽光を受けて輝く水滴を写実的に再現し、現実の自然景観と幻想的な水の演奏を融合させる。
- **高揚感：** 小さな噴水から背の高い水柱へと発展し、最後には五つの間欠泉が大地全体を使った壮大なシンフォニーを奏でる。
- **爽快感：** ポンプを押して圧力を蓄積し、指を離した瞬間に大量の水が勢いよく空へ解き放たれる、物理的な手ごたえを楽しむ。

このゲームの中心は「押す・ためる・放つ」という操作である。

単に美しい温泉を眺めるゲームにはしない。自分の指で巨大な自然現象を引き起こしているという実感を、すべての演出の中心に置くこと。

## 2. 絵から借りる光と色

### 2.1 美術の基本方針

トーマス・モランの指定作品から、青緑色の温泉、金色の鉱物沈着、乳白色の岩肌、陽光に透ける蒸気という自然景観の要素を借りる。

原画の構図や絵柄は再現せず、実際に存在しそうな地形と水の質感をThree.jsで立体的に構築する。

ラッセンの作品に見られるような、現実と想像が溶け合う色彩豊かな世界を目指す。映画の魔法的な場面に通じる光の演出や驚きの感覚も取り入れるが、既存のキャラクター、建造物、ブランド、作品固有の意匠は使用しない。

### 2.2 色彩設計

| 温泉の深部 | `#078DA8` |
| 温泉の浅瀬 | `#48DCCB` |
| 水際の鉱物沈着 | `#E7B45A` |
| 琥珀色の温泉 | `#DFA443` |
| 石灰質の岩肌 | `#F2E7D2` |
| 湿った岩肌 | `#B58D61` |
| 遠方の山 | `#91B5C8` |
| 蒸気 | `#F5F9FF` |

温泉は単色で塗りつぶさず、水深、鉱物の分布、光の反射によって連続的に色が変化するようにする。

虹色は水滴や霧の中に現れる光学的な現象として表現する。水柱そのものを原色の七色に塗り分けない。

### 2.3 時間帯による光の変化

ゲームの進行に伴い、朝から午後へと景色が変化する。夜間や月光の場面は設けない。

上記は1ワールド単位を約1mとした場合の初期値であり、実際の描画結果に応じて調整する。色温度は太陽光の色を決定するための目安とする。

### 2.4 レンダリングと光の演出

- トーンマッピング：`ACESFilmicToneMapping`
- 出力色空間：`SRGBColorSpace`
- 露出：0.95〜1.15
- 通常時のブルーム強度：0.25〜0.45
- 成功時のブルーム強度：0.55〜0.8
- クライマックス時のブルーム強度：0.9〜1.2
- ブルームのしきい値：0.8〜1.0
- ブルーム半径：0.25〜0.45

ブルームは陽光の反射、水滴、圧力計の発光部分などに限定する。岩肌や空、ポンプ全体が発光しているような画面にしない。

水面には太陽の方向に伸びる反射光を作り、カメラの角度によって輝きが変化するようにする。

蒸気には逆光を受けた際に縁が輝く効果を加える。蒸気によって操作対象が隠れないように、密度と透明度を制御すること。

## 3. 舞台と登場するもの

### 3.1 温泉地帯の全体構成

広大な高原に、鉱物が長い年月をかけて堆積した段々状の温泉地帯を作る。

遠方には山々と草原が広がり、その上には青空と白い雲がある。手前から奥へと五つの間欠泉を配置し、それぞれの近くに専用のポンプを設置する。

五つの間欠泉は緩やかな扇形に配置する。完全な横一列にはせず、奥行きを利用して縦向き画面でも全体を見渡せる構造にする。

| 対象 | 寸法の目安 |
|---|---|
| 温泉地帯の主要部分 | 幅36m・奥行き32m |
| 個々の温泉池 | 直径5〜8m |
| 間欠泉同士の距離 | 7〜10m |
| ポンプの高さ | 1.8〜2.2m |
| 温泉の段差 | 0.3〜1.2m |
| 最大噴射高度 | 約17m |

乗りもの、人物、動物は登場させない。本作では温泉とポンプ、水柱そのものが主役である。

### 3.2 地形と鉱物沈着

地形はPlaneGeometryや独自のBufferGeometryを利用し、複数の周波数のノイズによって生成する。

温泉の縁には、不規則な曲線を持った石灰質の段丘を作る。完全な円形や、同じ形状の岩の反復は避ける。

温泉の水際には、乳白色、黄土色、琥珀色、赤褐色が帯状に重なる鉱物沈着を再現する。

岩肌のPBRマテリアルの目安：

- Roughness：乾燥部分0.75〜0.95、湿潤部分0.25〜0.45
- Metalness：0.0
- 法線の微細な変化：0.1〜0.3相当
- 頂点カラーや手続き的テクスチャによる局所的な色の変化

鉱物の結晶や水際の凹凸は、細かなポリゴンを大量に配置するのではなく、ノーマルマップやシェーダー内のノイズを利用する。

### 3.3 温泉の水

温泉には水深に応じた色の変化を実装する。

浅瀬では底の鉱物が透け、深部では青緑色が濃くなるようにする。水面には異なる方向へ進む複数の波を重ねる。

水面シェーダーに以下を組み込む。

- フレネル反射
- 複数の正弦波による法線の変化
- 水深に応じた光の吸収
- 太陽光のスペキュラ反射
- 水底に映る簡易的なコースティクス
- 水滴が落下した場所から広がる同心円状の波紋

水面の基準Roughnessは0.06〜0.15、IORは1.333相当とする。

環境反射はプロシージャルな空の環境マップを基本とし、五つの温泉それぞれについて毎フレーム反射用カメラを描画する方式は避ける。

### 3.4 空と雲

空は大型の球体または専用シェーダーで描画し、天頂から地平線にかけて自然な色の勾配を作る。

雲はノイズによって生成した半透明の形状を利用し、立体感と陽光による陰影を持たせる。移動速度は遅くし、背景が高速で流れる演出は行わない。

### 3.5 五つのポンプ

ポンプは、真鍮、銅、磨かれた金属、透明なガラスを組み合わせた架空の機械とする。

既存製品の再現ではなく、温泉地帯に設置された楽器のような統一感のあるデザインにする。

各ポンプに次の構造を持たせる。

- 指で押し込める大型の円形ピストン
- 圧力の蓄積が見える透明な円筒
- 円筒内部を上昇する水
- 水圧で動く機械式の針
- 圧力の充填状況を示す発光リング
- 間欠泉へつながる金属製の配管

圧力計には文字や数字を付けない。

ポンプの金属部分はMetalness 0.7〜0.9、Roughness 0.2〜0.4を目安とする。

五つのポンプには、ターコイズ、琥珀、エメラルド、サファイア、ローズゴールドのアクセントを割り当て、それぞれ異なる音程を持つ楽器として扱う。

### 3.6 間欠泉の水柱

本作で最も重要な描画対象であるため、水柱の質感と運動には特に力を入れること。

水柱を単純な青い円柱や、均一な粒子の集合体として表現してはならない。次の要素を重ね合わせる。

| 構成要素 | 表現方法 |
|---|---|
| 水柱の中心部 | 時間とともに変形する半透明のメッシュ |
| 水柱の外周 | ノイズによって揺らぐ水の薄膜 |
| 飛散する水滴 | InstancedMeshまたはPoints |
| 水柱の根元 | 白い泡と水煙 |
| 頂点付近 | 放物線を描いて広がる水滴 |
| 落下部分 | 重力に従って水面へ戻る水滴 |
| 着水部分 | 水しぶきと拡大する波紋 |

噴射直後は細く勢いのある水柱が立ち上がり、頂点付近で水が四方へ広がり、その後に大量の水滴が落下する。

水の飛散は、初速度と重力を用いた簡易的な弾道計算で実装する。重力加速度は9.8m/s²を基準とするが、見栄えを優先して調整してよい。

水柱の直径は根元で0.5〜0.9m程度。噴射中は太さや輪郭を絶えず変化させる。

流体シミュレーションをそのまま実装する必要はない。少ない計算量で水の重量感、連続性、透明感を再現することを優先する。

### 3.7 虹と蒸気

飛散した水滴の中に、赤、橙、黄、緑、青、紫へと連続的に移り変わる虹を発生させる。

虹は独立した不透明なアーチではなく、水煙の中に透けて現れるようにする。太陽、カメラ、水滴の位置関係を参考にしつつ、鑑賞しやすい位置へ演出的に補正してよい。

噴射が終わった後も虹を約1〜2秒残し、蒸気とともに徐々に消失させる。

蒸気はノイズを持つ半透明パーティクルで表現し、ゆっくり上昇しながら拡散させる。煙のような灰色や黒色にはしない。

外部の画像、3Dモデル、テクスチャ、音声ファイルは一切使用しない。必要な素材はすべてGeometry、CanvasTexture、シェーダー、WebAudioなどを利用して生成する。

## 4. 指1本のゲームループ

### 4.1 基本の流れ

1. 五つのポンプのうち一つが発光し、操作を誘う。
2. 子どもがポンプのピストンを指で長押しする。
3. ピストンが沈み、透明な円筒内部の水位が上昇する。
4. 圧力計の針が動き、配管の内部を光が進む。
5. 圧力が満タンになると、発光リングが一周して完成する。
6. 子どもが指を離した瞬間、間欠泉から大量の水が噴き出す。
7. 水滴が陽光を受けて輝き、虹と成功音が発生する。
8. 水が温泉へ戻り、次のポンプが発光する。

この一連の操作を、各段階で五つの間欠泉について繰り返す。

### 4.2 長押し中の手ごたえ

長押ししている時間に比例して、機械と音と水の状態を連続的に変化させる。

| 圧力 | 視覚的な反応 | 聴覚的な反応 |
|---|---|---|
| 0〜25% | ピストンが沈み始める | 小さな機械音 |
| 25〜50% | 円筒内の水位が上がる | 水の流れる音 |
| 50〜75% | 配管が振動し、光が進む | 上昇する音程 |
| 75〜99% | 噴出口から蒸気が出る | 響きが次第に豊かになる |
| 100% | 発光リングが完成する | 澄んだ充填完了音 |

圧力が100%になったらピストンをわずかに押し返し、発光リングをゆっくり脈動させることで、指を離すタイミングを伝える。

圧力が満タンになっても勝手に噴射しない。自分が指を離したことによって水柱が発生するという因果関係を守る。

### 4.3 失敗を作らない仕組み

途中で指を離した場合は、蓄積した圧力を維持する。再び押せば続きから充填できるようにする。

対象外の場所に触れても、減点、警告音、画面の揺れ、圧力の低下などは発生させない。

満タンになるまで押し続けられない子どもでも、数回の短い長押しを繰り返せば必ず噴射に到達できる構造にする。

ポンプが満タンになった後は、何秒押し続けても破裂や暴走を起こさない。

時間制限、残機、得点、ランキング、失敗画面は設けない。

### 4.4 操作を誘う演出

操作対象が切り替わった直後から、該当するポンプの円形ピストンをゆっくり発光させる。

約3秒間操作がなければ、発光リングの脈動と、ピストンのわずかな上下運動を追加する。さらに操作がなければ、小さなチャイムを一度鳴らす。

文字、矢印、手のアイコン、説明用ウィンドウは使用しない。

次に操作すべき対象以外のポンプは、充填を誘う発光を停止する。

**触るもの、変化するもの、操作の結果を、常に同じ画面内で理解できるようにすること。**

### 4.5 指を離した瞬間の爽快感

圧力満タンの状態から指を離した際は、入力から100ms以内を目標に噴射演出と音を開始する。

ピストンが戻る動き、配管を通過する光、水柱の立ち上がり、噴射音を連続した一つの現象としてつなげる。

噴射前に長い待機時間やカットシーンを挟まない。

ポンプの反動は機械部分だけに表現し、カメラを振動させない。

## 5. 盛り上がりの設計

全体を3段階、各段階5回の噴射、合計15回の成功操作で構成する。

1回の操作から噴射、次の対象への移行までを約9〜13秒とし、通常の遊び方でクライマックスと余韻を含めて約3〜5分を想定する。

子どもの操作速度によって所要時間が変わっても問題ない。時間を合わせるためだけの待機は設けない。

### 5.1 第1段階：五つの温泉を目覚めさせる

朝の温泉地帯から始まる。

| 項目 | 設定 |
|---|---|
| 成功回数 | 5回 |
| 満タンまでの長押し | 約1.6秒 |
| 水柱の最大高度 | 4〜5m |
| 噴射と着水の演出 | 約4〜5秒 |
| 音楽 | 単音と水音 |
| 虹 | 小さな虹 |

それぞれのポンプを初めて操作する段階である。操作対象が直感的に分かることを最優先する。

一度噴射した間欠泉は、温泉の色彩や水面の輝きが増し、目覚めたことが景色から伝わるようにする。

### 5.2 第2段階：虹の水柱を育てる

太陽が高くなり、水面の青緑色が鮮やかになる。

| 項目 | 設定 |
|---|---|
| 成功回数 | 5回 |
| 満タンまでの長押し | 約2.2秒 |
| 水柱の最大高度 | 8〜10m |
| 噴射と着水の演出 | 約5〜6秒 |
| 音楽 | 2〜3音の和音 |
| 虹 | 水柱を囲む大きな虹 |

水柱の太さ、飛散する水滴の範囲、噴射音を増強する。

操作した間欠泉に呼応して、以前に操作した別の間欠泉が小さな水柱を一度だけ噴き上げる演出を加える。

自分の操作によって、周囲の自然が少しずつ音楽を奏で始めたことを感じさせる。

### 5.3 第3段階：大地を楽器にする

午後の金色の陽光が温泉地帯を包む。

| 項目 | 設定 |
|---|---|
| 成功回数 | 5回 |
| 満タンまでの長押し | 約2.8秒 |
| 水柱の最大高度 | 13〜15m |
| 噴射と着水の演出 | 約6〜7秒 |
| 音楽 | 和音と短いアルペジオ |
| 虹 | 複数の温泉にまたがる虹 |

一つのポンプを操作するたびに、周囲の間欠泉が順番に応答する。

最後のポンプに圧力が蓄積される際は、五つすべての間欠泉の根元から少量の蒸気が立ち上る。配管にも順番に光が走り、大規模な噴射が始まることを予感させる。

各段階では五つの間欠泉を必ず一度ずつ操作させる。長押し時間以外の難易度は増加させない。

### 5.4 クライマックス：温泉オーケストラ

15回目の操作で指を離すと、約25〜30秒間の水のオーケストラが始まる。

| 経過時間 | 演出 |
|---|---|
| 0〜4秒 | 最後の間欠泉が高さ15mの水柱を噴射する |
| 4〜10秒 | 五つの間欠泉が順番に異なる音程で噴射する |
| 10〜16秒 | 左右の間欠泉が交互に噴射し、水のリズムを作る |
| 16〜22秒 | 五つの水柱が音楽に合わせて連続的に立ち上がる |
| 22〜25秒 | 全間欠泉が最大約17mまで同時噴射する |
| 25〜30秒 | 水滴が降り注ぎ、大きな虹が現れる |

最後の同時噴射では、温泉地帯全体を横断する虹と、無数の水滴による光の解放を表現する。

画面全体を白くするフラッシュは使用しない。光量の増加は局所的な反射、水滴の増加、複数の水柱、和音の厚みで表現する。

クライマックスでもブルーム強度は最大1.2程度、しきい値は0.8以上とし、空の色、五つの水柱の輪郭、虹、温泉の地形が判別できること。

### 5.5 余韻と再プレイ

クライマックス終了後は約8秒間の余韻を設ける。

大きな水柱は徐々に低くなり、温泉の水面に波紋が広がる。虹がゆっくり消え、環境音だけが残る。

その後、約3秒かけて朝の景色へ移行し、すべてのポンプを初期状態に戻す。

開始時と同じように中央のポンプが発光することで、再び遊べることを示す。

終了画面、リザルト画面、再プレイボタンは設けない。

## 6. カメラと画面構成

### 6.1 基本視点

五つの間欠泉を見渡せる、斜め上からの透視投影カメラを採用する。

- PerspectiveCameraの垂直FOV：40〜48度
- 俯角：25〜35度
- カメラ移動の補間時間：1.2〜2.0秒
- カメラのロール角：常に0度
- カメラの振動：なし

子ども自身にカメラを操作させない。

### 6.2 操作対象と水柱の追従

ポンプの操作前は、そのポンプが画面中央付近に位置するようにカメラを移動する。

長押し中はカメラを固定し、指の下から操作対象が移動しないようにする。

噴射に備えて、操作前から最大噴射高度を含めた構図を確保する。噴射開始後は水柱の中心へ向かって注視点を滑らかに移動する。

クライマックスでは五つの間欠泉全体の中心を注視点とする。

水柱が伸びるたびに慌ててカメラを引くのではなく、予想される最大高度と水滴の飛散範囲から、必要な撮影距離を事前に算出すること。

### 6.3 縦向き・横向きへの対応

画面のアスペクト比が変化するたびに、カメラの距離と注視点を再計算する。

水柱、虹、ポンプを含むバウンディングボックスを画面座標へ投影し、重要な対象が安全領域内に収まるまでカメラの距離を調整する。

画面の上下左右には原則として約8〜10%の余白を確保する。

次の操作対象は画面の中央30%程度の領域に配置し、五つの間欠泉も可能な限り同じ画面内に収める。縦向きで操作対象が小さくなる場合は、地形の配置やカメラ角度も調整する。

クライマックスにおいても、水柱の頂点や虹の端を見切れさせないこと。

## 7. 操作仕様

iPad SafariとPCブラウザの両方に対応させる。タッチ操作とマウス操作はPointer Eventsで統一する。

使用する操作は以下の三つだけとする。

- ポンプに触れる。
- そのまま押し続ける。
- 指またはマウスボタンを離す。

`pointerdown`、`pointerup`、`pointercancel`、`lostpointercapture`を適切に処理する。

有効なポインターは同時に一つだけとし、二本目以降の指による操作は無視する。Pointer Captureを使用し、長押し中に指が多少ずれても圧力の蓄積を継続する。

操作対象には、見た目より1.3〜1.6倍程度広い当たり判定を設ける。画面上で最低64〜80 CSSピクセル程度の操作領域を目安とする。

ブラウザによる意図しない操作を防止するため、以下を実施する。

- `touch-action: none`
- `user-select: none`
- `-webkit-touch-callout: none`
- スクロールとオーバースクロールの抑制
- ダブルタップやピンチによるズームの抑制
- 長押し時のコンテキストメニューの抑制

SafariでCSSだけでは防止できないジェスチャーについては、必要なイベント処理を追加する。

画面回転、アプリ切り替え、タッチキャンセルの際は長押し状態を安全に解除し、それまでの圧力を維持する。意図しない噴射や入力不能状態を発生させないこと。

## 8. 音響設計

### 8.1 基本方針

すべての音をWebAudio APIで手続き的に合成する。既存の楽曲や音声ファイルは使用しない。

最初の有効なタップでAudioContextを生成または再開する。そのタップは音声の有効化だけに消費せず、ポンプの操作としても処理する。

### 8.2 環境音と操作音

| 音 | 合成方法 |
|---|---|
| 温泉の水音 | フィルターを通したノイズ |
| 風 | 低域のノイズと緩やかな音量変調 |
| ピストンの動作音 | 短い低周波音と金属的な倍音 |
| 圧力上昇音 | 周波数が連続的に上昇するサイン波 |
| 満タン音 | 澄んだベル状の音 |
| 噴射音 | 帯域の異なる複数のノイズ |
| 水滴の着水音 | 短い減衰音を不規則に重ねる |
| 虹の出現音 | 高音域のアルペジオ |

環境音は控えめにし、ポンプを操作した音と噴射音を聞き取りやすくする。

### 8.3 五つの間欠泉の音程

各間欠泉に、同じペンタトニックスケール内の音程を割り当てる。

| 間欠泉 | 基準音 |
|---|---|
| ターコイズ | C4・261.63Hz |
| 琥珀 | D4・293.66Hz |
| エメラルド | E4・329.63Hz |
| サファイア | G4・392.00Hz |
| ローズゴールド | A4・440.00Hz |

第1段階では単音、第2段階では和音、第3段階ではオクターブ音やアルペジオを加える。

クライマックスでは、水柱の噴射と発音のタイミングを同期させ、96〜108 BPM程度のオリジナルの演奏を作る。

MasterGainは0.2〜0.35程度から調整し、コンプレッサーなどで突発的な大音量を防ぐ。発音と消音には短いフェードを使用し、クリックノイズを避ける。

## 9. 画面の文字と開始方法

ゲーム画面には文字、数字、得点、進捗率、ボタンのラベルを一切表示しない。

圧力の蓄積は水位、圧力計の針、発光リングで示す。段階の進行は景色と水柱と音楽の変化によって伝える。

起動直後から温泉地帯を表示し、中央のポンプがゆっくり発光している状態にする。

そのポンプに触れることで、直ちに最初の操作が始まるようにする。

タイトル画面、説明画面、ロード完了ボタンは作らない。別紙の禁止語は、表記違いも含めてコードやコメントに記載しない。

## 10. 画質の自動調整

2020年モデルのiPad Proを主な性能基準とし、実際のゲーム中に50fps以上、可能であれば60fpsを維持することを目標とする。

| 設定 | high | mid | low |
|---|---:|---:|---:|
| DevicePixelRatio上限 | 2.0 | 1.5 | 1.0 |
| 影の解像度 | 2048 | 1024 | 512または無効 |
| ブルーム | 有効 | 低解像度 | 無効または簡易発光 |
| 水滴の総数上限 | 8000 | 3500 | 1200 |
| 蒸気の総数上限 | 400 | 180 | 80 |
| 地形の分割数の目安 | 128×128 | 80×80 | 48×48 |
| 水面の法線変化 | 3層 | 2層 | 1層 |

初期画質はmidとし、起動時およびゲーム中のFPSを測定して調整する。

- 約3秒間、平均FPSが50を下回った場合は一段階下げる。
- 約10秒間、平均FPSが58以上で安定した場合は一段階上げることを検討する。
- 画質変更後は一定時間の再変更禁止期間を設ける。
- バックグラウンド移行中や起動直後のシェーダーコンパイル時間は判定から除外する。

`?q=low`、`?q=mid`、`?q=high`で画質を固定できるようにする。固定指定時は自動画質変更を停止する。

パーティクルはプール方式で再利用し、毎フレームのGeometryやMaterialの生成を避ける。クライマックスで五つの水柱が同時に発生しても負荷が急増しないようにする。

low設定でも、水柱の高さ、虹、ポンプの動作、音楽、操作の手ごたえは省略しない。

## 11. 技術構成

### 11.1 ファイルとライブラリ

実装先は以下の1ファイルとする。

`site/games/e03/index.html`

HTML、CSS、JavaScript、シェーダーをこのファイル内にまとめる。

Three.jsはリポジトリに同梱されている以下のファイルを使用する。

- `site/vendor/three/build/three.module.min.js`
- `site/vendor/three/examples/jsm/`

importmapを利用し、`three`を`../../vendor/three/build/three.module.min.js`へ、`three/addons/`を`../../vendor/three/examples/jsm/`へ対応させる。

CDNや外部ライブラリの追加、外部素材の取得は禁止する。

`<head>`内に以下を必ず含める。

`<meta name="robots" content="noindex">`

`</body>`の直前には以下を必ず含める。

`<script src="../../gf-playlog.js" defer></script>`

### 11.2 状態管理

ゲームの状態を明示的に管理し、複数の噴射や状態遷移が競合しないようにする。

| 状態 | 内容 |
|---|---|
| READY | ポンプへの入力待ち |
| CHARGING | 長押しによる圧力の蓄積 |
| CHARGED | 満タン・指を離す操作の待機 |
| ERUPTION | 間欠泉の噴射 |
| TRANSITION | 次の操作対象への移行 |
| CLIMAX | 五つの間欠泉による演奏 |
| AFTERGLOW | 余韻 |
| RESET | 初期状態への復帰 |

途中で指を離した場合は、圧力を維持したままREADYへ戻す。

ゲーム進行、描画、入力処理、音響処理を論理的に分離する。フレームレートによって圧力上昇速度や音楽のテンポが変化しないように、経過時間を基準として処理すること。

### 11.3 準備完了とエラー監視

`window.__ready`を初期状態で`false`とし、シーン構築、必要な素材生成、初回描画、入力受付の準備が完了した時点で`true`にする。AudioContextの起動は準備完了条件に含めない。

`window.__errors`を空配列として初期化し、実行時エラー、未処理のPromise rejection、初期化エラーなどを記録する。

エラー監視はThree.jsの読み込み前から有効にする。

### 11.4 自動プレイ

URLに`?autotest`が付いている場合、自動的にポンプの充填と解放を繰り返す機能を実装する。

通常プレイと同じ圧力蓄積処理、噴射処理、状態遷移を利用する。単に成功回数を書き換える方式にはしない。

15回の噴射、全3段階、クライマックス、余韻、初期状態への復帰まで実行できるようにする。

自動テスト時の音声再生はブラウザの自動再生制限に従い、音声が無効でもゲーム進行を止めない。

テスト結果やデバッグ情報はコンソールまたはJavaScriptの監視用変数から確認できるようにし、ゲーム画面には表示しない。

## 13. 実装時の最重要方針

優先順位は次のとおりとする。

1. 自分の指で圧力をため、解放する気持ちよさ。
2. 水柱が勢いよく立ち上がる物理的な爽快感。
3. 操作方法が直感的に理解できること。
4. 五つの間欠泉による壮大なクライマックス。
5. 温泉、水滴、鉱物、陽光の写実性。
6. iPadでの滑らかな動作。

装飾を増やすことよりも、押している間の機械の動作と、指を離した瞬間の水の解放を徹底的に作り込むこと。

完成時には、子どもが自分の小さな指で広大な自然を動かし、大地全体を楽器に変えたと感じられる作品にすること。
