# E08 きんいろの おかの かざぐるま — 実装メモ

実装: `site/games/e08/index.html`（HTML + CSS + JS を1ファイル。Three.js r0.187.0 同梱版を importmap で読み込み。CDN・外部画像・外部モデル・音声ファイルなし）

## 実装の要点

- **遊び**: 黄金色の丘に白い風車が15基（3列×5基、列ごとに奥の丘へ。蛇行順）。中央の停止中の風車の羽根（または回転軸の周り）をタップ／スワイプすると、押した瞬間に回り始め（最初のフレームで角速度を与える）、慣性で約16rpmまで加速。スワイプは回転方向と速さを反映するが、向きや速さが合っていなくても必ず回る。回っている風車に触れると一時的に速くなり、新しい風の波が出る（進行数は増えない。0.6秒以内の連打は波を重ねない）。
  - 当たり判定は画面上の回転範囲の円（羽根の長さ×1.3、最低半径40px＝直径80px）。最初の指の pointerId だけを扱い、2本目以降は無視。背景に触れると、触れた地面から小さな風の輪と種子が出るだけ（進行に影響なし、不快な音なし）。
  - 放置: 待機中は触ってほしい羽根（右下の1枚）の縁を根元から先端へ光が流れる。3秒で光が強く速くなり、6秒で羽根が約3°ゆっくり揺れる。自動で成功にはしない。
  - 状態: LOADING → WAIT → START → WAVE（追加操作可）→（5・10基目は STAGE_END）→ MOVE → WAIT …… 15基目 → CLIMAX（18秒）→ AFTER（10秒）→ フリープレイ（WAIT/WAVE/MOVE を `free` フラグ付きで再利用。中央の風車に触れると波が出て次の風車へ順に移る）。
- **風の波（核）**: 波は最大32本を uniform 配列で GPU に渡し、草（頂点シェーダー）と地面（フラグメントシェーダー）で同じ `windAt()` を評価。各波は発生位置・発生時刻・速度・振幅・幅・到達範囲を持つリングで、前線の通過時に草が根元から倒れ（段階1: 30° / 2: 34° / 3: 38°、合計は45°で頭打ち）、通過後は減衰する揺り戻し（約1.5秒）。前線の少し後ろはわずかに暗く、前線は金色の光沢（逆光ほど強い）になるので、光の帯が丘を越えていくように見える。速度・幅は段階ごとに 15/19.5/23 u/s、7/10.5/12 u（第2段階は約1.3倍速・1.5倍幅）。常時のそよ風（2〜6°の周期的な突風）と、回っている風車からの小さな周期波で草原は止まらない。
  - 第2段階: 新しい風車を回すと近くの既存の風車が順に速まって波を出す。第3段階: 既存の全風車が距離に応じた時間差で波を出し、波が合流する。5基目・10基目では、その段階の風車が順に波を送る。
  - クライマックス: 全風車が加速、手前の列から順に大きなリング、さらに手前から奥へ／奥から手前へ交互に5本の大きなうねり（速度34 u/s）が谷全体を横断して交差。種子が空へ上昇、Cmaj9 の和音とアルペジオ。
- **絵作り**: 地形は風車の下の丘＋周辺の丘（ガウス関数）＋低周波の正弦波＋少量のノイズ＋遠方の連なる稜線。地形メッシュは中心ほど細かい非一様格子（low 192 / mid 224 / high 256 分割、±1500）。地面の色は高さ・傾き・ノイズとパレットから計算し、遠方ほど青紫（farHill）に寄る大気遠近。草は InstancedBufferGeometry の株（葉6枚＋穂2本の近景用、葉4枚＋穂1本の遠景用、どちらも先細りで弧を描く帯）を、注視点の周りで世界座標に固定したタイルとして折り返し配置（カメラが動いても草は滑らない）。高さは GPU で高さテクスチャから取得。風による曲げ・揺り戻し・光沢はすべて頂点／フラグメントシェーダー。
  - 風車: 先細りの塔（Lathe）、コンクリート基礎、金属のフランジ、ナセル、ノーズコーン、翼断面・ねじれ・先細りを持つ手続き生成の羽根3枚（MeshStandardMaterial、roughness 0.36〜0.42、metalness 0.1〜0.12、未塗装金属部 0.78）。ロータ面はカメラに向け、少し太陽側に振って羽根が黒いシルエットにならないようにした。
  - 空: グラデーション＋太陽のにじみ＋手続き生成の雲（太陽側が金色、反対側が青灰色、ゆっくり流れる）。環境マップはこの空から PMREM で生成し、時間帯が変わると更新。
  - 時間帯: 進行に合わせて、指示文の表の色（空・地平線・太陽・草の根元/中央/穂・遠方の丘・羽根）と太陽仰角 38°→28°→18° を連続的に補間。夜にはしない。
  - **白飛び対策（前回の反省）**: ACESFilmic、露出 1.0 固定。ブルームは通常 0.3／成功時 0.55／最高潮 0.95、しきい値 0.95（最高潮のみ 0.92）、半径 0.35。雲の明るさも抑えた。mid 画質（ブルームあり）のクライマックス最大の光の瞬間で、空の青・全風車・丘の輪郭が見えることをスクリーンショットで確認（`site/thumbs` 用の撮影時に確認、ファイルは未保存）。
- **カメラ**: 操作対象の回転軸を常に画面中央に置く（`lookAt(回転軸)`）。基礎と、羽根の回転軌跡の円全体（16点）を含む点群が、縦横両方の視野で NDC ±0.78（段階2: ±0.72、段階3: ±0.68＝徐々に広く見せる）に収まる距離を二分探索で求める。カメラの高さは地面+14以上、基礎までの見通しを地形で遮られないよう持ち上げる。各風車のカメラ方向は、他の風車が視線や撮影位置にかからない角度を事前に選択。移動は 3.2〜7秒（視線の向きの変化を毎秒12°以下）。クライマックスは15基すべての基礎と回転軌跡を ±0.8 に収めて全体の中心を画面中央に置く。リサイズ／回転では状態を保ったまま構図だけ再計算。霧の距離はカメラと注視点の距離に合わせて伸ばす（引いた構図でも風車が霞まない）。
- **音**: WebAudio のみ（最初のタッチで生成/resume）。草原の風（ノイズ＋ローパス、ゆっくり変化）、羽根が通るたびのうなり（注視中の風車の回転角に同期）、接触の金属音、機械の始動音（のこぎり波＋スイープ）、波の「サァーッ」（帯域ノイズ、距離で音量）、成功音（Cメジャーペンタトニック：第1段階2〜3音、第2段階3〜4音、第3段階4〜6音）、段階終了の重なる上昇音と和音、クライマックスの Cmaj9。手続き生成の残響、マスター Gain＋DynamicsCompressor。タブ非表示で suspend。
- **画質**: `?q=low|mid|high` で固定（自動調整停止）。指定なしは mid で開始し、3.5秒のウォームアップ後、平均48fps未満が3秒続くと1段階下げ、57fps超が15秒続くと上げる（クールダウンあり、下げた後の上げは1回まで、クライマックス中は上げない）。high: PR1.75/草36000+16000株/影2048/ブルーム/種子600/雲5オクターブ、mid: PR1.25/22000+10000株/影1024/半解像度ブルーム/250/4、low: PR1.0/12000+6000株/影512/ブルームなし/80/3。切り替えで進行は失われない（地形分割は起動時のみ）。
- **テスト用**: `window.__ready`、`window.__errors`（Three.js 読み込み前に監視開始。フレーム内の例外も記録）、`window.__test`（state, target, done, climaxT, climax, peak, free, fps, q, waves, finished）。`?autotest` は通常と同じ `onDown/onMove/onUp` に合成イベントを流し、15基をタップとスワイプで交互に回し、途中で回転中の風車への追加タッチと背景タップも行う → クライマックス → 余韻 → フリープレイで1回触れて次の風車へ移るまで。
- **画面の文字**: なし（読み込み中は金色の円が脈打つだけ）。

## 確認結果（このクラウド環境）

- `python3 -m http.server`（ルート `site/`）＋ Playwright ヘッドレス Chromium（SwiftShader: `--use-angle=swiftshader --enable-unsafe-swiftshader`）。テストスクリプトは `logs/e08/run-test.js`、結果は `logs/e08/test.txt`。
- `games/e08/index.html?autotest&q=low` を **1024x768（横）と 768x1024（縦）で全工程 PASS**: `__ready === true`、`__errors` 空、コンソールエラーなし、15/15 基 → クライマックス（最大の光の時間帯に到達）→ 余韻 → フリープレイ（1回触れて次の風車まで移動）。各約220秒。
- 追加の短縮確認（約60秒、test.txt 末尾）: 390x844（iPhone 縦）q=low、1024x768 q=high とも `__ready`、エラーなし。iPhone 縦でも風車が中央にあり見切れていないことを画像で確認。q=mid は 640x480 で全工程を実行して PASS（サムネイル撮影を兼ねる。ログは test.txt に未収録）。
- スクリーンショット: `shot-1.jpg`（序盤・2基目の波）、`shot-2.jpg`（中盤・9基目の波）、`shot-3.jpg`（クライマックス約9.5秒＝最大の光付近）、`shot-4.jpg`（フリープレイ）、`p-shot-1〜4.jpg`（縦の同場面）。すべて 300KB 以下の JPEG。縦横とも操作対象の風車の回転軸が画面中央、基礎と羽根の先端が画面内。クライマックスは15基すべてが画面内で、全体の中心が画面中央。
- サムネイル: `site/thumbs/e08.jpg`（mid 画質、640x480 で撮った第2段階の画面、約37KB、文字なし）。
- 禁止語（ひらがな・カタカナ表記を含む）が `site/games/e08/`・`logs/e08/`・サムネイルにないことを grep で確認。
- 外部通信: ゲーム本体は外部にアクセスしない。共通の `../../gf-playlog.js` のビーコンだけはテストで 204 を返して代用。

## 未解決・注意点

- iPad Safari 実機での動作・FPS・タッチ感触・音は未確認（SwiftShader は CPU 描画で 2〜5fps のため性能の指標にならない。通常時とクライマックスの実機 FPS は未計測）。high の頂点数（草 約52,000株）が実機で重い場合は自動調整で mid/low に下がる想定。
- 自動テストのスクリーンショットは q=low（ブルームなし、草が少ない）。mid/high は草が密で、波の金色にブルームが乗る。
- 画面から遠い場所の草原は地面シェーダーの色と光沢で表現しており、草の株そのものは注視点の周り（近景半径約56、遠景半径約200）だけ。クライマックスの引いた構図では手前の一部と遠景が地面シェーダーのみになり、やや平滑に見える。
- 縦画面のクライマックスは、15基を横幅に収めるためカメラが遠く、風車は小さく見える。
- 指示文との差: 地形メッシュは遠景まで覆うため ±1500 の非一様格子（中心付近の間隔は 128〜256 分割の 700 四方と同程度）。クライマックスの大きなうねりは谷全体を数秒で渡らせるため 34 u/s（通常の波は指示どおり 12〜26 u/s）。ブルームのしきい値は 0.92〜0.95、最高潮の強さは 0.95（白飛び防止を優先）。草の株の高さは近景 0.4〜1.1、遠景の株はまとまりとして 1.2〜3 程度に拡大して表示。
- メモリ: 波・種子・音のノードは上限付きの配列／使い捨てノードで、フリープレイを続けても増え続けない設計だが、長時間の実測はしていない。
